# 紅點貓（Guidebook 閱讀器）

Climbio 家族首頁的「紅點貓」卡片直接進入 `/redpoint/`，手機版（PWA，可以加到主畫面、離線使用）。首頁「開啟紅點貓的世界」則指向 `/redpoint/?world=1`，啟動後直接開世界地圖，App 返回仍回紅點貓首頁；此參數不影響 `?topo=` 分享收件流程。定位是**最簡單好用的 Guidebook 閱讀器**：從「世界」收下 Climbio Studio 發佈的岩場與 OpenClimbing 的全球 Topo 岩場（也可以開朋友傳來的連結），離線看岩場頁、Topo、3D 與路線清單，記錄完攀。沒有拍照、相簿、掃 QR：手機、平板、電腦一樣，右下「＋」可展開「傳給朋友」與「世界」。已下載內容可離線使用（世界索引、下載及公開分享需要連網）。

兩款 App 的完整資料備份與選擇性復原見 [備份規格](backup.md)。

## 外觀

版面、元件、動態照岩點貓（[style.md](style.md)），顏色是戶外白底深海藍：頁面掛 `data-climbio-theme="outdoor"`，介面色都來自 `css/brand-tokens.css`（`appkit/ui.css` 對到 `--bg`、`--surface`、`--accent`…），紅點 `--brand-role-accent` 只用在字標的點。對話框、提示、照片、加到主畫面用 AppKit（`appkit/ui.js`、`photo.js`、`install.js`）。介面有七種語言（`i18n/redpoint/`），只跟瀏覽器語言，沒有手動選擇，繁體中文是其中一種；設定與大部分畫面文字在語言包裡，既有 Topo 操作的部分文字仍在程式裡。

**右上頭像與個人資料（共用 AppKit）**：岩點貓與紅點貓共用 `AppKit.account.avatar()` 頭像、`AppKit.account.summary()` 統計摘要與 `AppKit.account.detail()` 個人資料卡，樣式在 `appkit/ui.css`。紅點貓選單提供共用暱稱、岩場／岩壁／路線統計、個人完攀記錄、匯出、匯入、「同步到其他裝置」（已配對裝置間雙向同步）、使用說明（`/guides/redpoint-manual.html`）、自動合併岩場（有候選才出現）、安裝及底部共用連結。統計由 `redpoint/db.js` 已收下的各來源掃描，合併資料按節點 ID 去重；世界索引上未收進本機的不計。

## 啟動

先讀本機資料並顯示首頁或分享連結，不等待外部身分驗證服務。

頁面在載入主程式之前先載入 `appkit/recover.js`（`data-boot="8000"`、`data-cache="redpoint-cat"`）。有網路時，開機看門狗會攔截自家網域腳本的下載失敗、語法或執行錯誤；主程式啟動完成要呼叫 `akBooted()`，頁面載入後 8 秒內沒呼叫也算開機失敗。開機失敗時：若有等待中的新版 Service Worker，先送 `SKIP_WAITING`，等它接手再重新整理；沒有就解除 Service Worker、刪掉 `redpoint-cat` 開頭的快取再重新整理。只清快取，不動 IndexedDB（已收岩場與完攀紀錄仍在）。`sessionStorage` 限制十分鐘內最多自動修復一次，避免真的壞掉時無限重新整理。離線時不自動清快取，保留「打開不等網路」的設計。

## 多裝置版面

- **手機、平板直放（寬度 < 900px）**：單欄，岩場頁、Topo、路線清單一頁一頁換（Zoom & Morph）。
- **平板橫放、電腦（寬度 ≥ 900px）**：雙欄工作區。左欄是岩場頁（寬度 `--pane`＝34% 視窗寬，限制在 360–440px），固定不動；Topo 和路線清單開在右欄（`body.split`），在右欄換頁不做 Zoom & Morph（看 Topo 時按記錄，右欄換成路線清單），返回只關右欄、岩場頁留著。路線清單內容最寬 760px、置中。首頁卡片內容最寬 1200px、置中。不是從岩場頁打開的 Topo（例如首頁的 Topo 卡片）維持全頁。導覽邏輯在 `redpoint/app.js` 的 `syncSplit()`，頁面堆疊（`nav`）不變。
- **右下的地球**：所有裝置一樣，只有「世界」一個功能：按了直接打開世界，不展開選單。

## 畫面


- **來源標籤與使用者授權文件**：外站岩場卡片依序顯示「岩場名稱 → 岩壁數 → 來源」（OpenStreetMap／theCrag），全部左對齊；來源是卡片最後一行純文字（含資料庫小圖示），不加外框或底色，也不在頁面最下方另加授權列。岩場橫幅也改為短名稱，其他作者署名維持原樣。`extension/thecrag.js`、`extension/openclimbing.js`、`redpoint/openclimbing.js` 在匯入時將短標籤寫到岩場組合的 `props.sourceLabel`，`redpoint/source-credit.mjs` 僅讀該欄位，不再識別或轉換舊版署名（既有收藏需重新匯入）。theCrag 未查明的作者不使用假署名，另記 `props.attributionStatus: unverified`，`license: NOASSERTION`；OSM 原始 `attribution`、`license`、`source.url` 仍保留。設定選單頁尾的「資料來源與授權」連至 `redpoint/sources.html`，可查 OpenStreetMap（ODbL）與 theCrag 個別作者／混合版權注意事項；世界地圖本身不放授權文字。文件與模組列入 PWA 離線快取。

- **分享網址的預覽**：`/redpoint/` 貼到 LINE、Messenger 等的連結卡片是「紅點貓」、一句說明（跟 `manifest.webmanifest` 的 description 同一句）和紅點貓圖示（`redpoint/index.html` 的 `og:` 標籤）；岩點貓（`/hold/`）、Studio（`/studio/`）同樣各有自己的名稱、說明、圖示。
- **測試版標示**：開發版（`climbio-dev.web.app`）和本機，logo 旁有橘色「測試版」標籤，分頁標題和加到主畫面的名稱是「紅點貓 Beta」（`manifest-dev.webmanifest`），跟岩點貓一樣（`redpoint/boot.js` 判斷網域）。
- **首頁**：上方左邊是橫式 logo（`icons/cats/redpoint-cat-wordmark.svg`，藍色 Bolt 貓加 Climbio 向量字，38 px 高、離左邊 16 px，位置和大小對齊岩點貓左上的字標）、右邊設定按鈕（齒輪，維持同一設定圖示）；手機裡還沒有任何資料時是空白的首頁：「探索世界」和「看 3D 岩場範例」（直接打開大砲岩的分享連結 `/p/rw9oa7t1taemt9zj`，第一次用就看到岩場可以做成 3D 路線圖），右下地球開世界；所有資料都是卡片（正方形滿版照片、圓角、照片下緣的名稱與一行副標），新的在前：收到的岩場（入口照片、署名、幾面岩壁；有 3D 模型的岩場卡片標「3D」；署名「甲；乙 改編」的乙跟前面的人同名就只顯示一次、不寫「改編」，`io.js` 的 `credit`，檔案裡的署名不動）、Topo。點卡片，照片變成下一頁那一塊（岩場頁的橫幅、Topo 的照片，見下面的換頁動畫）；卡片沒有長按動作，也不能拖（不能手動換順序、合併）；動作都在展開頁右上「更多」：岩場頁是分享（個人收藏與合併的岩場沒有）、刪除（合併的是重新命名、拆開、刪除）；Topo 頁是分享、刪除（區域裡只有這一張照片時連區域一起刪）。合併岩場改由首頁選單的「自動合併」。刪除要確認、不能復原：岩場連同裡面的照片、地圖和圖層。首頁順序是組合 `items` 的順序（最後一筆在最上面，新收的岩場排最上面）。
- **合併的岩場**：把切成幾包的同一座岩場（例如 OpenClimbing 太大時切開的「第幾包／共幾包」）或同一地區的幾本併成一張卡片。資料是一個組合（`type: group`，`props.merged: true`，`items` 指到原本的各個岩場）：成員原樣保留，所以各自的來源網址、自動更新、完攀紀錄（記在成員的組合 id 上）照舊，拆開後一切還在。卡片左上寫「N 個岩場」，名稱先用被疊上去的那一張的，可以重新命名。打開是接在一起的岩場頁：成員的照片、節點照 id 去重後接起來（`flatSet`），岩壁、路線清單、地圖、Topo 前後張都照合併後的內容；入口照片用第一個成員的。不能整組分享（右上沒有分享鈕），到成員的 Topo 或岩壁那一層分享。有一邊已經是合併的，就把另一個併進去；刪除合併的卡片會連裡面每個岩場一起刪（先確認）。備份、匯出入把它當一個岩場組合。
- **右下地球**（首頁）：打開世界。
- **設定選單**：共用暱稱、匯出、匯入、「同步到其他裝置」（`mode: 'devices'`）、使用說明、安裝、資料來源、隱私、條款及版本。朋友互傳入口在首頁「＋」清單、位於「世界」之前（`mode: 'send'`），不混入個人設定。完整備份與配對同步見 [backup.md](backup.md)、[sharing.md](sharing.md)。
- **岩場頁**：上面是入口照片的橫幅（左下名稱、署名、岩壁數、路線數），下面照石頭（岩壁）組合：一個分區（上攀區、抱石區）一段，分區標題旁寫幾面岩壁或幾顆石頭（大多是抱石的叫「顆石頭」）、幾條路線；一顆石頭一張兩欄小卡（第一張 Topo 的照片、幾張 Topo、幾條路線，完攀過的右上有爪印和條數；右下的爪印鈕本身不放數字），點了打開它的第一張 Topo。組合方式從資料來：照片畫面的 `props.node` 指到岩壁，岩壁的上層是分區，分區、岩壁照 `props.order` 排，同一面岩壁的幾張 Topo 照上面最小的路線編號排；沒有指到岩壁的照片排在最後，一張一張卡。只有一個分區時不顯示分區標題。主卡（入口照片）右上是原始資料（組合寫了 `source.url` 才有，例如作者的路線書文件：開新分頁）、交通（岩場或分區節點寫了 `props.approach` 或位置才有：有交通圖（`props.purpose: approach` 的地圖畫面）就打開交通頁——上面是交通圖（道路、停車場、地名，建議路線畫成帶箭頭的粗線，署名在左下），下面是說明和「導航到〇〇」的按鈕（交通圖上有名稱的停車場，開 Google 地圖導航）；沒有交通圖只跳一個「怎麼到〇〇」的對話框；岩場節點有位置（`geo` 是 Point，例如 theCrag 匯入的）時對話框的按鈕是「導航到〇〇」，開 Google 地圖導航，交通頁也多一個導航到岩場的按鈕；節點寫了位置沒寫說明也有這顆鈕）和地圖鈕：岩場有地圖畫面（`surface: map`，交通圖除外）就打開岩場地圖（`mapkit/` 的向量地圖：分區範圍、岩壁與石頭畫成一塊塊的示意（名稱寫在下面）、步道，分區名稱自動放在不壓到石頭的空地；點一面岩壁或一顆石頭打開它的第一張 Topo，還沒有 Topo 的說一聲；每次打開都從整個岩場開始；地圖的署名跟岩場一樣（岩場作者自己畫的）就不在地圖上重複），右上的照片鈕看區域照片；沒有地圖就直接看區域照片（照片畫面的 `props.node` 指到岩場或分區的，例如路線書的手繪配置圖：用看 Topo 的畫面打開，上方寫「區域照片 1/2」，左右滑換下一張；不算 Topo，不出現在石頭卡片裡）。上方列左邊返回、右邊分享；往上滑、主卡捲出去之後，岩場名稱移到「<」右邊。右下是紅色的爪印（有路線節點才有），打開路線清單。岩壁數、路線數是從組合的 `nodes` 數出來的（岩壁、分區節點、路線節點），圖層裡路線用「線段指到的路線、bolt 與確保站的上層」算；資料檔不另存這些數字（公開格式的「放法與連結」）。
- **路線號碼**：沒有線、只標了位置的路線（轉自別處、照片上本來就印著號碼牌的路線書）在 Topo 上是一個編號牌，中心就是標記的位置；有牌子大小的蓋在照片上原來的牌子上、跟著照片縮放，顏色用原牌子的顏色。路線清單、照片上的路線數、點路線打開哪張 Topo 都把它算成「標在照片上」（`redpoint/app.js` 的 `isRouteMark`），匯入時它指到的路線一起帶過來（`io.js`）。資料寫法見 [format/VOCABULARY.md](../format/VOCABULARY.md)、顯示見 [topokit/README.md](../topokit/README.md)。
- **分享一張 Topo**：Topo 頁右上分享先出圖片預覽（限時動態尺寸，版面、字型、署名跟岩點貓同一套，`appkit/share-image.js`），選「圖片」交給系統分享，選「連結」走原本的連結分享。有點選路線就以那條路線為主（難度、名稱、取景），沒有就是整張 Topo 加岩壁名稱；底圖是照片加 Topo 的線與編號牌（`app.js` 的 `topoBase`），只在本機產圖、不上傳。
- **3D 岩場**：岩場的每張 Topo 都是同一個 3D 模型拍的快照時（`app.js` 的 `model3dOf`），點岩場卡片、開箱完按「看這個岩場」都直接進 3D，不經過岩壁小卡的岩場頁：回到上次離開時最近的那面岩壁（記在這台的 localStorage `redpoint.wall3d.<模型 id>`）。第一次進來（開箱後），電腦、橫放的螢幕跟 2D 岩場一樣從卡片放大：卡片的封面就是作者端拍的全區快照（掛在岩場節點、`props.model.camera` 記著拍的鏡頭，4:3 跟卡片同比例，不畫路線；不算區域照片），放大後填滿畫面（比畫面寬就左右裁、比較窄就上下裁），模型好了在同一個鏡頭換成 3D，停 0.5 秒再花 2 秒往前飛進第一面（一路只放大、不縮小再放大；飛行中手勢先不動），飛到了路線才淡入；手機直放看全區要先縮很小再放大，直接進第一面；之後進來，卡片的照片放大成那面岩壁的快照，模型載好後換成 3D（載入的時間就看快照）。上方中間是岩場名稱、右上分享；底部一排岩壁名稱，目前最近的那面亮起來，點了沿步道走過去；右上分享鈕旁的清單鈕開關路線清單（也可以往上拉、點上緣的握把）（跟路線清單頁同一種列，含爪印），點一條鏡頭走到那條路線前面、亮起來、浮出說明卡，清單收回；點 3D 畫面也收回。清單上方是原始資料、交通、地圖鈕（跟岩場頁一樣，有資料才有）。清單每列右邊的爪印就是完攀記錄（跟路線清單頁同一份），3D 畫面沒有另外的記錄鈕。3D 一律滿版，介面是半透明的深色玻璃、白字：收著時只有浮在畫面底部的岩壁名稱，拉開才有玻璃底；電腦、橫放（寬度 ≥ 900px）也一樣，岩壁名稱與清單在畫面下方置中（560 px 寬）。橫的大螢幕（iMac 等）路線的編號牌、難度籤和線依畫面高度放大，最多 1.9 倍；直放的手機和小視窗維持原尺寸。點岩場到放大動畫開始之間不等 3D：3D 程式（約 3 MB）在首頁閒置時先載好（手機裡有 3D 岩場才載），24 MB 的模型從手機儲存空間讀出來是在動畫開始後的背景進行。快照仍留在資料裡：載入時的過場、舊版 App、2D Topo、分享預覽圖都用它。沒有 3D 模型的岩場照舊是岩場頁。
- **路線清單**（岩場頁右下的爪印）：上面三格是完攀、爬了、沒爬各幾條，點一格只看那一種、再點取消；下面一顆石頭一段，一列一條路線，跟路線書一樣：編號（跟 Topo 照片上的牌子一樣，照編號排）、名稱、類型與 bolt 數、難度（窄體斜字），不顯示說明和首攀（在 Topo 裡看）、右邊的爪印。爪印按一下換狀態：沒爬（淡的虛線圈）→ 完攀（紅底爪印蓋下去）→ 爬了（紅框、爪印斜一點）→ 沒爬，一天爬完一次記好；按的時候只更新那一列和上面的數字，列不會跳。點路線那一列打開畫著它的 Topo，亮那條、浮出說明。紀錄是紅點貓自己的一份（`redpoint.log`，鑰匙是岩場（組合）的 id，值是 `[1 爬了／2 完攀, 完攀次數, 第一次完攀日, 最近一次日]`，沒爬就沒有這一筆；只在本地保存，隨手動備份／復原），格式和岩點貓的攀爬紀錄一樣（[app.md](app.md)），但不併進岩點貓的統計。
- **Topo**：全螢幕看（`topokit/` 的 `<climbio-topo>`，雙指縮放、點兩下放大），一次看所有路線，不用縮放就看得出有哪些路線、多難：編號牌直接帶難度（topokit 的預設 - **世界**：整合 Climbio Studio 發佈的 Guidebook（`type: guidebook`）與 OpenClimbing 全球岩場索引（開放資料集 climbio/crags 的 `openclimbing/index.json`），一進去就顯示全部（旅行前先逛不同的地方，不只看附近）。兩份來源由雲端函式合成國家 → 地區 → 岩場三層樹，存成一個靜態檔 Storage 的 `public/world.json`（壓縮，CDN 留 5 分鐘）：發佈、下架後重寫，`refreshWorld` 每天 05:00（台北）再補寫一次（`functions/projects.js` 的 `writeWorld`、`functions/world.js`）；OpenClimbing 索引抓不到就留著上一份。合成程式是 `redpoint/world-data.mjs`（`buildWorldFile`、`hydrateWorld`；500 公尺內相連岩場的合併分組也在這裡算好），部署時複製進函式的 `vendor/`。檔案 `{ v, t, books, oc, tree }`：`books` 是 Guidebook 原樣，`oc` 是合併後的岩場（不能推算的欄位才存，座標約 1 公尺精度），`tree` 的節點用整數指到 `worldItemsFrom(books, oc)` 的位置，岩場不重複存；沒有名字的岩場名稱留空，由紅點貓用語系補「未命名」。每一筆 Guidebook 有作者在 Studio Crag 選的國家時多一個 `cc`（小寫 ISO 國碼），有拍照位置時多一個 `at`（`[經度, 緯度]`，照片 `camera.position` 的平均）。開機後 `loadWorld()` 抓 `Backend.loadWorld()`，讀進來還原成 `{ books, oc, tree }`；沒有雲端服務的站、或雲端的讀不到時，手機用同一份 `buildWorldFile` 從開放資料集自己合成（`fetchWorldFile`）。原樣存進 `localStorage` 的 `redpoint.world`（舊版存的 `{ books, oc }` 不算，等這次抓新的）。進入世界直接顯示完整的樹，背景再要新的，沒變就不重畫。所在國家排第一格是顯示時依當前語系套用 `homeFirst`／`homeCc`，不寫進預先合成或存下來的樹。
  **立體卡堆，沒有地圖**：世界是國家 → 地區 → 岩場三層（分層與排列在 `redpoint/world-stacks.mjs`，純函式，測試 `tools/world-stacks.test.mjs`）。GPS 與區域只用來分組、排位置，不畫底圖、圖釘、群聚，也沒有下方橫向卡片列。
  - **分層**：國家＝`cc`（OpenClimbing 的 `country`）；地區＝區域路徑第一段 `ap[0]`（Guidebook 是書名：Studio Crag 一個專案一本，名稱就是 `ap`）；沒有 `cc` 的岩場歸最外層「其他」。岩場不超過 12 個的國家不分地區，點國家直接攤開成岩場；更多的才分，地區要至少 3 個岩場才獨立成疊，其餘（含沒有地區名的）併成該國的「其他」。數字是岩場個數（OpenClimbing 自動合併的組合算一個）。
  - **排列**：同一層的卡堆依大致地理位置排進格子：每列 3／4／5 疊（寬度 <560／<900／≥900），由北到南一列一列、列內由西到東；「其他」與沒有位置的排最後。國家這一層顯示時，再依當前語系把使用者所在國家排到第一格（`homeFirst`／`homeCc`），不寫進預先合成或存下來的樹。
  - **卡堆**：正面只有名稱與岩場數，不用照片代表整個地區；下面墊的張數是厚度（`layers`，岩場越多越厚，1–6 層）；岩場全部收過的疊在岩場數前打勾。
  - **搜尋**：世界上方有搜尋欄（跟岩點貓找牆一樣），依岩場名稱或所在國家、地區名稱跨層找，結果直接是岩場卡片（Guidebook 在前、其餘依名稱）；清空回到原本那一層，離開世界時清掉。
  - **展開與返回**：點一疊，同層其他卡堆淡出，下一層從點的那一疊的位置散開到各自的格子（Web Animations，`prefers-reduced-motion` 時不播）；左上返回把這一層收回到原來那一疊的位置，再顯示上一層，所以位置不變；在最上層按返回離開世界。目前在哪一層記在頁面裡（`worldPath`），從岩場返回世界時還在原來那一層、捲動位置也回來。
  - **岩場卡片**：最後一層沿用既有卡片（入口照片、名稱、已收下／下載標記），Guidebook 在前、OpenClimbing 依名稱；一批 24 張，捲到底才接著放（`IntersectionObserver`），只載入看得到的圖；圖用清單的 `thumb`／`preview`（Guidebook）與 `climbio/crags` 的 `openclimbing/<id>/preview.jpg`。點卡片：收過的直接打開，沒收過的走既有下載流程（Guidebook 直接開箱，OpenClimbing 先問再收，電腦版有 theCrag 連結時先列出）。收下之後世界裡的「已收下」標記跟著更新。
- 每一頁都多一筆瀏覽紀錄：左上返回和返回手勢都關最上面那頁。
- **換頁是岩點貓的 Zoom & Morph**（`js/wall.js` 的 `flyBetween`，這裡是 `app.js` 的 `morph()`、`enter()`）：卡片的照片變成新頁裡照片的位置，整個新頁跟著等比縮放、用 `clip-path` 裁成卡片的樣子，再展開到全螢幕，照片疊在最上面、展開到最後才淡掉；返回（左上、返回手勢）反過來縮回那張卡片，卡片上的照片先藏著、縮完才出現。只動 `transform` 和 `clip-path`（合成層），舊頁一直留在底下直到動畫播完，所以不會露出空白、不閃；內容（岩場頁的照片、Topo 的資料）先填好再換頁。首頁重畫時只換有變的卡片，照片網址留著用，返回時捲動位置還在。沒有對應的卡片（世界、開箱）直接換頁；減少動態效果時都直接換。

## 收岩場（開箱）

點開的連結（`/?topo=<網址>`，根目錄的 `entry.js` 轉到 `/redpoint/?topo=…`）、世界都走同一個開箱畫面（`receive()`），像岩點貓收線：

1. **先問**（只有世界）：背景下載與確認卡並行；確認卡顯示封面、分享者暱稱、岩場名稱、岩壁數與路線數，選「收下」才加入本機，「取消」就不收。收過同一網址或同一 Guidebook 的直接開本機資料。**自動更新**：打開已收岩場時，比對已記錄的來源與 `/p/<組合 id>/index.json` 的公開版本；換成收下那一版的後代裡最新的一版（一次刪很多的大改 Studio 發成另一本，不是後代，不會換過去），不列入世界的書（世界清單沒有）改問 `Backend.guidebookVersions` 這本所有的版本；新版本才增量下載變更的 JSON、圖片與圖層（同一岩場 10 分鐘內不重複查詢，離線或 ZIP 不查），完成後更新畫面與提示。
2. **開箱**：上面是誰分享的，中間一張微斜的卡片，先是閃光骨架。讀到第一份檔案就下載**合成預覽圖**（組合的 `props.preview`：一張圖，上面是入口照片、下面是每張照片的小圖排成格子，Studio Crag 發佈時做的），一到就把入口照片模糊地放上去、每張照片排一格暗的小圖；之後照片下載到哪，小圖就依序亮到哪（超過 2 MB 的檔案、例如 3D 模型下載時，計數後面接它自己的百分比，例：`5／6 · 42%`，不然停在最後一個檔案看起來像當掉）、入口照片越來越清楚，數字「11／24」跟著跳。
3. **揭曉**：照片清楚、名稱落下、左下貼上膠帶「收到的岩場」、輕震，出現「看這個岩場」：開箱這頁換成岩場頁（入口照片展開成橫幅，岩場頁從這張卡片展開）。左上 × 隨時可以關掉（取消下載）。

**加入主畫面：跟岩點貓一致，先使用、後建議。** 手機瀏覽器（包含朋友從 LINE、Messenger 或 Instagram 分享過來的網址）直接進入開箱／收下岩場，不要求先安裝，也不跳整頁導引；「世界」選擇未下載岩場時保留原本的下載確認，按下載就開始收。第一次成功收下岩場／Topo 後，返回首頁才顯示 `ak-hint` 輕量提示列「加到主畫面」，不遮住岩場頁、路線圖或世界；按 × 後這個瀏覽器不再自動提示，設定裡仍保留手動安裝。從主畫面開啟的 App 不提示；Android Chromium 有 `beforeinstallprompt` 才呼叫原生安裝，iPhone 顯示分享選單操作，LINE 等內建瀏覽器提醒在 Safari／Chrome 開啟。與岩點貓共用 `appkit/install.js`（安裝能力、是否已安裝、關閉記錄），兩款的提示位置、時機和關閉行為一致，只有產品名稱與顏色不同。

**iPhone 的本地資料注意事項：** Safari／內建瀏覽器和主畫面 Web App 的 IndexedDB 可能分離，瀏覽器中已收的岩場不保證自動出現在新安裝的主畫面 App；安裝步驟旁告知可能要重收，不要宣稱會自動搬移資料。使用者可以持續在原本的瀏覽器觀看已下載內容，安裝不是離線閱讀的必要條件。分享的 `?topo=` 仍應直接保留並開箱，不導向首頁或強迫從「世界」重新尋找。

讀法（`redpoint/io.js` 的 `fromUrl`）：公開 `/p/<id>/<檔>` 網址由 `projectFiles` 導向開放資料集；分批並行下載 JSON、圖片與模型，優先顯示預覽；接收整份存在 IndexedDB 供離線閱讀。收件來源存在 meta `sources`，之後分享沿用該來源網址；下載中斷時在岩場頁提示補下載，並請求瀏覽器持久化儲存。

## 個人收藏（外站匯入）

出國前先把當地的岩場資料存下來：電腦版 Chrome／Edge 的 `extension/` 收藏工具把支援網站的岩場、路線與 Topo 轉成公開格式 v2，先放在擴充功能的 IndexedDB，開啟紅點貓分頁（`#collect`）後將資料傳給紅點貓匯入本機。匯入成功才清除暫存，轉檔與照片處理都在使用者的瀏覽器執行。手機可透過已配對的「我的裝置」同步收藏。
  - **能收藏**：theCrag 的岩場頁（要有路線清單和 Topo；頁面上只標了路線、沒畫線的 Topo 照片也收，不放圖層，照片上沒有可以點的路線）。任何在頁面放 `<link rel="climbio" href="入口.json">` 的網站（出口是 Climbio 公開格式 v2，例如龍洞）：擴充功能找得到入口就能收，不用更新擴充功能的網站清單（`climbio-site.js`）；紅點貓也能直接貼入口網址收。
  - **OpenClimbing**（`openclimbing.org/relation/…`）：資料在 OpenStreetMap（路線是 `site` 關係底下的 `climbing=route_bottom` 節點，名稱、各種難度、長度，授權 ODbL）與 Wikimedia Commons（照片；Topo 線是路線的 `wikimedia_commons:path`，照片寬高的比例座標，授權逐張，只收 CC 與公眾領域，其他的不收）；讀它們的公開 API，不是爬網頁。區域底下有好幾個岩場時列出各岩場讓使用者勾選，一個岩場一個資料夾，畫面 origin 是 `authorized`（照片的 CC 授權，署名照 Commons），沒有 Topo 的不收。OSM 上有 Topo 線、且已驗證收進索引的路線約 7200 條（2026 年 11 月索引：捷克、法國、德國、義大利、波蘭、瑞士為主，另有西班牙、土耳其、奧地利、賽普勒斯、英國、挪威、葡萄牙、美國；東亞目前沒有）。
  - **OpenClimbing 的資料在建索引時查好、驗證好**（`tools/openclimbing-pack.mjs`）：用 OpenClimbing 官方匯出的 SQLite（只讀岩場與路線，不讀使用者的攀登紀錄）取出每個岩場（含子岩場）有線的照片路線，問 Commons 照片在不在、授權是不是 CC／公眾領域（規則同 `sourcekit/openclimbing-read.js` 的 `imageInfoOf`），再實際讀每張照片的網址確定讀得到。結果分四種不混在一起：`ok`（收）、`missing`（Commons 沒有檔案、網址 404／410、不是圖片）、`unlicensed`（授權不符）、`unknown`（網路中斷、逾時、429、5xx、403：重試四次仍失敗才算，不當成沒有照片，岩場列在待補，不進索引；再跑一次同一個指令只重試這些）。每個岩場一個 `openclimbing/<relation id>/topo.json`（路線、線條、照片資訊），索引（`openclimbing/index.json`）的 `tc` 是驗證過的路線數、`pc` 是驗證過的照片數、`tcu` 是 OSM 標的 theCrag 網址，沒有驗證過照片的岩場不在索引裡。點小卡時只讀這個檔再下載照片，不再即時查 OSM 或 Commons；點下去先進整頁的連線中，讀到資料才問「下載」，有問題就在那一頁說明。這些資料不進版控：產出在本機 `data/openclimbing/`（版面同資料集的 `openclimbing/`），上傳到 climbio/crags 由人做；App 從資料集讀（`openclimbing.js` 的 `OC_DATA`），`redpoint/sw.js` 把它們存進不隨版本清掉的 `redpoint-cat-data` 快取（先用存好的、背景更新），離線照樣看得到、第一次沒連過網的人看不到。更新流程：下載新的匯出檔 → `python3 tools/openclimbing-index.py <匯出檔> data/openclimbing/index.json` → `node tools/openclimbing-pack.mjs <匯出檔>`（結束碼 2 代表有 `unknown`，重跑）→ `python3 tools/openclimbing-previews.py --out data/openclimbing` → 上傳 `data/openclimbing/` 到資料集的 `openclimbing/`。
  - **OpenClimbing 的整區下載**（`redpoint/openclimbing-group.mjs`）：來源標的上層區域（`areaPath`）相同、同國家、相距 500 公尺內相連的岩場，在世界畫面合成一個岩場，下載一次收齊，離線包保留每個子岩場。不看名稱，也不靠 GPS 推測行政階層；沒有上層區域的岩場單獨一筆。連成一包的 Topo 路線超過 100 條（`MAX_PACK_TOPO`）、或岩場數超過 40（`MAX_PACK_CRAGS`）時，沿地圖長軸、依路線數對切成幾包（名稱是上層區域加（第幾包／共幾包）），每包都在上限內。下載量由路線數上限主導；岩場數放到 40，是為了避免像 Yzeron - Historique 這種小岩場多、路線未超標的區域被切成多包。名稱只是編號的岩場（56）前面加上層區域名（Rocher Canon 56），來源沒有名稱的用上層區域名；位於已知地區（`REGIONS`，目前只有 Fontainebleau，以座標框判斷，只用在顯示、不改分組）的再冠地區名（Fontainebleau · Rocher Canon 56），大包也一樣（Fontainebleau · Rocher Canon（2/8））。來源沒有名稱也沒有上層區域的，查 `UNNAMED_PLACES`（`redpoint/openclimbing-group.mjs`，OpenClimbing id 對照附近城鎮名，索引更新後有新的就補一行）；表裡沒有才顯示「未命名岩場」。
  - **不收：Boolder 與 bleau.info**（楓丹白露）：Boolder 的資料庫（`boolder-org/boolder-data`）以 CC BY 4.0 開放，但路線名稱與難度主要來自 bleau.info；bleau.info 保留所有權利，未經書面許可不得重製、存進資料庫或公開（照片與插圖同），Boolder 是否已取得它的再散布同意沒有公開說明。Boolder 的 Topo 照片放在它的伺服器，使用條款寫明照片、文字與名稱標誌歸原作者，沒有開放授權。路線線條只能疊在照片上，所以不收。楓丹白露改用 OpenClimbing 的 OSM 與 Wikimedia Commons 資料（見上）；要收 Boolder 或 bleau.info，必須先取得書面許可。
  - **其他網站**：尚未支援時顯示一般提示，不執行轉換。
  - 所有網站都一樣：沒有 Topo（路線圖）的頁面不下載，只在頁面上說明請手動打開要收藏的岩場頁。紅點貓以路線圖為中心。

- **桌面世界岩場的 theCrag 入口**：OpenClimbing 岩場的 OSM relation 若有 `climbing:url:thecrag`，在電腦點圖釘或下方卡片時，選擇對應的 theCrag 網址會在新分頁開啟；使用者再自行按「紅點貓收藏」擴充。未收過的岩場仍可下載 OpenClimbing，已收過的仍可打開本機岩場。合併岩場保留每個成員的對應連結、去除重複，沒有精確網址時不顯示 theCrag 入口；現有精簡索引沒有此欄位的，桌面點擊時向 OSM 批次查一次，不用爬 theCrag。

- 「設定 → 匯入 → 本機檔案」選擇 `.climbio` 或 ZIP，列出可匯入岩場，使用者勾選後匯入；已有同一岩場時先提示覆蓋。
- **缺照片**（下載到一半、檔案遺失）：卡片和岩場橫幅是有圖示的底色，不是破圖；岩場頁上方提示「還有 N 張照片沒下載」（個人收藏沒有網址可以補下載，提示說要在原網站用擴充再收藏一次）；打開沒有照片的 Topo 只說一聲「這張照片還沒下載」，不開一張空白的。
- **刪除**：確認後只刪手機的副本及本地收藏版本，不碰備份或已分享內容。
- **個人收藏與朋友互傳**：來源網站內容不因收藏而取得轉傳或公開權利。畫面的 `origin` 是 `personal`，授權與署名照原站（`license`、`attribution`、`source.url`）。公開分享仍只有 `origin` 是 `self`、`authorized` 的畫面可進入公開資料集（`io.js` 的 `shareable`）；個人收藏沒有公開分享鈕，Studio 發佈也擋下。首頁「＋」→「傳給朋友」可主動選擇個人收藏，走 WebRTC 私人直傳並保留 `origin: personal`；使用者需確認來源允許傳給朋友，不能把私人傳輸當成授權。攀登紀錄、金鑰不跟著傳。
- **匯出／匯入**：設定只保留兩個資料入口。匯出先選岩場，存成本機 `.climbio` 檔，包含本機照片、Topo 與攀爬紀錄；不含未勾選岩場。匯入讀「本機檔案」（`.climbio`、ZIP），先勾選岩場後只取代選中的內容。個人收藏來源與原始授權保留，仍不開放直接公開分享。

## 分享

岩場頁、Topo 頁右上「更多」的分享：透過系統分享連結，無法呼叫系統分享時複製。已公開的岩場使用固定網址 `/p/<包 id>`；分享個別 Topo 會附照片 id。收來的岩場沿用來源網址，不重複上傳；只存在本機的岩場須經「公開」確認後才上傳到 `climbio/crags`，並由 `datasets` 登記。發佈產生專案 id，網址由發佈結果決定，後續版本以 `origin` 關聯；發布內容採 CC BY-SA 4.0，照片與來源授權須先確認。

**分享、收入的最小單位是 Topo，任何子集都完整**（公開格式的「放法與連結」，`tools/format-placement.mjs` 檢查）：分享一個 Topo，包裡有照片畫面、疊在上面的圖層、照片檔，加上它用到的節點（線段指到的路線的名稱、難度，照片指到的區域，連同上層一路到最上層）放在這一包的組合的 `nodes`，發佈資料裡辨識用的特徵點欄位（`props.features`）不放進去。自己畫的路線節點（編輯器寫在圖層裡的）打包時移到組合，圖層只留 bolt、確保站和標註。子區域、主區域、整個岩場也是這棵樹的一段加上它用到的節點，收的人單獨拿到就能看、不用再回頭找別的檔案。

## 資料

**一次下載、離線看所有資料**：收一本岩場或一組 Topo，JSON 和全部照片一次下載到手機，之後完全離線可看；效能優化只能在這個前提下做，要改這個行為先提設計案。

全部是 Climbio 公開格式 v2（[format/README.md](../format/README.md)），存在這支手機的 IndexedDB（資料庫 `redpoint`，`redpoint/db.js`），存之前都過 `validate`：

| store | 內容 |
|---|---|
| `docs` | 畫面（照片）、圖層（線段、bolt）、組合（收到的岩場；首頁也是一個組合，id 在 meta `home`） |
| `photos` | 照片檔（以畫面 id 為 key）；岩場的入口照片以組合 id 為 key |
| `meta` | `home`、`author`（署名）、`sources`（收來或傳上去的網址）、`received`（收下的岩場版本：組合 id → `t`）、`shareShots` |

### 共用照片版面

岩場、區域與 Topo 小卡使用 AppKit 的雙欄正方形照片卡（圖還沒下載好時是閃動的灰底，圖到了才淡入，不顯示半張圖），名稱與副標疊在照片下緣，尺寸、圓角、間距與岩點貓相同。一張 Topo 拍到兩個分區時，照片掛在路線多的那區；另一區借用畫著它路線的那張照片，也有自己的卡片（路線數是那區自己的）。卡片沒有長按動作，分享與刪除在 Topo 頁右上「更多」，刪除需確認；從岩場刪除照片也會移除組合內的參照。岩場頁左上只有返回，名稱留在入口照片上。

照片頁佔滿畫面，上方不保留標題列：返回、在哪顆石頭、分享浮在照片上，尺寸、間距與岩點貓共用。看路線圖預設像相簿一樣，照片等比對齊畫面左右邊緣、垂直置中；路線圖層使用相同縮放與位置。換頁縮放動畫不影響照片的版面尺寸。看 Topo 時起始視角左右滑動換前後一張 Topo，首尾不循環，放大後拖曳照片，手勢與岩點貓一致。

## 桌機版面

與岩點貓共用 `css/desktop.css`：首頁卡片與頁首採一致的內容邊界，設定選單對齊頁首。岩場總覽使用完整的內容寬度，左側入口照片、右側岩壁卡片；開啟 Topo 或路線清單時才切為左右雙欄。確認卡以對話框呈現。Topo 可用一般滑鼠滾輪直接縮放，並顯示縮放按鈕；世界、交通與岩場地圖在桌機顯示地圖控制。
