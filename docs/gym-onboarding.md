# 岩館整合 Climbio：給 AI Agent 的完整流程

你是替岩館經營者（館主）整合 Climbio 的 AI Agent。館主通常不是工程師：**整個流程由你主導**，一開始一次問完需要的資料，之後除了同意公開與驗收，不再打擾他。

目標：館主的牆面照片，變成公開的互動牆；他現有的岩館 App 裡，使用者能看線、定線；定好的路線也出現在岩點貓。

## 規則

- 照片、岩館名稱、牆名稱、App 的做法都**只用館主給的**，答不出來就給選項和建議，不要編造。
- **公開發佈收不回**：牆面與路線公開在 Climbio 的開放資料集（Hugging Face 的 `climbio/walls`，CC BY-SA 4.0，署名）。要聽到館主明確說「可以公開」才發佈，並且每一版都要問；不能替他同意。
- 只改岩館 App 的路線頁；不動他們的帳號、紀錄、資料庫。金鑰、權杖不寫進版控。
- 你能判斷的自己判斷到底（岩點要自己看圖檢查，看不準放大再看），不要把「請人複核」丟給館主。做不到的寫「卡在：…」，不要說已完成。
- 先讀 [AGENTS.md](../AGENTS.md) 與對應文件，不預讀全部文件。

## 第 0 步：一次向館主要齊這些

用**一則訊息**把下面列成清單問館主，等他一次答完（他答不出來的，你提供選項與預設）：

1. **岩館名稱**：公開牆一定要有，找牆面也靠它分組。
2. **牆面照片**：每面牆一張，正對牆面、整面入鏡、不歪斜、光線均勻；告訴你放在哪個資料夾，或直接貼給你。**每面牆的名稱**（例如「主牆」「洞穴」）。換了角度或重拍的照片算另一面牆。
3. **他們的 App**：網頁、iOS、Android、React Native 還是 Flutter；原始碼在哪裡（你能修改的資料夾或 repo）；哪一頁是路線頁（目前怎麼顯示路線、怎麼定線）。
4. **使用者與路線怎麼對應**：例如路線 id 存在他們資料庫的哪個欄位、完攀紀錄怎麼記。Climbio 不管這件事，由他們的 App 決定。
5. **定線規則**：起攀岩點最多幾顆（預設 2，有的岩館是 4）。
6. **同意公開**：說明上面「公開發佈收不回」的內容，確認他可以接受；**等到真的要發佈前還要再問一次**（第 3 步）。
7. **怎麼驗收**：他想在哪裡看成果（測試環境網址、測試版 App）。

## 第 1 步：準備環境

```
git clone https://github.com/climb-io/climbio
cd climbio
node --version
```

需要 Node.js 與能裝 Python 套件的環境（牆面處理會用到）；缺什麼就照錯誤訊息補，補不了寫「卡在」。

## 第 2 步：處理牆面（照片 → 岩點檔）

```
node tools/studio.mjs start gym <工作資料夾> <照片…>
```

照它印出的「下一步」做；之後每一步都只跑 `node tools/wall-batch.mjs next <工作資料夾>`，它會印下一步、要看的圖、判斷準則。流程是：偵測岩點 → 精修外框 → 分級檢查 → **你看圖判斷** → `verify` 通過才算做完。

細節與判斷準則在 [studio-wall.md](studio-wall.md)「代理做牆面」，不要另外發明做法。完成後 `review` 會產出單檔頁面，手機也能看：給館主看最終結果，不問他岩點對不對（那是你的工作），只讓他確認是他的牆。

## 第 3 步：打包，交給後台的「牆發佈」內嵌頁（要館主明確同意）

1. 把結果給館主看，再說一次：公開後收不回、CC BY-SA 4.0、署名。**發佈那一下要由館主或他的工作人員按**，你不能代按。
2. 打包：`node tools/wall-batch.mjs zip <工作資料夾> --gym "<岩館名稱>"`（只有通過 `verify` 的牆才能打包；岩館名稱用第 0 步館主給的），得到 `<工作資料夾>/walls.zip`。
3. 在岩館 App 的**管理後台**放「牆發佈」內嵌頁（做法在 [embed.md](embed.md)「牆發佈內嵌頁」：一個 iframe、`ready` 後送 `init`），請工作人員把 `walls.zip` 丟進去、確認預覽、勾同意、按發佈。沒有後台可放，就把這個 iframe 放在一個只有工作人員看得到的頁面；實在不行，請館主在 GitHub 的 [Issue](https://github.com/climb-io/climbio/issues) 說明，請維護者代發。
4. 發佈成功時內嵌頁回 `published { walls: [{ id, name, version, base }] }`：**記下包 id 與版本**（牆 id 是包裡畫面檔 `<牆 id>.json` 的檔名）。

## 第 4 步：放進岩館 App

細節在 [embed.md](embed.md)（訊息、模式、原生 App 的橋接），照它做：

1. 在路線頁放內嵌頁，**鎖定第 3 步發佈的那一版**（`init` 用 `…/walls/<包 id>/v<版本>/…` 的網址，別人再發新版本也不影響）；網頁用 `<iframe src="https://embed.climbio.app/routekit/v1/?mode=view">`，原生 App 用 WebView 直接開同一網址）。先註冊 `message` 監聽，收到 `ready` 再送 `init { wallId: "<包 id>/<牆 id>" }`。
2. 看線：`mode=view`，換路線送 `setRoute`。定線：`mode=edit`（起攀上限用第 0 步的答案：`&maxStart=4`）。
3. 使用者定完，App 送 `submit`（名稱、難度、暱稱由 App 收）；成功回 `submitted { routeId, routeUrl }`，**把 `routeId` 存起來對應他們自己的使用者**。刪除用 `remove`（只能刪自己這個網站提交的）。
4. 舊路線大量匯入、需要代發金鑰的做法見 [gym-agent.md](gym-agent.md)，一般整合用不到。

## 第 5 步：驗收與交付

- 看線：換成內嵌頁後，路線與原本一致；定線存出來的路線用看線讀得回來；提交後岩點貓重新整理看得到。
- 回報最前面依序寫：**驗收連結、最終結果（牆數、已整合的頁面）、牆的包 id／牆 id**；館主還要決定的事放後面；做不到的寫「卡在：…」，說清楚做到哪、解開後要做什麼。

## 之後更新牆面

- 岩點或外框調整：用同一面牆重新處理並發佈，成為新版本，舊路線照舊；App 不用改。
- 換了照片（重拍）：當成**新的一面牆**，換新的牆 id；App 的 `init` 換成新牆，舊牆的路線不會自動搬過去。要固定在某一版，`init` 用那一版的網址（見 [embed.md](embed.md)）。
- 牆 90 天沒有任何更新（發佈或寫線）會自動從找牆面拿掉；想提早下架請聯絡維護者。
