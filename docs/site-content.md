# 網站與 GitHub 文件分工（AI Agent 需遵守）

## 單一原則

**公開網站寫給人看；GitHub 版控的規格、原始碼與 Agent 規範寫給 AI Agent 讀。**
網站解釋 Climbio 是什麼、哪些能力已可使用、怎麼操作、專案方向與進度，以及如何讓自己的 AI Agent 參與；不要在網頁複製安裝指令、API、JSON Schema、程式碼片段、詳細演算法或 Agent 任務規則。

## 網站內容界線

- 首頁（八語）：產品與使用者入口。四個一般使用者入口仍為岩點貓、朋友互傳、紅點貓、紅點貓收藏。
- `guides/`（八語）：一般使用者的使用說明，Studio、路線書整理與實際拍攝指南。必要的使用操作可以詳細；不要變成 SDK 規格站。
- `project/`（八語）：人類讀得懂的功能狀態、可驗證的公開進度與 AI 參與方式。公開進度以 GitHub commit/issue/release 為準；開發中、計畫中不能寫成已完成，不得編造百分比。
- `kits/`：可展示能力與可互動示例；安裝、整合、授權細則與 API 文件指向 GitHub。Kit 網頁由 `tools/build-kits.mjs` 產生，不能只手動改輸出頁；新文案應改產生器與 `kits/content/`。
- `redpoint-sites/`：給岩場網站經營者看「加入後的用途與條件」，詳細實作看 GitHub。
- `studio/` 是真正可操作的工作台，必要功能、欄位與使用者提示必須保留；不要為了縮短介紹刪除其工作流程。

## AI Agent 入口

- 共同入口：根目錄 `AGENTS.md`，按任務查 `docs/` 與各 Kit README，不預讀全部文件。
- 外部協作與提交方式：`CONTRIBUTING.md`。
- 技術規格、資料格式、可重現測試、部署、AI 工作文件一律以 GitHub 版本檔案為唯一維護來源。
- 網站允許「請把此 GitHub 專案交給 AI Agent」之類的**人類指引**，不要另抄一份 Agent 操作規範到網站。
- 為相容舊版網址而仍保留的靜態工作文件，不應再成為網站的新入口；確認沒有程式依賴後再清除。

## 多語與連結

- 四個一般使用者入口與 `guides/`、`project/` 均須對應八語；不能從其他語言導向英文或繁中作為方便的替代。
- 「紅點貓收藏」的直接使用者入口只有首頁和文件首頁；其他文章可以講功能，但不另外增加連到收藏頁的入口。
- 產品頁的技術連結應直達公開 GitHub 正確檔案；保持網站單純。新頁面需加最基本的連結測試。

## 社群分享 meta

每個獨立頁面都要有 `description`、`canonical`、`og:*`、`twitter:*`（標題、簡介、網址、縮圖）。新增獨立頁面後執行 `node tools/social-meta.mjs` 補齊（可重複執行；頁面內容由語言包動態填入的，標題與簡介要手動寫進標籤）。簡介寫在頁面的 `description`，缺簡介時先補 `tools/social-meta.mjs` 的 `FALLBACK_DESC`。
