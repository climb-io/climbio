# 紅點貓資料藍圖：產品入口、內容風格與推廣計畫

> 2026-11-14 · 產品／網站／內容共同規範 · 工作分支：`dev`  
> 本文件是對外導覽與推廣規畫，不取代 `docs/redpoint.md`、`docs/studio-crag.md`、`format/README.md` 的技術規格。**已實作、需要額外適配、未來構想必須分清楚。**

## 1. 一句話定位

**讓世界各地的攀岩路線，帶得走、找得到、用得上。**

岩友可以收藏現成網站上的岩場；Guidebook 作者可以把舊路線書轉成可編輯的資料；網站經營者可以提供資料入口。紅點貓負責把可使用的路線與 Topo 帶到手機，在沒有訊號的岩壁旁仍能讀取已下載的內容。

不是「再建一個要大家重新上傳的資料庫」。Climbio 提供開放格式、閱讀與編輯工具；資料來源、保管權和公開範圍由提供者決定。

### 明確不做

- 不要求岩友為了看路線先學資料格式或懂 GitHub。
- 不要求岩場網站重建資料庫，亦不要求所有網站必須改成 Climbio 格式。
- 不將「技術上讀得到」等同「法律上可以重新公開」。
- 不把個人收藏當成公開資料來源或世界上的公開指南。
- 不宣稱所有網站、所有文件、所有 Topo 都已支援自動轉換。
- 不把首頁做成互動 App；首頁是成果展示與導引，真正操作在紅點貓或 Studio。

**一般岩友需要完整功能操作時，前往 [紅點貓完整使用說明](../guides/redpoint-manual.html)；**本文件仍聚焦資料生態、推廣與首頁規畫。

## 2. 三條入口，共用一個結果

| 入口 | 使用者 | 一句主張 | 主要 CTA | 實際產品邊界 |
|---|---|---|---|---|
| [收藏岩場](https://climbio-dev.web.app/redpoint-collect/) | 正要出發的岩友 | 下次出發，不用再找一次路線圖 | 下載 Chrome 收藏工具 | 電腦版 Chrome 擴充功能將支援網站的資料轉成公開格式，直接交給電腦版紅點貓保存在本機；可透過「我的裝置」同步到手機 |
| [轉換路線書](https://climbio.app/guides/convert/) | 路線書作者、岩場維護者 | 做過的路線書，不用再做一次 | 開始轉換路線書 | Studio 可匯入／轉換既有資料；AI 為選用；發佈前需核對結果與權利 |
| [串接岩場網站](https://climbio-dev.web.app/redpoint-sites/) | 岩場站經營者、開發者 | 你整理的岩場資料，也能被帶到現場 | 複製給 AI 的網站盤點說明 | 原站格式要有讀取器；若自行提供 Climbio 格式 v2 入口，可省去專站適配 |

對外呈現次序固定：**岩友 → 作者／維護者 → 網站經營者／開發者**。有現成路線資料的人，不應被要求先理解開源架構。

### 資料流與權利範圍

```text
A. 個人收藏（不是公開分享）
支援的岩場網站 → Chrome 收藏擴充 → 電腦上的紅點貓（本機）
                                         ↓ 同步到其他裝置
                                  手機的紅點貓／離線閱讀

B. 網站串接（來源維持原站）
原站公開 URL/API → 網站讀取器 → Climbio 可讀結構 → 使用者選擇下載
              └→ 或網站自行輸出公開格式 v2 + <link rel="climbio">
                                                 ↓
                                          紅點貓本機／離線

C. 作者自主發佈（另需確認授權）
現有 Word／Google 文件／PDF／網站與照片
             ↓ AI 輔助／Studio 轉換
可編輯的 Guidebook → 維護者核對 Topo、GPS、署名與授權
             ↓ 使用者決定公開
Climbio 的開放資料集（CC BY-SA 4.0）＋ 公開索引
             ↓
      紅點貓與其他相容 Viewer
```

**共通底線：**可離線使用的是使用者選擇下載的資料；是否可公開、改作、再分享，必須尊重每一種來源的授權。平台不應將外站收藏內容自動當作公開索引。

## 3. 三頁內容與實作盤點

### 收藏岩場

**保留**：下載 ZIP、Chrome 手動安裝說明、支援網站示例、用「同步到其他裝置」帶到手機、來源授權提醒。

**應明確**：

1. 首屏只講「找到 → 收藏 → 出發前下載 → 到現場使用」，不要把 `chrome://extensions` 放進主標。
2. 現階段電腦 Chrome 擴充需要手動安裝，不要包裝成已上架的一鍵安裝。
3. 帶到手機的路徑以目前介面「同步到其他裝置」（首頁右上頭像）為準；介面改名時一併改頁面、擴充回報字串、測試。
4. 個人收藏保存於自己的裝置；原始作者與照片權利不會因收藏而轉移。
5. 支援網站示例是已對接案例，不代表其中任何頁面都保證能抓到照片、Topo 或完整路線。

### 轉換路線書

**保留**：AI 轉換提示的單一來源 `studio/crag/ai-prompt.js`、複製功能、ZIP 及本機匯入、預覽、修正、地圖／GeoJSON、實測案例、FAQ、詳細 Markdown 大綱。

**應明確**：

1. 首屏以「省下重做時間」為主，不先談 AI、ZIP、GeoJSON。
2. 表達成「嘗試自動描線；不能描出的路線可用記號調整」，不能保證每條都正確。
3. 不再使用「轉完就是最終結果／不必確認」等語句；發佈前至少確認位置、路線編號、來源和授權。
4. Studio 是編輯與發佈者，紅點貓是閱讀者；Studio 使用 Climbio 母品牌 Logo，不能另做 Studio 貓 Logo。
5. 既有文件的真實實測數據要標明是案例，不能視為對所有路線書的承諾。

### 串接岩場網站

**保留**：HTTPS、CORS、資料與 Topo 座標說明、授權、`for-ai.txt` 複製、公開格式 v2 的 `rel="climbio"` 入口、龍洞範例。

**應明確**：

1. 首屏以「保留自己網站」為主；開發規格放在下方。
2. **兩種路線不可混為一談**：原站格式需要新讀取器；原站若直接輸出公開格式 v2，可由通用入口讀取。
3. AI 在第一階段是「盤點現有 API／檔案」，不應擅自修改原站或生成不存在的資料。
4. 提供 CORS 只是技術條件；還需來源正確、格式可解析、授權可使用。
5. 原站資料沒有授權時，不應把它標成 CC BY-SA 4.0；開源程式授權與內容授權各自獨立。

## 4. 視覺與文字系統

### 品牌

- 三頁使用同一支 CSS：`css/redpoint-outreach.css`，以 `css/brand-tokens.css` 戶外色票為基礎。
- 正式母品牌圖樣用 `icons/brand/climbio-horizontal-light.svg`；紅點貓使用 `icons/cats/redpoint-cat.svg`，不可重畫或用相似造型替代。
- 正式戶外介面：背景 `#F7F9FB`、卡片 `#FFFFFF`、文字 `#0C1C2B`、操作色 `#0B4A6B`、輔助藍 `#2E8CC9`；紅點 `#FF6B6B` 只當角色點綴，勿當一般 CTA。
- 使用**已完成、經確認**的真實岩壁攝影或實際紅點貓 Topo 畫面，避免虛構 UI、開發中有明顯破洞的 3D 模型與過度裝飾。**不得在三個推廣頁或首頁使用 `demo/crag.jpg` 作為成品示範**；現階段優先使用已上線的真實操作截圖（`https://climbio-redpoint-demo.web.app/desktop-topo.png`），保留完整畫面、不裁切重要路線資訊。後續若找到已確認授權與品質的真實岩壁照片，再逐頁替換。
- 大標題一個結果；正文短段；主要 CTA 一個；次要 CTA 最多一個；需要技術細節的讀者往下看。
- 手機版先看主張與 CTA，照片移到其下；卡片改單欄；字體、按鈕保持相同尺度。
- 依 `prefers-reduced-motion` 減少動態；圖片含 alt；選單、按鈕可鍵盤操作。

## 5. 首頁入口設計

首頁依序介紹岩點貓、Studio Wall、Studio Crag、紅點貓收藏、紅點貓和 Climbio。每幕使用一張照片和一段文字，前五幕各有一個圖示入口。第六幕先顯示文案，再將文案上移，岩點貓、紅點貓、紅點貓收藏、Studio、文件、Hold Lab、3D Lab 和 GitHub 的入口在同一張照片上出現。

首頁依裝置語言顯示繁中或英文。讀者可點擊照片或文案、向左滑動，或按右方向鍵前進，也可向右滑動或按左方向鍵回上一幕。輪播在第六幕顯示完整入口後停住。裝置選擇減少動態效果時，採用手動換幕，第六幕直接顯示完整入口。舊的 `#redpoint-data` 和 `#developer` 連到文件對應段落，`#redpoint` 保留路線書場景，`#studio` 連到 Studio。

## 6. 推廣計畫

### 第一階段：先驗證三條完整體驗

優先以龍洞與已能確認權利的岩場資料當示例；若展示外站資料，清楚標來源，不把其內容納入自己的公開發佈。

- **收藏體驗**：電腦開啟支援網站 → 下載／安裝擴充 → 收藏一個岩場 → 電腦上的紅點貓收下 → 「同步到其他裝置」傳到手機 → 飛航模式仍能看已下載 Topo。
- **轉換體驗**：作者提供一份有權處理的路線書 → Studio 預覽 → 描線／保留可調整記號 → 作者確認 → 發佈到 Climbio 的開放資料集 → 紅點貓打開。
- **網站體驗**：現有網站整理公開資料網址 → 測試 HTTPS、CORS、示例回應與授權 → 能直接輸出格式 v2 則提供 `rel="climbio"`；否則開立讀取器支援任務。

### 第二階段：做可分享的真實示範

每條入口只需要一段簡短的真實畫面，不重做第二個可操作 App：

- **岩友 15–30 秒**：「在網站找到 → 按收藏 → 手機看 Topo → 離線畫面」；拍真實流程。
- **作者 20–40 秒**：「原本的路線書 → Studio 預覽 → Topo 可點 → 紅點貓成果」。
- **網站 15–30 秒**：「原站保留 → 資料入口 → 紅點貓閱讀」，避免用不存在的一鍵串接動畫冒充功能。

紅點貓實際 App 演示影片已另行產出，但首頁目前採用照片和文字；三頁的示範影片未產出前，以真實岩壁照片及簡明流程即可，不增加虛構展示。

### 第三階段：分眾溝通

| 對象 | 主打痛點 | 導流到 | 可用內容 |
|---|---|---|---|
| 一般岩友、出國攀岩者 | 出發前反覆截圖、印 PDF，現場網路差 | 收藏岩場 | 30 秒離線收藏示範、實際支援來源 |
| Guidebook 作者、開發路線維護者 | 已整理多年，不想重新畫線與重輸入 | 轉換路線書 | 作者同意的前後對比、校對步驟 |
| 地區岩場站、路線網站作者 | 不想再維護另一份同步資料 | 串接岩場網站 | 龍洞輸出範例、AI 盤點模板 |
| 開源開發者 | 想直接讀／寫格式，不想依賴整個 App | GitHub 格式與 Kits | 最小格式、驗證器、獨立元件範例 |

**發布素材原則**：先由本人或來源授權的例子起步；公開每份照片、Topo、路線資料時都要確認授權。推廣素材不可暗示已經與外站官方合作，除非確有合作。

### 第四階段：建立可持續參與的循環

1. 岩友因離線功能使用紅點貓，發現個別岩壁仍缺照片與定位。
2. 向作者或維護者分享「轉換路線書」入口，而非自行公開轉載。
3. 維護者將自己的資料整理發佈，或讓既有網站提供可讀入口。
4. 新的 Guidebook 更好用，帶動下一批岩友收藏與回報。
5. 更新仍由原維護者負責；紅點貓只讀取使用者獲准讀取的版本。

### 驗收重點

- 三個頁面與首頁各有**一個主要目的**，瀏覽 5 秒可分辨入口。
- 在窄手機（約 375 px）、平板（768 px）、桌機（1440 px）檢查斷行、圖片、按鈕及連結；並測鍵盤焦點。
- `for-ai.txt` 的複製按鈕、Studio AI 提示複製、收藏 ZIP 下載在實際部署環境皆可使用。
- 原本導向 App／Studio 的連結不能失效；跨頁路徑在開發站與正式站均可正常解析。
- 所有展示資料保留來源與權利說明；私人收藏不可誤標成公開 Guidebook。
- 有關位置：天然岩場的**發布位置**必須是實際且可確認的座標；若照片用來進行 GPS 地理校正，必須取得可驗證的原始拍攝 GPS。只有一般路線照片、沒有照片 GPS 的 Guidebook 仍可以在核實岩場位置後閱讀／編輯，不能虛構照片 GPS。
- 可量測三個導流卡點擊、安裝說明到下載的轉換、首個岩場成功離線的回報，以及維護者完成首次發佈的比例；採自願、低個資方式，不因量測導致集中保存使用者路線內容。
