# 代理做完、人驗收

所有 AI 代理（不分引擎）接到任務，共用一條大原則：**AI 把工作完整做完、自己驗證，最後的結果交給人驗收。** 人不做中間的複核，也不替代理收尾。

## 做完的標準

- AI 能判斷的都自己判斷到底；不確定的把照片放大、換角度再看，定案後把理由記下來。**不留「請人複核」的清單。**
- 人只答 AI 不能代替的決定：要不要公開發佈（公開就收不回）、資料裡沒有的事實（例如岩場位置）、照片明顯不夠要不要補拍。
- 結果真的寫進資料，用工具重算數字；只改文件、或回報裡說「已更新」但資料沒變，不算完成。
- 做不到的部分寫「卡在：…」，說明做到哪、解開後的下一步；不編造結果、不說「已完成」。

## 驗收要在原本的 AI App 上直接看

驗收的人不必打開終端機或別的工具。依成果放在哪裡，給能直接點開的連結：

| 情況 | 給什麼 | 例子 |
|---|---|---|
| 已部署到雲端 | 測試站網址（`https://…`），手機直接開 | 3D 牆發佈後的岩點貓連結、`climbio-dev.web.app` 上的頁面 |
| 沒部署雲端（僅限同機自驗） | 本機的虛擬連結（`http://127.0.0.1:<埠>/…`），代理在本機開好伺服器；**僅限驗收的人就在同一台電腦上**（跨機或手機驗收仍須部署測試站或發單一檔案） | 3D 牆的 `node tools/studio.mjs try3d <資料夾>` |
| 單頁就能看完 | 把成果整理成單一檔案（圖都內嵌、手機寬度），發成 AI App 能直接打開的形式 | 岩館牆面的 `review/index.html` 發成 Artifact |

規則：

1. **連結先自己打開驗證**：回 200、顯示的是新資料（不是舊的）、數字和文件一致，再回報。
2. **版本要寫清楚**：驗收的是哪一版（版號或提交編號）；內容之後又改了，要重新給連結。
3. **回報最前面依序寫**：驗收連結、最終數量或結果、提交編號或專案資料夾路徑；等人答的題放在後面。
4. 人的判斷一律由人親口答，代理記下原話；代理不替人按「驗收通過」或「發佈」。

## 各種任務怎麼接上

- Studio 的新任務（岩館牆面、岩場照片、路線書、3D 牆）：先跑 `node tools/studio.mjs start <類型> <資料夾>`，它印下一步與完成標準，見 [studio-work.md](studio-work.md)。
- 岩館牆面的岩點檔：[studio-wall.md](studio-wall.md)「代理做牆面」。
- 3D 牆：[studio-work.md](studio-work.md) 的 3D 牆列（`try3d` 一鍵試用）。
