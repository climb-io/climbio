# 開發與驗證

## 真實帳號測試

公開分享與本機功能測試應使用隔離的測試資料，不依賴個人或共用 Google 帳號；不得把正式使用者資料、存取憑證或裝置金鑰寫進測試資料與版控。

瀏覽器擴充功能須安裝在實際使用的 Chrome 設定檔，使用獨立測試資料測收藏與紅點貓本機匯入；程式模擬測試使用替身，不能連線修改正式資料。

## 測試的新增、保留與清理

測試是為了防止**仍在使用的功能退化**，不是為了累積測試數量、檔案數或覆蓋率。先看現有測試能否保護這次改動，不要求每次修改都新增案例。

1. **新增前先找重複**：先找同模組、同使用流程已有的測試；優先擴充或整併現有檔案。只有獨立模組、不同測試層或明確需要隔離時才新開測試檔。
2. **必須說得出要防什麼錯**：核心資料格式、資料保存／刪除／同步、權限與公開發布等高風險行為優先保護；一般功能按可能發生的退化補足必要案例。純文件、註解與不改行為的整理，不為了有測試而造測試。
3. **驗證真正的行為**：以真實被測程式執行，檢查輸出、持久化結果、畫面操作或錯誤處理；外部 API／模型可以用替身隔離。不能只設定假資料再驗證同一份假資料、重複驗證固定文字或實作細節，卻抓不到功能壞掉。新增案例應能說明「哪種錯誤會讓它失敗」。
4. **修 Bug 優先做回歸**：可重現時，先用最小案例證明修復前會失敗，再修到通過；避免為同一 Bug 在 Node、瀏覽器及多裝置各複製相同斷言。測試放在最便宜、足以抓到問題的層級，跨層只保留必要的使用者流程。
5. **功能退場就一起清理**：已刪除的產品、功能、入口或資料格式，對應測試、fixture 和文件一起刪除；不為不存在的功能保留相容性測試。若目前仍有實際呼叫者，應指出呼叫點再判斷，不能只因舊名稱就判定可刪。
6. **改動回報精簡**：新增或大幅調整測試時，用一兩句說明保護的風險、為何現有案例不足；刪除或整併時說明不再保護的舊行為。列出**實際跑過的**檢查及結果，未跑不得說通過。

## 依產品跑測試

每個測試檔恰好屬於一個產品（`tools/test-groups.mjs`：hold 岩點貓、redpoint 紅點貓、studio Studio、kits 開源元件、shared 共用層、backend 雲端函式、tooling 開發工具、wall3d 3D 牆實驗）。改哪個產品就只跑它的，不必等別的產品的測試：

```sh
npm run test:product -- --list                # 各產品的測試數量
npm run test:product -- redpoint              # 紅點貓的 Node 測試
npm run test:product -- studio --e2e          # Studio 的 Node 測試，再跑它的瀏覽器案例（Chromium）
npm run test:product -- hold shared           # 改了共用層：加跑用到它的產品
```

改到 `appkit/`、`site.js`、`backend/` 這類共用層，除了 `shared`，再加跑用到它的產品；改 `routekit/`、`topokit/`、`mapkit/`、`format/` 跑 `kits`，再加用到它的產品。新增測試檔時在 `tools/test-groups.mjs` 加進對應的產品，`tools/test-groups.test.mjs` 會擋掉沒歸屬或重複歸屬的檔案。Node 測試不會卡住：每個測試最多 2 分鐘，跑完就結束（沒關的伺服器、計時器不等）；卡在無窮迴圈、3 分鐘沒有輸出就整組強制停掉（不留空轉的子行程），印出卡在哪個測試，結束碼非 0（`TEST_IDLE_MS` 可調）。Node 22.8 以上時測試共用一個程序（`--experimental-test-isolation=none`，舊版一個檔案一個程序），測試改全域變數（`location`、`document`）要在結束時還原，不能刪掉別的測試檔設的。瀏覽器測試一次只跑一組。

**核心**（格式、權限、資料完整性、同步、發布）必須保有有效測試；**功能**測試隨受影響模組執行；**視覺與細節**測試重點檢查真實使用情境並整併重複案例。日常仍依下節跑最小必要驗證；完整回歸只在使用者要求時執行。不以提高覆蓋率為理由擴增低價值案例。

## 本機先驗證改動範圍

每次推送與正式版發布，預設先跑 `npm run check`（語法、語言包），再依實際改動選最小的 Node 測試與 Chromium 瀏覽器案例；完整回歸只在使用者明確要求時執行。
```sh
npm run check
npm run test:smoke                       # 冒煙（CI 也跑）：示範牆存入、RouteKit、沒有後端的分享與收線
npm run test:e2e                         # 只有使用者明確要求才跑完整回歸
```

| 改動 | 本機瀏覽器驗證範圍 |
|---|---|
| 文件、註解、Node 邏輯、部署 workflow | 不跑瀏覽器；工具／workflow 本身做對應驗證 |
| 新增牆面（裁切、分析畫面） | 內部 e2e 案例 |
| 沒網路時的處理（分享、補下載照片） | 內部 e2e 案例 |
| Service Worker 首裝、離線重開、部署新版後第一次開（直接是新版、不重新載入；一般網路與慢速 4G）、開著不動時的更新提示 | 內部 e2e 案例 |
| 滑線、路線圖繪製 | 內部 e2e 案例；改共用開啟／儲存流程時再加示範牆冒煙案例 |
| `routekit/`（路線的繪製、快取、定線規則、元件） | Node 測試（quick）、`routekit.spec.mjs`，再依改到的部分加滑線、小卡（`card-base`）、分享預覽、操作示範膠帶（`tour-tape`）、順序（`seq-tap`）的案例；改快取或底圖時比較大牆案例的指標（`large-wall-metrics.json`） |
| `mapkit/`（向量地圖的看圖與編輯） | Node 測試（quick）、內部 e2e 案例 |
| 牆面頁路線清單（排序、完攀篩選、長按選單、小卡版面） | 內部 e2e 案例 |
| 補點、輪廓、長按、放大鏡 | 內部 e2e 案例；改模型啟動時加 內部 e2e 案例 |
| 分享預覽、匯出 | 內部 e2e 案例 |
| 分享與統計 | 內部 e2e 案例；依受影響流程選 `mobile.spec.mjs` 案例 |
| 桌機裝置判斷、分享預覽 | 內部 e2e 案例（桌機／觸控筆電／手機／平板／standalone），再選 內部 e2e 案例、手機分享與收線、內部 e2e 案例 |
| 安裝、開場、操作提示、語言 | `mobile.spec.mjs` 中相關案例；必要時用 內部 e2e 案例 與 內部 e2e 案例 |
| 全域版面、共用 CSS、平板 | 受影響功能案例加 內部 e2e 案例，檢查截圖 |

選案例依行為與呼叫關係，不只看檔名；新增行為沒有覆蓋時補必要案例。已通過且未再修改的範圍不重複跑。瀏覽器與 UI 案例須檢查截圖；自動測試不能代替實機配對、系統分享或手勢驗證。

沒有瀏覽器的環境（例如雲端）先裝好，版本要跟 `package.json` 的 `@playwright/test` 一致（升級 Playwright 時一起改）：

```sh
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers npx -y playwright@1.64.1 install --with-deps chromium webkit
```
