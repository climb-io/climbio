# 分享與備份

核心原則是自由定線、一鍵分享，不打擾使用者。編輯結果先存在裝置，備份與復原見 [backup.md](backup.md)。使用者按「分享」即可分享圖片或路線連結；公開牆面的資料依公開發佈流程處理；「朋友互傳」只傳送使用者選取的內容，「我的裝置」則會在配對驗證後自動同步缺少或較新的個人資料。分享操作不要求使用者理解底層儲存、身分驗證或金鑰。

## 使用者看到的行為

### 已發佈牆面

使用者可主動從公開牆面或分享連結收下內容；單純開啟 App 不會自動下載其他裝置的內容。個人資料可使用本機備份／復原，或在兩台已配對裝置同時開啟「我的裝置」時自動雙向同步；兩者都不是背景雲端備份。

### 分享

分享畫面只有一頁：路線圖預覽（限時動態 9:16，風格、尺寸由路線自動決定）和兩顆分享目標，沒有短影片、短句、風格選項。

| 目標 | 做什麼 |
|---|---|
| 圖片 | 系統分享路線圖的圖片，只在本機產圖：不會上傳，也不附路線連結，離線也能使用。圖片做好才分享（iPhone 要在按下的當下呼叫分享，圖還在畫時按下會提示再按一次） |
| 連結 | 系統分享路線連結（只有連結，不附文字與圖片）；連結還沒好時按下不分享 |

按「連結」時：

1. 首次分享路線連結：顯示暱稱與內容授權確認；暱稱不可空白。確認後繼續分享。**路線連結只給公開牆**（Studio 發佈的牆，收下後 `pub` 為 1）和 3D 牆；手機自己拍的牆沒有連結按鈕，只有路線圖片，要給朋友走附近交換（見下面的「附近交換」）。App 不上傳牆的照片和岩點，牆只由 Studio 公開到資料集。
2. 後續分享：按下分享後產生可傳送的連結；失敗時顯示原因與重試，不要求額外帳號操作。
3. **公開牆資料**：牆的照片與岩點由 Studio 發佈到公開資料集 `climbio/walls`；App 在公開牆上分享路線只傳遞該路線（`Backend.shareRoutes`：牆沒有公開就丟 `code: 'private'`、什麼都不傳）。雲端函式也擋：`datasets` 的 `publishWall` 和 `walls` 的 `publish` 都要帶 `source: 'studio'`，沒帶（岩點貓、舊版）回 400 `studio only`。每條公開路線由裝置金鑰簽章確認作者，公開資料與個人備份分開。

   **授權**：分享公開牆的路線不問暱稱、不另外同意，直接傳、直接給連結；授權就寫在條款與隱私權政策：路線公開在這面牆上，任何人都能看、能下載，CC BY-SA 4.0，署名是目前的暱稱（沒設定就不署名；暱稱可從頭像選單改）（[terms.html](../terms.html)、[privacy.html](../privacy.html)）。

   **下載來的公開牆先是私人牆**：收下（`saveSnap`）時不標公開（`pub` 為 0），新增路線、定線、分享路線連結都不問授權；伺服器確認這面牆是公開牆（`pullWall`）才記 `pub`，之後才有連結與分享。同意畫面只留決定需要的內容：標題、暱稱、一段資料集說明、按鈕、條款連結。

   **公開牆資料流**：Firestore 的 `datasets/{包 id}` 與公開牆索引只記種類、版本與檔案資訊；照片、縮圖及岩點檔案儲存在公開資料集 `walls/<包 id>/v<版本>/`，路線更新存於 `wallRoutes`。
   - **岩點貓收牆**：找牆面清單（`/w/gym/…`，伺服器快取）裡每面牆的入口和縮圖直接是資料集的網址（版本在路徑裡，內容不變，Hub 的 CDN 送），不經過函式、不讀 Firestore；一次下載整面牆（圖層、畫面、照片）到手機，之後離線看。`/p/<包 id>/<檔>` 也導向資料集，不存副本。
   - **研究者**：只下載根目錄的 `walls.jsonl`（每面牆一行：大小、岩點數、有沒有精修、逐顆檢查完沒有…）就知道要哪些牆，再用 `allow_patterns` 只抓那些牆的最新版；說明在資料集的 `README.md`（原稿 [walls-dataset-card.md](walls-dataset-card.md)）。
   - **路線**：大家定的線留在 Climbio 的 `wallRoutes`（岩點貓要即時看、改），路線有變動就馬上由函式把 `walls/<包 id>/routes.json` 和 `index/world.json` 的那一行寫進資料集（`hf-public.js`）；每天一次（排程 `daily`）更新 `walls.jsonl` 的路線數與統計。
   - **天然岩場**：Guidebook 及 Topo 公開成品放在 `climbio/crags`，`datasets` 索引供紅點貓「世界」與固定分享網址讀取。Studio Crag 發佈使用 `prepare` 取得上傳位置，照片直傳資料集，完成後由 `publish` 登記；每次發佈建立新的專案 id，以 `origin`、`root` 與 `lineage` 關聯版本。世界清單按同一來源的版本群組顯示，公開資料集保留發佈內容。
   - **3D**：室內 3D 牆放 `climbio/walls3d`（`walls3d/<id>/`，專案 `type` 是 `wall3d`），天然岩場的 3D 模型放 `climbio/crags3d`（`crag3d`；大砲岩的模型從 Guidebook 複製一份進來，Guidebook 裡的照舊給紅點貓用）。做法跟岩場一樣（`prepare` 取 Hub 上傳網址、模型由瀏覽器直接傳、`publish` `hf: true` 一次 commit），單檔上限 400 MB、整包 1.5 GB；Studio 3D 牆公開發佈走這條，尚未公開的專案仍保存在作者自己的裝置或資料夾。說明：[walls3d-dataset-card.md](walls3d-dataset-card.md)、[crags3d-dataset-card.md](crags3d-dataset-card.md)。
   - **統計**：同一個排程把整份數字寫成資料集的 `stats.json`（資料集大小、岩點、路線、精修記錄、Firestore 各集合文件數），[統計頁](https://climbio.app/stats/)（`stats/index.html`）直接從 Hub 讀，不經過任何函式。
4. 傳完 iPhone 常不讓接著分享：提示再按一次，第二次直接分享。

3D 牆路線可用包含路線資料的網址分享；未提供雲端分享能力的自架站仍可產出本機路線圖片。

兩款 App 共用一個暱稱（`climbio.nickname`，最多 40 字且不可空白），供分享圖片、路線與岩場顯示；暱稱可隨時從頭像選單修改。

首頁不顯示待分享入口或數量，路線頁保留一般分享按鈕。**讀取走 CDN 快取**：App 讀公開牆的線是 GET `/w/<牆 id>/shared.json`（Hosting 快取 60 秒，全部使用者共用，雲端函式每面牆每分鐘最多跑一次，跟使用者人數無關），App 每面牆最多一分鐘讀一次；新增、刪除的線其他人最慢約一分鐘就看得到；`u` 是作者金鑰的雜湊，自己用金鑰算同一個值就知道哪些線是自己的。寫入（存線、刪除）才是一次函式呼叫。**Studio 公開牆上定好的線（有起攀、完攀）改完停 30 秒（切到背景馬上）自動公開**，上傳不先問牆有沒有公開，牆不是公開牆時伺服器回 404（`js/sync.js` 的 `autoShare`），不用按分享，授權條款是 CC BY-SA 4.0、署名暱稱，不另外同意；沒有暱稱、沒網路就先留在本機，下次存線再傳。手機自己拍的牆和朋友分享來的私人牆不上傳。自己的路線隨時可以刪，刪了就從公開牆撤回；失敗時保留本機資料。

牆面小卡只標示公開的牆：顯示地球。圖片與未分享不顯示圖示。

收到的分享仍可收下、檢查作者更新。

### 連結預覽

連結分享只送網址，沒有任何個人化文字（個人化只在圖片）；貼進聊天軟體的卡片由預覽頁決定，每個層級都有對應的預覽頁，標題、說明、縮圖在 `functions/share-preview.js` 統一組句，讀不到的欄位省略，預覽不因此失敗：

| 層級 | 連結 | 標題 | 說明 | 圖 |
|---|---|---|---|---|
| 岩點貓路線（含 3D 牆的線） | `/r/<牆 id>/<路線 id>/` | 路線名稱＋難度 | 岩館・牆名・岩點數・定線者 | 牆的縮圖 |
| 岩點貓公開牆 | `/r/<牆 id>/` | 牆名稱 | 岩館・路線數・岩點貓 | 牆的縮圖 |
| 天然岩場 | `/p/<專案 id>` | 岩場名稱 | 岩場節點名・路線數・紅點貓 Topo | `preview.jpg` |
| 岩場裡的一張 Topo | `/p/<專案 id>?at=<Topo id>` | Topo 名稱 | 岩場名・路線數・紅點貓 Topo | `preview.jpg` |
| 3D 牆 | `/p/<專案 id>` | 牆名稱 | 岩館・3D 牆・岩點貓 | `thumb.jpg` |

岩點貓路線的預覽頁已經查到這條路線的圖層，轉進 App 前存進 `sessionStorage['climbio.handoff']`（`{ url, doc }`，預覽頁與 App 同源同分頁；岩場預覽頁交的是入口 `index.json`，紅點貓讀同一個網址時直接用），App 網址對得上才用、只用一次，收線不再呼叫一次 `route.json`；存不進去（無痕、換瀏覽器）就照常下載。預覽頁在轉進 App 前先畫出標題、說明和模糊的縮圖版面（同源換頁會留著這一頁到 App 畫出來），點開連結馬上有東西看，不是空白。人打開預覽頁就轉進 App 收下（岩點貓路線進 `/?p=&r=`，3D 牆的線進 `/hold/?m3d=&rid=`，岩場進紅點貓 `?topo=`）。沒有公開的資料（紅點貓收藏的外站來源 `?topo=<網址>`）沒有預覽頁，連結本身就是來源網址。

### 朋友互傳

「朋友互傳」與「我的裝置」是不同用途（共用 `appkit/nearby.js`，雲端函式 `nearby` 只協助裝置相互找到，不存交換內容）：

| | 朋友互傳 | 我的裝置 |
|---|---|---|
| 入口 | 岩點貓與紅點貓首頁「＋」→「傳給朋友」（朋友分享不放在世界或找牆面的子頁） | 兩個 App 的更多選單「同步到其他裝置／我的裝置」（`mode: 'devices'`） |
| 要不要配對 | 不用 | 要，一次 |
| 方向 | 單向，我送你收（`mode: 'send'`） | 雙向、自動 |
| 收的人 | 手動按「收下」（或「拒絕」） | 不用動 |
| 金鑰、攀登記錄 | 不給 | 一起同步 |
| 個人收藏 | 紅點貓可主動選取傳送 | 一起同步 |

- **找人**：打開就加入房間（房間是對外 IP 的雜湊，IPv6 取前 64 位元）；未配對的人看到的名字是每次開啟畫面產生的四位匿名代號（例如「岩點貓 4821」「紅點貓 7392」，同名再加暫時識別碼）；本機暱稱由 `AppKit.nearby.nickname()` 管理，兩款 App 共用；`deviceName()` 自動組合「暱稱＋裝置類型」僅在配對後交換，沒有獨立的裝置改名設定。每個人一條連線（`links`），可以同時連很多人。
- **朋友互傳**：附近的人是勾選清單（可全選），要傳的東西也是勾選清單；按「傳給 N 人」就同時傳給所有勾選的人（一批最多 8 人，其餘排隊；同一項只打包一次），每個人各自顯示「等對方收下／傳送中 3/5 · 40%／已傳送／對方沒有收下」。收的人看到「○○ 想傳 N 項給你」，按「收下」才收（沒按之前對方的檔案一律不收）。不帶金鑰、攀登記錄，也不會自動收對方的任何東西。紅點貓的個人收藏可由使用者明確勾選傳給朋友，但必須自行確認第三方資料的轉傳權利；這不會讓資料公開發佈。教練傳給很多學員、朋友互傳都用這個。
- **掃 QR code 連線（不用伺服器）**：未設定 `SITE.cloud.nearby`，或連續兩次無法連上連線服務時，「朋友互傳」下方才出現「顯示 QR code」「掃 QR code」；伺服器正常但附近沒有人，不會顯示 QR 備援。一方顯示 QR code（WebRTC 的 offer，壓縮後約 500 位元組，只帶區網候選），另一方掃了再顯示自己的（answer），第一方掃回去就連上；連上後對方出現在「附近的人」裡，一樣勾選傳送。沒有 `SITE.cloud.nearby`（自架的站、後端 none）時只有這個。
- **我的裝置（永久配對、自動同步）**：點「加入新裝置」，另一台也點「加入新裝置」，在這台的清單點它：兩台顯示同一組 4 位數確認碼（SHA-256(兩邊的亂數) 的後四位），都按「一樣，確認」才配對（避免配到岩館裡別人的手機）。配對前只看到匿名代號，雙方確認四位碼後**真實裝置名稱才自動交換**，之後兩邊都顯示對方暱稱與裝置類型（重新連線時會更新）；每台存一把只有彼此知道的密鑰（`localStorage` `climbio.nearby.pairs.<app>`：`[{ psk, name, last? }]`，用密鑰認人、不用名字，岩點貓、紅點貓各自配對）。打開「我的裝置」頁，配對過的裝置出現就自動連、同時連好幾台（兩台都想連時 id 小的留下），連上後互相用密鑰證明（HMAC，`proof:<驗證者亂數>:<證明者亂數>`），證明過才同步：各自把對方沒有或比較新的送過去，收到的自動收下；比較新看每項的 `t`（紅點貓：組合的修改時間；岩點貓：路線 id 加修改時間，改過的線會再傳），沒有 `t` 的照 `v` 的涵蓋。每台顯示「在線／離線」「同步中／已同步 · 送出 N · 收到 M」「離線 · 上次同步 3 天前」。同步的還有：岩點貓的完攀記錄與哪些線是我出的、3D 牆的路線（模型各自下載）、裝置金鑰（兩台配對就是同一個人：這台沒有就用對方的；各有一把就都留著，`climbio.deviceKey.more`，兩台都能改兩把金鑰寫的線，寫入被擋（`taken`）時換另一把重試）；紅點貓整份攀登記錄（`__logs__`）自動同步，不用對方有那個岩場，所以可以直接備份到自己的電腦。**刪除不同步**；攀登記錄只增不減。取消配對在「我的裝置」頁每台旁邊。
- **配對房間**：配對過的裝置另外用「配對房間」（密鑰的 SHA-256 前 24 碼，`pairRooms`）在伺服器上互相找到，伺服器回傳的人帶 `via`（是哪個配對房間找到的），客戶端據此知道是哪一台：同一個區網但一台走 IPv4、一台走 IPv6 時，IP 房間不同，配對房間仍然對得上（伺服器看不到密鑰，只看得到雜湊）。同步只在兩台同時打開「我的裝置」、而且所在網路允許裝置直連時發生；列表以「同步中／已同步／離線」逐台顯示狀態，不放常駐操作說明，只有首次配對或連線失敗才提示網路條件。不在可直連的同一網路時用備份檔。
- **入口提示**：第一次用過之後（紅點貓：收下第一個岩場、岩點貓：出完第一條路線）首頁上方出一次可關閉的卡片，按下去進「我的裝置」；關掉、配對過、或正在顯示「加到主畫面」時不出現（`redpoint.syncHintX`、`climbio.syncHintX`）。
- **傳什麼**：岩點貓＝牆面（一面牆連同照片、岩點、這面牆上所有路線；3D 牆只在「我的裝置」傳路線），紅點貓＝岩場或 Topo（跟分享連結同一種打包）；朋友互傳可將紅點貓的個人收藏直接傳給朋友，朋友收下後仍是本機資料，不會自動變成可公開發佈；公開連結／Studio 發佈仍依原授權檢查。
- **資料不經過伺服器**：資料走裝置之間的 WebRTC DataChannel（不設 STUN／TURN，同一個網路用區網位址直連，所以不連任何第三方）；雲端函式只轉送連線訊息（offer、answer、ICE），不碰資料。一次最多 150 MB、2000 個檔案，收的人也照這個上限檢查。
- **收下怎麼存**：包放在記憶體（`ShareTools.open` 認得 `mem://<包>/<路徑>`），收下時走既有的讀取流程（岩點貓 `ShareTools.fetchWall`＋`saveSnap`，紅點貓 `fromUrl`＋`saveGot`），存好就丟掉。岩點貓收來的牆只留在這台（不算公開牆、不查公開路線），路線的 `own` 一律是 0；紅點貓收來的沒有可以回頭查更新的網址（不記 `sources`）。再收同一份內容視為更新：岩點貓路線依路線 ID 合併，兩邊已有的同一 ID 依修改時間處理；點位相同但路線 ID 不同的線可以並存。
- **連不上**：訪客或公司 Wi-Fi 可能不允許裝置互相連線（用戶端隔離），20 秒連不上就說明原因；對方離開或連線中斷，畫面說「連線中斷」。要求：瀏覽器支援 WebRTC（不支援就不顯示入口）；自動找人另外要有 `SITE.cloud.nearby`（主網有）。
- **雲端函式 `nearby`**（`functions/nearby.js`）：`join`、`poll`（續命並收訊息；帶 `wait`、`sig` 就保持開著，附近的人有變動或有訊息才回，最長 55 秒，客戶端中途斷線就立刻刪掉自己的文件）、`send`、`leave`；Firestore `nearby/{代號}`（房間、App、匿名名稱、最後出現時間；不可存使用者自訂的真實裝置名稱）、`nearbyMsgs/{…}`（待收的訊息，收走就刪）；70 秒沒 `poll` 當作離開，`cleanSnaps` 每天掃掉過期的。客戶端沒有任何操作 55 秒就自己離開（顯示重新尋找的圖示，點了才再開始），不讓人放著給別人隨時連。只用 Admin SDK 存取，不開放 Firestore 規則。訊息最多 16 KB、每人最多 60 則待收。

### 暱稱與公開

- **只有公開一種連結分享，沒有分享方式可選**：不需要暱稱也不另外同意條款（有暱稱就署名），傳送是自動的；暱稱可從兩款 App 的頭像選單改。圖片不更動分享包。
- 傳成功的牆記 `w.share = 'public'`、`w.pub = 1`，小卡顯示地球。失敗保留原本的狀態，可在下次按連結時重試。
- 手動備份保留為私有檔案，不套用分享權限。
- 給身邊的朋友互傳用朋友互傳，收下的牆只留在那支手機，不算公開牆。

## 公開資料與路線權限

- **公開牆與路線**：牆面第一次公開時上傳照片、縮圖與岩點。路線資料存於 `wallRoutes/{照片編號}`，每個路線 id 對應獨立的修改時間、內容與作者金鑰；路線 id 在收線、再分享與「我的裝置」交換時不變。路線修改只影響該 id，其他人的路線不覆寫。
- **編輯權限**：建立路線的裝置第一次需要公開寫入時，在背景建立 ECDSA P-256 裝置金鑰；金鑰公鑰指紋 `kid` 是作者識別。後端 `functions/device-key.js` 驗證 `put` 等寫入簽章及重放保護，只有同一作者金鑰能更新或撤回該路線。金鑰由本機備份或已配對的「我的裝置」交換，不顯示成帳號操作。
- **本機收線**：從 `/r/<牆 id>/<路線 id>/` 讀取路線圖層、對應牆面與照片；若本機已有照片只合併路線。相同路線 id 依修改時間更新，不同 id 的相同岩點組合可以共存。收到的資料先屬於本機，公開前仍須使用者主動分享。
- **公開索引**：找牆面讀資料集的 `index/world.json`（Climbio 官方站；別的站照開放格式），公開路線讀 `walls/<包>/routes.json`；`/r/<牆 id>/<路線 id>/` 預覽頁與 `route.json` 由 `routePage` 從資料集切出（只讀、不查資料庫）；發佈的 Guidebook 與 3D 可從 `/p/<專案 id>` 取得固定分享網址。後端只管理公開索引與必要的路線寫入，不代替本機備份。
- **公開授權**：首次公開時確認使用者的暱稱、素材權利及 CC BY-SA 4.0。已公開的資料集內容無法當作私人資料收回；本機刪除與撤回自己的公開路線是不同操作。

## 可替換後端

`backend/firebase.js` 提供公開牆、路線、岩館索引及 Guidebook 清單；`site.js` 可將後端設為 `none`。無雲端服務的站點仍可本機定線、匯出圖片與檔案，或用可直連的裝置做朋友互傳。備份與復原見 [backup.md](backup.md)。
