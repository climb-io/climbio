# Crag Guidebook 公開版本

Crag Guidebook 的公開發佈不要求帳號。版本以不同專案 id 保存，透過來源關係讓紅點貓找到同一本書的適當版本。

- **發佈**：使用新的專案 id；`origin` 指向上一版，`root` 指向最初版本，已發佈的 id 不能被改寫。
- **人人可改、不被改爛（不認作者）**：沒有帳號、金鑰或維護者，誰都能匯入一本來改、再發佈成下一版；平台不判斷誰是真正的作者。避免改爛靠兩件事：
  - **小改接在後面**：同一本書大家預設看到最新的一版。每一版都留著，改壞了任何人從前一版「從這一版開始改」再發一次就退回去。
  - **大改變成新的一本**：一次刪很多（路線超過 3 條、岩壁超過 2 面、照片少了超過 3 張，或超過上一版的 10%，取大的；`studio/crag/versions.js` 的 `bigChange`）不接在原本那本後面，發成沒有 `origin` 的新一本（自己一個 `root`），名稱要跟原本不同；原本那本照舊。判斷在 Studio 發佈前（工具端），伺服器不在背景改資料。
  - 2026-11 曾試過維護者金鑰（正式版／修改建議），因為變成要由平台管理誰是作者而拿掉；資料庫裡舊版本的 `key`、`official` 欄位不再使用。
- **讀取**：紅點貓保存收下時的來源與版本；打開時自動更新到收下那一版後代裡最新的一版（大改是另一本，不是後代，不會換過去），使用者仍可在其他版本裡自己選。
- **世界清單**：同一個 `root` 的多個版本群組顯示，Guidebook 最新的一版排第一；3D 牆照下載數及發布時間排序；使用者仍可查看其他版本。
- **不列入世界**（岩友間分享、地點敏感的岩場）：發佈時勾「不列入世界」（組合的 `props.unlisted`，專案文件 `listed: false`）：世界清單、世界地圖、資料集目錄（`crags.jsonl`）都不列，`/p/<id>` 連結和編輯連結照樣打得開。檔案仍在開放資料集，算不張揚、不是保密。上一版不列入的，下一版預設也不列入（要明確選列入才改）。拿到連結的人靠雲端函式 `datasets` 的 `versions`（公開唯讀，同一個 `root` 所有的版本）找最新的一版：紅點貓自動更新、Studio 版本紀錄與編輯連結在公開清單找不到這本時改問它。
- **計數**：`index.json` 是更新檢查，不當成完整下載；以整包下載用的 `pack.json` 計算。
- **權限及容量**：公開的照片、Topo、岩壁與路線必須通過格式與素材權利驗證；依網路來源限制每天的準備容量與發佈次數。
- **公開後**：不提供由發佈者直接抹除已公開內容的功能；有不當內容時由管理者處理索引。

詳細流程見 [Studio Crag](../studio-crag.md) 與 [紅點貓](../redpoint.md)。
