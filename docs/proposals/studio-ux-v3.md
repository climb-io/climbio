# Climbio Studio UX V3 — Crag 工作區

> **已確認：單一 Climbio Studio 品牌、單一共用 Shell、Crag 工作區（岩點偵測另有 Hold Lab），Logo 直接沿用 Climbio 母品牌。** 完整共通操作規範見 [studio-design.md](../studio-design.md)。本文件是兩種工作區的領域流程規格，**不是兩個獨立 Studio 產品**；現行路由參考 [studio-crag.md](../studio-crag.md)，整合之前依現行實作。

## Goal / Users

Studio 的主要使用者不同於一般岩友：

- **Crag 工作區**：岩場開發者與 Guidebook 維護者；拍攝現場、地理定位、路線資料及長期更新。

共同目標是「**批次、自動化建議、人工可校正、可恢復、可驗證、可攜**」。

## Crag 工作區 — 從照片到地圖，建立完整岩場

### Core Journey

1. 建立 Guidebook 專案，匯入多張照片、CSV／試算表路線及合法的外部 v2 資料。
2. 解析 GPS／EXIF；區分**拍照點、推估岩壁、人工確認位置**。
3. 建議照片與岩壁的關聯；建立或調整區域、分區、岩壁階層。
4. 在地圖上調整岩壁線、區域、拍照點，保留幾何與來源。
5. 在照片上繪製或校正 Topo：路線、共用段、分岔、Bolt、確保站、編號。
6. 在路線資料工作區批次維護名稱、難度、類型、長度、來源及署名。
7. 發布前驗證格式、照片權限、公開 GPS／方向與授權；匯出或發布 Guidebook。
8. 後續修改建立新版本，不默默覆蓋使用者的既有快照。

### 共享選取

- **Map Workspace**：岩場／區域／岩壁、拍照點、預估範圍與地理編輯。
- **Photo / Topo Workspace**：照片、路線線段、標號、分支／共用段及 Bolt。
- **Route Data Workspace**：路線表格、欄位、歸屬、批次匯入及來源。

選擇地圖岩壁，對應照片與路線同步切換；選擇路線，Topo 定位及表格高亮。資料／狀態只保留一份，工作區透過明確 selection API 同步，避免獨立複本不同步。

### 地理定位要求

照片 GPS 通常是**相機位置而非岩壁**；鏡頭方位／焦距可能缺失或不準。推估結果必須顯示信心／誤差和校正入口，不能把推估值標成已驗證 GPS；未經明確同意，不能發布拍攝者精確位置與方向。

### Topo / Guidebook 要求

- 一條路線可出現在多張照片上，路線資料和顯示幾何分離。
- 保留共同線段／分岔的編輯模型，不能因簡化渲染而複製錯誤路線。
- 支援多層岩場結構，但**不強制每個岩場都有完全相同層級**。
- 匯入外部 Guidebook 只視為快照，未另開發同步協議前**不宣稱雙向同步**。
- 發布檢查來源、署名、授權、敏感座標、格式與可讀取性。

### Baseline / Gap

現有 [studio-crag.md](../studio-crag.md) 已描述照片歸岩壁、GPS 推估、MapKit／TopoKit、路線表格、匯出與版本發布；**三工作區一致選取、地理信心呈現與實際體驗**需在正式產品驗收時特別檢查。

## Non-Goals

- Crag Studio 不把自動 GPS、紅線辨識或第三方照片視為人工驗證或可任意公開。
- Climbio Studio 使用同一個 Shell 和母品牌 Logo；工作完成不以貓咪動畫或視覺裝飾為必要條件。
- 不能以官方 Firebase 作為本機專案功能的前置條件。

## Ownership / Tests / Exit

Studio 負責人維護工作流程；影像品質、地圖幾何、Kit 元件及發佈服務各自有 Reviewer。所有交互更改必須包含單元測試、桌面／iPad E2E、實際案例與 Review。

**退出條件**：Crag Studio 完成一份已授權實際岩場資料的建立、Topo 更新、匯出／發佈與再讀取，保留 ID、來源、署名及版本。不得把自動化測試替代真實相機／iPad 驗收。
