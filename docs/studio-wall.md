# Climbio Studio：Wall（室內牆面，電腦、平板、手機）

網址 `/studio/wall/#<專案 id>`（`#<專案 id>/<牆 id>` 直接打開那面牆；舊網址 `/studio/holdlab/` 轉址過來）。入口是 Studio 首頁的「室內牆面」卡和 `/lab/`；沒有專案 id 時是岩館的作品清單（沒有作品就連到首頁的「交給 AI」）；首頁交過來的照片（`#inbox=`）每張一面牆、分組變分區。3D 牆不在 Wall 裡，從 `/lab/` 進 `studio/wall3d/`。專案是牆面專案資料夾（`studio/wall/store.js`）；電腦版 Chrome 存在選的資料夾，其他（手機、iPad）存在瀏覽器的私有檔案系統。頂列沒有返回，只有 Studio 字標連回首頁；工作區各自獨立。

**固定連結** `/studio/wall/#p=<公開牆的包 id>`：不選資料夾，從開放資料集（`/p/<包 id>/`）把這面公開牆的照片和岩點收進瀏覽器的專案（`openPublic`），接著精修；發佈用 `packJob`，是同一個包的新版本（`version` 加一，不認人）。同一個包只收一次，專案 id 記在 localStorage（`climbio.wallpub.<包 id>`），再開直接回到那個專案。停用（`retired`）的岩點不進編輯器，只記進 `published`，之後發佈照樣留著。

## 五個步驟（步驟列，跟 Crag 同一種）

| 步驟 | 做什麼 |
|---|---|
| 牆面 | 岩館 → 分區 → 牆的卡片（縮圖、岩點數、要看幾顆）；上方是跟 Crag 路線清單同一種的工具列，「加牆面照片」（HoldScan 偵測加 HoldKit 外框，幾秒，過程用全螢幕過場）；還沒有牆時主畫面只有「加牆面照片」；點一面進岩點 |
| 岩點 | 編輯器（見下）：預設停在待確認的第一顆，一顆一顆看、修；「逐顆檢查完了」在面板底部；步驟旁小字是全部待確認幾顆 |
| 檢查 | 一整頁：還有待確認岩點、還沒按「逐顆檢查完了」、處理失敗的牆，點了打開那面（`StudioShell.checks`） |
| 報告 | 每一步的岩點外框跟最後的岩點比（見下「岩點報告」），上方切換牆；發佈步驟每面牆的「報告」也打開這裡 |
| 發佈 | 每面牆一列（`StudioShell.pubList`）：尚未發佈／已發佈第幾版／有更新；只有尚未發佈和有更新的才有「發佈」或「更新發佈」鈕（要勾選有權發佈；從公開牆收進來精修的牆不再問，收進來沒改過也不算有更新）；發佈完成後對話框只留網址，不再出現發佈鈕。發佈就是公開。每面牆都有「匯出 ZIP」（不公開）：`<牆 id>.json`（Climbio 公開格式 v2 的照片畫面，只含裁切範圍裡的岩點）和 `<牆 id>.jpg`（照片），就是[內嵌頁](embed.md)和別的 App 要的資料；匯出前先用 `validate` 驗證，不合格不匯出 |

## 岩點報告

發佈前（「報告」步驟）、已公開的牆（`/studio/wall/#r=<公開牆的包 id>`，不用專案，上方有到 `#p=` 接著精修的連結）、Lab 的 Hold Lab 頁（`/lab/hold-lab/`）是同一個畫面：`studio/wall/report.js` 算數字、`report-view.js` 畫、`report.css` 排（顏色取頁面的主題，Studio 深色、Lab 淺色）。步驟卡、定義與限制是三條線共用的報告框架（`studio/report-frame.js`、`report-frame.css`）：Lab 的 3D 牆頁用 `studio/wall3d/report.js` 把開放資料集 `climbio/wall3d-lab` 的 `pipeline/*-summary.json`（重建、偵測、投票、留出照片檢查）整理成步驟，天然岩場頁用 `studio/crag/lab-report.js` 整理包裡的 `lab.json`（每區模型、留出照片認牆、路線投影誤差）；數字一律從檔案讀，頁面不寫死。

- **階段**：發佈前從這面牆的研究記錄還原（`fromRecord`，跟發佈時寫進 `<牆 id>.edits.json` 的同一份）：自動偵測、（人選過 SAM2 的）SAM2、人工檢查。已公開的牆有開放資料集的各步比對資料（`research/hold-lab/<包 id>/stages.json`，version 2）就用它的各步外框（`fromStages`：自動偵測、重描外框、SAM2、AI 檢查），否則從那一版的 `edits.json` 和畫面還原。岩點貓的記錄（有 `final`）畫面是原始岩點，人工檢查換上 `final` 的外框。
- **數字**：最後一步是答案，前面每一步跟它一對一配對（沒有可靠 ID 時以重疊 IoU ≥ 0.3 估算）：蓋到答案不到 85% 是切掉一角、多出來超過 25% 是外框太大、沒配到是多認，答案沒被配到是漏掉；找到率為配對顆數除以最後階段岩點總數。卡片只顯示找到／總數（百分比）、誤判與外框可用三項；相對上一步有變化才顯示顆數差。兩階段都有完整唯一的岩點 ID 時照 ID 配對，重描不改岩點身分；舊資料缺 ID 時依外框配對並標明估算。最後階段只顯示岩點總數、檢查狀態及修正摘要；只有偵測或無參考結果時不顯示百分比。最後階段尚未確認時，數字僅是與當前參考結果的一致程度。最後一步跟前一步比，有岩點 id 照 id 對，標出沒動或微調、重畫（重疊不到 0.9，跟研究記錄同一個值）、手畫新增、刪掉。各步比對資料裡原本算好的分類不用，一律在這裡重算。
- 照片上：左右拖曳對照前一步、「標出問題」用顏色標分類、「看改的地方」逐一放大這一步變好或人改過的岩點；Ctrl／⌘ 滾輪、雙指縮放。

## 從岩點貓帶進來的牆

以前從岩點貓帶進來的牆（`w.pack`）照舊能編輯、發佈成岩點貓分享包的新版本，但現在沒有帶新的進來的入口。

- 發佈是同一個包的新版本：檔案照岩點貓的分享包（`ShareTools.wallPackage`，同一個包 id、同樣的檔名）寫進開放資料集，岩點貓上的這面牆換成新版；整面都發（岩點貓沒有裁切）。
- **刪除、合併已公開的岩點＝停用**：別人在這面牆上的路線用岩點 id 指到它們（路線只帶跟牆上不同的外框）。進度檔的 `published` 記每顆已公開岩點公開時的外框 `{ id: poly }`；發佈時，已公開、現在不在岩點清單裡的（刪掉、合併掉的），照公開時的外框留在畫面裡，節點標 `props.retired: true`（`app.js` 的 `retiredOf`）；復原讓它回來就不再停用。發佈後這份外框更新成當時的樣子。
- 岩點貓收這面牆（新收的）：停用的岩點只放進原始岩點檔（補別人舊路線的外框、`retired` 標記留著），我的岩點檔沒有它，所以新路線點不到；舊路線自帶它的外框，照樣看得到、可以從路線拿掉（`js/sync.js` 的 `saveSnap`）。已經收過這面牆的人：岩點貓讀公開牆時（雲端函式 `walls` 的 `routes` 回 `src`、`ver`＝牆的畫面在哪、現在第幾版），版本跟上次不同就重讀牆的岩點（`js/sync.js` 的 `refreshHolds`、`applyPublicHolds`）：牆主人新增的加進來、停用的從我的岩點檔拿掉、沒人改過的換成新外框；我自己刪掉的不放回來，我改過、自己畫的照舊；照片尺寸變了就不動。自己公開的牆（`w.pack`）不更新。

## 編輯器（手機、電腦同一套）

照片全幅（深色），工具浮在照片上：左上上一面、下一面牆和牆名，右上復原、重做，下方一排工具（裁切、多選、待確認）；選到岩點後，動作列浮在它旁邊（手機固定在工具列上方）。右側（手機是底部一條，往上展開）只放「待確認」清單：縮圖加原因、進度條、「逐顆檢查完了」。沒有手勢、快捷鍵的說明列。

- **手動修正跟岩點貓的單點編輯同一套**（[app.md](app.md)「長按」「圈起來」，程式各自一份：`editor.js`、`geometry.js` 的 `trimPolySpikes`、`lassoOutline`）。**外框只在人動手時才變**。
  - **長按**（滑鼠左鍵或手指原地按住 0.5 秒；拖曳、Shift、Alt 不算）：按在岩點上（或外框外一點點）是選它，螢幕上比指尖（44 px）小就移到中間、放大到約畫面寬的 1/3；按在空白處打開「圈」補一顆。
  - **圈**（選到一顆時動作列的「圈」、L；長按空白處也直接打開）：拖一圈（不平移、不拖頂點），放開時畫的圈就是外框（剪掉繞過起點多畫的一段、前後各 2 點平均掉手抖、省掉偏差不到螢幕 1 px 的點）；有選到的換掉它的外框，沒有就補一顆。放開後自動重描貼齊（併進畫圈那一步，復原一次回到畫圈之前），不合用就留著畫的圈、不提示。圈太小（螢幕上不到約 400 平方像素）提示「圈太小了」、自己交叉提示「圈得不完整」，都還在圈、可以再畫；「取消」或 Esc 離開（畫到一半的 Esc 先丟掉這一圈）。
  - **重描**（R）：用目前外框當提示重算，合格就直接換上（算一步，復原拿得回來），不合格留著原本的並提示「重描的結果不合用，留著原本的」。合格＝有效、包住原本的中心、不壓到旁邊的岩點（一半以上蓋在這顆上面的不算）、面積是原本的 1/5～5 倍。這台存過 SAM2 模型（電腦版，不會為此下載 300 MB）用 SAM2 以外框當提示描（`RefineSam.fit`），沒有或描不出來用 HoldKit 從外接框算（本機、幾十毫秒）。重描途中這顆被改、刪、復原，晚回來的結果不用。
  - **頂點把手**：白色頂點、黃色邊中點；螢幕上離不到 14 px 的連續頂點併成一個把手（拖它時合成一點），放大就分得開；把手不到 3 個（岩點在螢幕上太小）不放，放大再調；把手之間短於 28 px 不放邊中點。頂點容錯 20 px、邊中點 14 px，都在範圍內選近的（觸控再放大）。拖邊中點新增頂點；點兩下頂點（或選到頂點按「刪頂點」）刪掉（併在一起的整組刪，至少留 3 點）。拖完自動剪掉外框上的細尖（剛拖的頂點不動）。拖頂點時有放大鏡：在上方（太靠上才換到下方，換邊要多過 40 px），比畫面再放大 2.5 倍（最多照片 1 px＝3 個螢幕點、至少 1.5 倍），黃色外框、白色十字是頂點會落的位置。
  - 其他：合併、平滑、刪除、復原與重做。沒有框選新增和方框候選。
- **待確認**：有旗標的、可能重複的、SAM2 跟原外框不同還沒決定的。選到一顆跟 SAM2 不同的，兩個外框並排（綠色是原外框、青色虛線是 SAM2），動作列是「採用 SAM2」「保留原外框」；自己修了也算決定。J／K 跳到上一顆、下一顆待確認，A 沒問題，R 重描、L 圈、M 合併、X 刪除、C 裁切、B 只看待確認、Z 復原、`[`、`]` 換牆。
- 手機沒有選資料夾，專案存在瀏覽器的私有檔案系統，所以從 `/lab/` 或 Studio 首頁「最近的專案」進來；沒有 SAM2（模型太大）。手機（`appkit/landing.js` 判斷，`html` 加 `ak-handset`；本機加 `?phone` 看）的版面只換掉放不下的：底部一條「上一顆、待確認幾顆、下一顆、清單」，清單往上展開（最高 52% 螢幕），按了任何動作或點了清單就收起來。
- 手機的 iPhone Safari 要實機測；Playwright 的 WebKit 存不了專案（OPFS 寫入讀回是空的），自動測試只跑 Chromium（內部 e2e 案例）。

## 代理做牆面：岩點檔的必走流程（一次做完，AI 檢查不能跳過）

AI 代理替岩館（原岩、內嵌示範、對外給岩點檔）產生或精修牆面的岩點檔，**多面牆一次做完，中途不停下來問人**；岩點辨識人眼看得出來的，AI 也要看得出來，**不把辨識的判斷丟給人**；人只負責 AI 不能代替的決定（要不要公開發佈），做完整理成一份清單**一次**交給人，人在手機的 AI App（Claude、ChatGPT…）看、回一段字就好，不用在本機環境。

**入口只有一個，所有代理（Claude、Codex、別的引擎）照同一套做：`node tools/wall-batch.mjs next <工作資料夾>`。** 它印出現在做到哪、下一步要跑的指令、要看的圖在哪、判斷檔怎麼寫；分級的規則寫在程式的 `POLICY`，不用自己讀文件、自己決定哪些要看。需要 playwright 加 Chromium；SAM2 第一次下載約 300 MB。Windows 和 Mac 都要能跑：Windows 上 Playwright 內建的 Chromium 拿不到 WebGPU（缺 `dxcompiler.dll`），SAM2 用 WASM；`run` 的本機伺服器送跨來源隔離標頭（COOP `same-origin`、COEP `credentialless`），WASM 才能多執行緒，不然單執行緒一面 500 多顆的牆要 35 分鐘以上。不改用電腦裡的 Edge／Chrome：實測 Intel 內顯用 WebGPU 載入 SAM2 會一直卡住。失敗時 `run.json` 的 `errors` 留完整的錯誤堆疊、頁面錯誤與跑了幾分鐘。

| 步驟 | 指令 | 誰做 |
|---|---|---|
| 1 偵測、2 SAM2 精修、3 匯出牆的分享包 | `run <工作資料夾> <照片…>` | 程式，全部牆連續跑；單面失敗自動重試（預設 3 次，SAM2 偶發的檔案系統錯誤重來就過），還不行就記 `failed` 繼續下一面；做過的牆跳過 |
| 4 分級檢查（**必做**） | `check <工作資料夾>`：先自動處理（見下「分級」），再出要看的對照圖 | 程式 |
| 5 看圖判斷（看不準和要刪的放大再看一次：`recheck`） | `next` 會列出每面牆要看的圖（`sheets/`、`sam-sheets/`、`audit-sheets/`、`overview/`）和判斷準則；代理逐張看圖，把全部牆的判斷寫成一個 JSON，`apply <工作資料夾> <判斷.json>` | 代理（圖多時分給子代理，子代理也拿同一份準則，最後合併成一個 JSON）。**看不準（`unsure`）不是交給人的出口，`delete` 也不會馬上刪**：兩種都進 `recheck` 放大、多帶周圍重新出大圖，這一輪**不能再答 unsure，一定要定案**，刪除要寫 `delete:<理由>`（`"<牆>#recheck"`）；說不出理由就保留 |
| 5a Volume 與漏掉的岩點 | 總覽每格回報沒有完整外框的 Volume（`volumes`）和完全漏掉的岩點（`missing`）；`shapes` 出 Volume 放大圖（有照片像素格線），代理照格線畫頂點（`"<牆>#shapes"`）；漏掉的岩點先加橢圓外框；`shapecheck` 把新加的外框疊上去再看一次，代理答對、改外框、拿掉裡面的碎片（`"<牆>#shapecheck"`）；Volume 都有外框後 `onvolume` 每個大外框（面積到中位數 3 倍以上：Volume、大岩點）一張放大圖，代理逐一找上面沒有自己外框的岩點（`"<牆>#onvolume"`），加上的再 `shapecheck` 一輪 | 代理 |
| 5c 細看（最後一步） | `closeup <工作資料夾>`：照片切成約 560 px 的格子（南港 5×4 格），左照片、右邊外框塗色並標編號（綠＝岩點、黃＝Volume 或大岩點）；每格回答 `"ok"` 或 `{ missing, bad, extra }`（`"<牆>#closeup"`）：missing 加橢圓外框、bad 進 `shapecheck` 照格線重畫、extra 帶理由進 `recheck` 放大確認才刪 | 代理 |
| 5b 完成閘門 | `verify <工作資料夾>`：每一步都判斷過、放大再看的都定案、總覽每格都答、新加的外框都再看過、沒有新冒出來的重複岩點；通過才寫 `<牆>/result.json`（交付的數字只從這裡抄），沒過列原因、以 1 結束 | 程式 |
| 6 整理給人 | `review <工作資料夾>` → `review/index.html`（單檔、圖都內嵌、手機寬度）；沒過閘門的牆不會交給人 | 程式 |
| 7 交給人 | 把 `review/index.html` 發成 Artifact（手機的 App 直接打開），一次貼給使用者；使用者每件點一個選項、複製回覆貼回對話 | 代理 |
| 8 記人的判斷 | 使用者回覆後逐項 `resolve <工作資料夾> <牆>:<題 id 或 sam:<岩點 id> 或 publish> <選項> --by human:<名稱> --said "<原話>"`，再 `review` 確認；更新示範資料 | 代理 |

### 分級（POLICY）：能自動的自動、AI 看圖的只看該看的，看不準的放大再看、定案

| 項目 | 怎麼處理 | 依據 |
|---|---|---|
| SAM2 重描後**沒有**「候選對不上」「分數低」「漏到鄰點」「大點視窗不一致」旗標，也沒有跟色彩貼邊不一致 | 程式直接採用 SAM2 外框，**不看圖** | 三面牆的人工檢查，98 到 99% 沒有重畫 SAM2 的外框（南港 99、市民抱石 98、萬華 96）；SAM2 的外框比 HoldKit 的粗外框準，所以「兩個外框 IoU 不到 0.9」不是要看的理由（明德 638 顆裡 592 顆如此、南港 520 顆裡 480 顆如此） |

| 代理畫的 Volume 和 Volume 上的岩點被當成可能重複 | 程式直接答不是重複 | 判斷準則第 5 條 |
| 偵測信心低、邊緣不確定（沒有上面兩種旗標） | 採用 SAM2，**不另外看** | 試過用「小又新偵測」「面積很大」這類規則抓要刪、要改的，召回率只有兩成多，加了也不會少看多少 |

不會處理的：偵測信心低但沒被前面抓到的貼紙或陰影（總覽看得出來的會回報在 issues）。交付時照實寫。

### 判斷準則（所有代理同一份）

準則寫在 `tools/wall-batch.mjs` 的 `RUBRIC`（第 1～3 條：岩點、Volume、刪除理由，跟 3D 牆的 `look3d`／`review3d` 共用 `tools/hold-rubric.mjs`），`next` 每次都印出來，子代理也要拿到同一份；不同代理（Claude、Codex、別的引擎）照同一份準則、同一批圖、同一個判斷檔格式，結果才會接近。重點：

1. **岩點**＝鎖在牆上、能抓能踩的立體物件（厚度、側面、陰影、固定螺絲）；小色塊看得出立體就是岩點。
2. **Volume**＝大型的木板或玻璃纖維多面體：Volume 本身一個外框（沿 Volume 跟牆面的交界畫整顆），上面的岩點各自一個外框，不併進 Volume、不算重複。
3. **刪除要有正面證據並寫理由**（貼紙、膠帶、商標、陰影、螺絲孔、反光、牆板、碎片、重複）；說不出理由或看不準就保留。理由寫進 `deleted.json`，`result.json` 按理由統計。
4. 外框三選一（原外框、SAM2、色彩貼邊）選沿著岩點跟牆面交界走的；色彩貼邊在深色陰影、跟牆同色處會漏、強反光處會破洞；差不多就用 SAM2。
5. 重複：同一顆留完整的、兩半合併；Volume 和上面的岩點、相鄰的岩點不是重複。
6. 總覽每格逐一找 Volume 和漏掉的岩點；7. 畫 Volume 照格線給頂點；8. 每個大外框逐一找上面沒有自己外框的岩點；9. 最後逐格細看：沒塗綠的岩點報 missing、明顯畫不好的外框報 bad、不是岩點的報 extra（帶理由）。
準則的修改依據：讓沒看過人工答案的代理照準則跑，回報「哪一題讓你猶豫」，有歧義就改準則（例如 Volume 碎片跟岩點算不算重複、大岩點被切碎怎麼畫、抽查看哪個時間點）。改了準則，`rubric.sha256` 跟著變，研究記錄分得出是哪一版。

### 完成的標準（所有代理同一個）

只有 `node tools/wall-batch.mjs verify <工作資料夾>` 通過才算做完；`next` 在閘門沒過前不會叫你整理給人。交付回報的數字（岩點、Volume、AI 補畫、刪除按理由、SAM2／重複／放大再看的判斷分布、抽查、總覽發現）只從 `<牆>/result.json` 抄，不自己數。

### 規定
- **不中途問人**：偵測、精修、分級檢查、修岩點、整理清單都是代理自己做完；失敗重試、記錄、繼續，不因為某面牆出錯、某題難判斷就停下來問。看不準的先答 `unsure`，由 `recheck` 放大再看並定案（定案那一輪不能再答 `unsure`），不留給人。
- **AI 檢查不能省**：`next` 列的圖都要看、判斷都要 `apply`；`verify` 沒過的牆 `review` 不會交給人；少了 AI 檢查的岩點檔不算完成，不能放進示範頁或發佈。
- **牆面資料預設是私有的**：岩館、客戶的牆面照片、岩點、路線不上公開資料集、不進公開 repo；`run` 預設不出發佈題，使用者明說這面牆要公開才加 `--public`。客戶專屬示範（仿客戶畫面的內嵌頁）只留在內部、單檔私下交付，不放公開主機。
- **人只看一種：「要不要公開發佈」**（只有公開的牆才有；只能由人答，發佈就是公開、收不回，工具不會發佈）。岩點辨識的判斷全部由 AI 做完，包括看不準的（放大再看、定案）。`review` 在 AI 檢查（重複岩點、SAM2、抽查、總覽、再看一次）都做完之前，不會把那面牆交給人。
- **不替人決定、不替人按**：人的判斷一定帶 `--by human:<名稱>` 和 `--said "<原話>"`，沒有就不收；代理不替人按「逐顆檢查完了」。
- **AI 通過閘門就算檢查完，人的檢查可做可不做**：`verify` 通過時寫出研究記錄 `<牆>/pack/<牆 id>.edits.json`，`reviewed: true`、`reviews` 記一筆 AI（`kind: ai-verify`）；人（或人交代他的代理）可以選擇再看過再發佈，看過就 `reviewed <工作資料夾> <牆> --by human:<名稱> --said "<原話>"` 多記一筆，也可以直接發佈。「要不要公開」仍然只能由人核准。
- **發佈一定帶完整的研究記錄**：`edits.json` 除了 Studio 同一套欄位（`base` 是 `run` 存的 `auto.json`：偵測加重描的外框與旗標），還有 `ai`：代理、判斷準則全文與雜湊、`POLICY`、每顆 SAM2 的外框、`ai-log.jsonl` 的每一步（題目、判斷、刪除理由、新加的外框）、`result.json`。`studio.mjs publish` 遇到代理流程的牆沒有這份記錄就拒絕。欄位說明在[資料集說明](walls-dataset-card.md)。私有牆不發佈，記錄只留在工作資料夾。
- 代理名稱從環境變數 `CLIMBIO_AGENT` 讀（如 `agent:codex`），沒設是 `agent:claude`。
- 交付時寫明每面牆（照 `verify` 印的、`result.json` 的數字）：岩點數、Volume 數、AI 補畫幾個、刪除按理由、程式自己處理幾個、AI 看圖幾個（各判斷了什麼）、抽查錯幾個、失敗的牆和原因，以及上面「不會處理的」。

## 已公開的牆再精修、再發佈（可重複多次，一定走這條）

同一面公開牆之後還會再精修（換更好的外框、補岩點、停用誤認的）。每次發佈有幾份資料要**一起更新**，以前各自手動做、很容易漏（沿用舊記錄、現行版沒換、路線掛錯牆、比對頁還是舊的），所以用 `tools/wall-republish.mjs` 一條龍，做完用 `check` 驗證：

| 步驟 | 指令 | 為什麼 |
|---|---|---|
| 1 切版本、算記錄 | `node tools/wall-republish.mjs plan <牆包 id> <新外框.json> <輸出資料夾> [--first 路線用到的岩點] [--retire …] [--unretire …] [--reviewed --by human:<名稱> --said "<原話>"]` | 發佈端每版最多改動 30% 的岩點（新增、改形狀、停用都算），整面重修要分成多版；`--first` 讓路線用到的岩點最早就完整。每一版都帶**這一版真正算出來的**研究記錄（相對精修前的有效岩點）；**不要沿用舊的 edits.json**（改的顆數、來源標籤都會錯） |
| 2 發佈每一版 | `node tools/wall-republish.mjs publish <輸出資料夾> --by human:<名稱> --said "<原話>"` | 公開收不回，核准一定是人在對話裡說的；重複岩點之類的題目 AI 先看圖答完，工具不替答；任何一版失敗就停 |
| 3 更新比對資料 | `node tools/wall-republish.mjs stages <牆包 id>` | Hold Lab 上方報告讀 `research/hold-lab/<牆包 id>/stages.json`，不會隨發佈重算；這步把「AI 檢查」階段換成現行版的有效岩點（要 HF 權杖 `CLIMBIO_HF_TOKEN` 或 `CLIMBIO_HF_TOKEN_FILE`；沒有比對資料的牆不用做） |
| 4 驗證 | `node tools/wall-republish.mjs check <牆包 id> [<照片編號>]` | 有任何一項不一致以 1 結束並列出：現行版 ≠ 最新版、記錄沒 reviewed 或沿用舊的、目錄統計對不上、路線用到停用的岩點、路線登記在錯的 id、比對資料顆數對不上 |

規則：
- **現行版（岩點貓、內嵌頁看到的那一版）只在新版本帶 `reviewed: true` 的記錄時才換**。多版系列只有最後一版 reviewed；`reviewed` 是「逐顆檢查完了」的宣告，只能由人同意（`--by human:` 加 `--said`），代理不替人按，也不要為了讓它生效而偷偷標。沒標就是「已發佈但 App 還看舊版」，要照實回報。
- **路線登記在照片編號，不是包 id**：牆 id 是畫面檔 `<照片編號>.json` 的 id（例如 `qob3734416nc`），包 id（例如 `6b2e872160caf900`）是資料集的資料夾。`wall-routes.mjs put` 用錯會另開一面沒有岩點的空牆，還會讓 `routes.json` 被別的路線蓋掉；`put` 現在會擋（畫面 id 不符、路線用到不存在或已停用的岩點），寫錯的登記用 `wall-routes.mjs unpublish <錯的 id>` 取消。`grade` 要傳字串（`"V7"`）。
- **不要停用別人路線用到的岩點**：公開牆上可能有別人的路線；停用、合併重複岩點前先看牆上所有路線（`check` 會列出缺的點）。真的要換，先決定留哪一顆，路線用到的那顆保留。
- **停用不是刪除**：發佈端不許少掉前一版的岩點，刪除、合併要標成 `retired`（外框留著）；停用也算一個變動（占 30% 額度）。
- 目錄（`walls.jsonl`）的路線條數、`index/world.json` 由每天 05:00 的排程更新，不是即時；`current.json` 已沒有程式使用，不用管。
- `shared.json` 已不是 App 讀的檔（線上 404 是正常的）；App 讀資料集 `walls/<包>/current/` 的畫面和 `walls/<包>/routes.json`。

## 為什麼分開

HoldScan 偵測加 HoldKit 外框（跟岩點貓同一套，本機、不下載模型；偵測用 2560 的模型輸入，電腦上約 5 秒），夠定路線用，外框比較粗。要精準的外框用 SAM2（約 300 MB 的模型、每張數分鐘），只在電腦版，岩館管理者平常不用開。

## SAM2 精修（電腦版）

牆面卡片的「精準重描」整面跑一次（手機沒有）：開始前先寫幾顆、約幾分鐘（要編碼的視窗數乘上每個視窗的時間，WebGPU 約 2.3 秒、WASM 約 5.5 秒）、第一次要下載約 300 MB，確認才開始。裁切範圍裡每個偵測框重描；有 WebGPU 用 WebGPU，建不起來或第一次跑失敗就改用 WASM；WebGPU 載入或第一次編碼超過 90 秒（Windows 的 Intel 內顯會一直卡住、不報錯）就記住這台不用 WebGPU（`localStorage` 的 `climbio.sam.noGpu`），提示關掉瀏覽器重開再試，之後直接用 WASM（卡住的運算佔著瀏覽器，同一頁、重新整理都建不了 WASM 的模型）；跑完要打開牆時讀檔失敗只提示，不算重描失敗；編碼器從 Hugging Face 下載，第一次後存瀏覽器私有檔案系統。

- **怎麼描**：每個偵測框在 1024／2048／3072 的視窗（照 256 格線）用「框＋框中心」與「只有框」各解碼一次；一般岩點加相鄰岩點的中心當負提示點（最多 8 個，遮罩包到鄰點中心標「漏到鄰點」）。**大岩點**（框面積到中位數 4 倍以上）另外用「以框為中心、岩點佔視窗約 6 成」的視窗放大描一次，兩個視窗的外框重疊到 0.9 用放大的，不然用一般的並標「大點視窗不一致」。遮罩精簡成多邊形的容差跟外框長邊成比例（長邊的 0.4%，1 px 起），大岩點不會被壓成 10 幾個點。
- **色彩貼邊**（另一個候選，`geometry.js` 的 `colorFit`）：原外框往內縮一圈的 Lab 顏色當種子，在原外框附近的帶狀區（長邊的 25%）長出顏色相近的像素，閉合、補洞、留最大的一塊；門檻取岩點內部與外框外一圈色差的中間。分不開標「色彩對比低」（沒有外框）、長到帶狀區邊緣或面積大很多標「色彩漏出」。大岩點先縮到長邊 200 px 再算。只給代理流程三選一用，編輯器不顯示。
- **結果掛在岩點的 `sam`**（`{ poly, flags, iou, pick, color, colorFlags, big }`），原外框不動：跟原外框重疊（IoU）到 0.9 以上又沒旗標的，直接採用 SAM2（`pick: 'auto'`）；其餘 `pick` 空白，進待確認，人選了才改成 `sam`（採用 SAM2）、`keep`（保留原外框）、`edited`（自己修）。岩點 id 不變，路線不受影響；手畫、改過形狀的岩點不動，已經決定過的重跑也不動。
- 跑完有待確認的，直接進那面牆的待確認。
- 旗標（SAM2 結果要看的岩點）：兩次解碼的遮罩重疊低於 0.97（小岩點低於 0.98）、偵測信心低於 0.6；只存在 `.studio`，不進公開檔案。

### 外框重描的量測（南港，2026-11-25）

原岩南港 Spraywall（公開牆包 `0fe38b21d07b3771`，人工精修的 v5 共 564 顆當答案）。照片從頭跑的 HoldKit 外框（545 顆）當提示，每顆配到重疊最大（≥ 0.3）的人工外框，共 515 顆；數字是跟人工外框的平均重疊（IoU）與重疊 ≥ 0.9 的比例。

| | 全部 515 | 大岩點 95 | 一般 420 |
|---|---|---|---|
| 原外框（HoldKit） | 0.786／24% | 0.795／27% | 0.785／24% |
| 舊 SAM2（改之前，同樣的提示框） | 0.884／65% | 0.934／89% | 0.873／59% |
| 新 SAM2 | 0.882／64% | 0.935／88% | 0.871／59% |

| 三個裡最好的（AI 都選對的上限） | 0.895／71% | 0.936／89% | 0.885／67% |

- 要 AI 三選一的 64 顆（12%）；AI 都選對的話全牆 0.886（只用新 SAM2 0.882、舊 0.884）：跟人工答案比，SAM2 本身持平，多出來的只有三選一的 0.002～0.004。大岩點兩個視窗對不上的 9 顆（退回一般視窗的結果）、分數低 7 顆、漏到鄰點 0 顆。
- 一個一個開關量：大岩點的放大視窗、比例容差、負提示點，跟人工答案比都沒有變好（大岩點 0.934 → 0.926～0.930），放大視窗加「兩個視窗對不上就退回」才持平（0.935）。**人工答案大多沿用舊 SAM2 的外框（頂點中位數 10～11，跟舊 SAM2 一樣）**，所以跟它比的重疊看不出比人工更貼邊；看圖：放大視窗描的大岩點沿著弧邊走（人工和舊 SAM2 是直線切過去），失敗的是只切出岩點上的一塊，就是「大點視窗不一致」擋掉的那種。
- **跟人工精修版看圖比**：新 SAM2 跟人工外框不一致（IoU 不到 0.9）的有 184 顆，隨機抽 30 顆並排看：新 SAM2 比較貼 12 顆（弧邊、凹邊沿著走，人工是直線切過去）、人工比較貼 11 顆、差不多 7 顆。人工贏的 11 顆裡 5 顆是 SAM2 整個描錯（描到陰影、旁邊的岩點、只描到一半），另外 6 顆是切掉一角；這 11 顆只有 1 顆會進 AI 三選一，其餘的色彩貼邊也有旗標（漏出、對比低）、SAM2 跟原外框的重疊也分不出來（0.47～0.88），目前的規則抓不到。所以整體還沒比人工精修好：貼邊的贏面在，但要先抓到整個描錯的那幾顆。
- 負提示點只加在一般岩點：加在大岩點上平均從 0.930 掉到 0.927（鄰點常在大岩點邊上）；一般岩點加不加一樣（0.870）。
- 色彩貼邊整體不準（0.66）：172 顆「色彩漏出」（多色牆面、相鄰同色岩點）、52 顆「對比低」；贏 SAM2 超過 0.03 的只有 32 顆，所以只當第三個候選、不自動採用。
- **漏掉的岩點多半是偵測就沒抓到**：南港明顯漏掉的 14 顆，13 顆在偵測（整張縮成 1280 給模型）就沒有框，1 顆是 AI 畫 Volume 時當成碎片拿掉。改成 2560 的模型輸入：找到 90.1% → 94.5%、多認 34 → 25，那 13 顆抓回 9 顆；另一面公開牆（照片只有 1600 寬）找到 88.7% → 89.5%、多認 62 → 47。切塊用原解析度偵測（每塊 1536）結果跟 2560 差不多（94.1%、多認 24），較慢，沒用。
- 試過用顏色自動找漏掉的岩點（沒被外框蓋到、顏色鮮豔或很暗的色塊；Volume 和大岩點裡找跟它本身顏色差很多的色塊）：南港明顯漏掉的 14 顆抓到 9 顆，但候選有 281 個（真的漏掉的約 7%），誤報多半是大岩點上的反光、外框和實際邊緣之間的細縫、天花板污漬；只靠顏色分不開，沒放進流程。
- 代理照格線畫的 Volume（南港 13 個）跟人工平均 0.784（SAM2 描的 Volume 0.903）；看圖兩邊差不多，差在範圍取法（人工有的只框 Volume 上的大岩點）跟各自的邊不準。試過把直線邊貼齊最強的邊（±4% 長邊、±6°）：0.798 → 0.804，9 個變好 4 個變差，差距小，沒放進流程。
- 試過的邊緣吸附（頂點沿法線 ±6 px 找最大色彩梯度）讓外框變差（SAM2 0.879 → 0.856，色彩貼邊不變），沒有放進流程。
- 時間：大岩點各多編碼一個視窗（南港 54 個一般視窗加 95 個），Windows 上 WASM 整面從約 14 分鐘變約 40 分鐘；Mac 的 WebGPU 約 6 分鐘。

## 研究記錄（開放資料）

精修的結果是公開資料，目的是讓偵測越來越準。只存「自動結果跟最後結果的差異」，不存編輯過程（拖曳、復原、平滑、旗標、花多久都不記）。

- **進度檔的 `base`**（`.studio/progress/<牆 id>.json`）：自動偵測加重描的結果 `{ 岩點 id: { poly, flags } }`，由 `app.js` 的 `noteBase` 在 HoldKit 偵測時寫（SAM2 重描時只補沒有的），是原外框；SAM2 的結果在岩點的 `sam`，不覆蓋它。匯入的牆沒有 `base`。
- **牆的 `reviewed`**（`project.json`）：人按「逐顆檢查完了」的時間。沒有它，沒被改的岩點只能算「沒看過」，不能當正確答案。AI 代理流程（`tools/wall-batch.mjs`）通過完成閘門也算檢查完，記錄裡的 `reviews` 分得出是誰（見上面「代理做牆面」）。
- **記錄**（`record.js` 的 `buildRecord`，公開時才算，沒有 `base` 回 null）：`{ holdlab, wall, sha256, license, reviewed, tools, flagged, deleted, reshaped, added, sam }`。
  - `deleted`：誤偵測，留自動的外框。`added`：漏偵測，外框在最後的 `holds`。`reshaped`：邊界不準（重疊 IoU 低於 0.9），留自動的外框和 IoU；小修不記。沒改的不寫，等於 `base` 跟 `holds` 一致。
  - `flagged`：自動結果標了要看的岩點，沒改的也留，用來校準信心。
  - `sam`：SAM2 跟原外框不同的岩點，人的選擇：`{ 岩點 id: { poly（SAM2 的外框）, iou, flags, pick: sam｜keep｜edited } }`；一致就直接採用的不記。
  - `tools`：holdkit 版本、偵測與 SAM 模型版本。
- **公開**（編輯器工具列的「公開」，`app.js` 的 `publishUi`）：經雲端函式 `datasets`（`publishWall`）（`functions/walls-dataset.js`，不登入、不記擁有者；請求要帶 `source: 'studio'`，岩點貓 App 和舊版沒帶標記會被拒絕：公開牆只由 Studio 發佈，岩點貓不上傳牆）寫進 Hugging Face 的公開資料集 `climbio/walls`，不經過 Drive。一面牆寫成 `walls/<包 id>/v<版本>/`：`<牆 id>.jpg`、`<牆 id>.thumb.jpg`、`<牆 id>.json`（Climbio Format v2 的照片畫面）、`<牆 id>.edits.json`（上面的研究記錄，沒有 `base` 就沒有）、`index.json`；同一個 commit 更新根目錄的 `walls.jsonl`（目錄，研究者先下載它；格式見 [資料集說明](walls-dataset-card.md)）；版本每次加一、舊版本留著；只算裁切範圍內的岩點。權杖在 Secret `HF_TOKEN`（只能寫這個倉庫），讀取免登入。索引在 Firestore `datasets/{包 id}`（名稱、現行版 `version`、最新版 `latest`、`reviewed`、時間、檔案、內容雜湊，Climbio 唯一保存的資料）；現行版改變時同一個 commit 也寫 `walls/{包 id}/current.json`（`{ version }`，內嵌頁直接讀資料集用；維護者的 `syncCurrent` 操作可以一次補寫所有牆），沒有擁有者，任何人都能發新版本，靠發佈端驗證（`functions/wall-check.js`）：每顆外框合理（至少 3 點、不超過 500 點、在照片內、面積不小於 12 像素平方也不超過照片的 4 成、不自己交叉）；新版本不能少掉前一版的岩點（刪除、合併的標成 `retired`，外框留著）；照片尺寸不變；相對前一版最多變動 30% 的岩點（新增、改形狀、停用合計，至少允許 3 顆），超過整份拒絕，要分成多次發佈。**現行版**（`/p/<id>/` 導向的版本）是最新一個「逐顆檢查完了」的版本，沒有就是最新的；新版本沒檢查過、現行版檢查過時現行版不換。每個網路來源每天最多 30 次，超過預算時暫停（同 `projects`）。不記修改時間或節奏。
- **不能收回**：公開後 Climbio 不因作者要求刪除；只有侵權、含可識別個人、法令要求才移除（要重寫倉庫歷史）。沒有私人選項，私人的牆用附近交換（WebRTC，[sharing.md](sharing.md)）傳給對方。公開前對話框列出內容並要求勾選「我有權公開」。沒有公開的牆不進任何資料集。

## 程式

- `sam.js`（SAM2.1 base+，解碼器 `models/decoder_single.onnx`、`decoder_multi.onnx`，自己匯出的，只給整面重描用）、`editor.js`、`app.js`、`index.html`。
- 外框的幾何（遮罩、輪廓、平滑、合併、找重複、修自交）用 `studio/wall/geometry.js`。

## 公開牆一定有岩館名稱，沒有擁有者

Studio 發佈的公開牆一定帶岩館名稱（新牆用分區所屬的岩館，沒有就用專案名稱；`node tools/studio.mjs publish` 沒有 `props.gym` 會拒絕）；雲端函式 `publishWall` 沒有岩館名稱回 400。岩點貓上的公開牆不能改名、不能增加照片，只能刪除。

**沒有擁有者、不用金鑰**：牆不記是誰發佈的（沿用 [open-versions.md](proposals/open-versions.md)）。只有 Studio 能發佈牆（`source: 'studio'`），任何人都能發佈新版本，在 Mac、Windows、換電腦、換 AI 代理都一樣，不用搬金鑰檔。每次發佈是新的一版（`walls/<包 id>/v<版本>/`，舊版本留著），岩館要固定在某一版，內嵌的網址就用那一版的網址（見 [embed.md](embed.md)）。

**岩點貓看到哪一版，由程式自動判定（現行版）**：新版本一定先過內容驗證（`functions/wall-check.js`：外框合理、不少掉前一版的岩點——刪除、合併的要標 `retired` 留著、照片尺寸不變、一個版本變動不超過 30%），沒過整份拒絕。通過後只有同時符合下面三項才成為現行版，否則照樣存成新版本，岩點貓不換：
1. 照片還是同一張（指紋和現行版一樣）；
2. 是最新一個「逐顆檢查完了」（`edits.json` 的 `reviewed`）的版本；
3. 現行版已經檢查過時，新版本也要檢查過。

**手動下架**：只有維護者（`node tools/wall-routes.mjs unpublish <牆 id>`，需要維護者身分）；岩館想收回就聯絡維護者。下架拿掉找牆面入口和所有人的線，資料集已公開的檔案留著；90 天沒更新也會自動下架。要更新牆用同一個牆 id 再發佈就是新版本，不用下架舊牆。
