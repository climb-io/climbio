# Climbio Studio：Wall（室內牆面，電腦、平板、手機）

網址 `/studio/wall/#<專案 id>`（`#<專案 id>/<牆 id>` 直接打開那面牆；舊網址 `/studio/holdlab/` 轉址過來）。入口是 Studio 首頁的「室內牆面」卡和 `/lab/`；沒有專案 id 時是開場：選照片（可以多張），或「我的岩點貓牆面」（要接後端）。專案是牆面專案資料夾（`studio/wall/store.js`）；電腦版 Chrome 存在選的資料夾，其他（手機、iPad）存在瀏覽器的私有檔案系統。頂列沒有返回，只有 Studio 字標連回首頁；工作區各自獨立。

**固定連結** `/studio/wall/#p=<公開牆的包 id>`：不選資料夾，從開放資料集（`/p/<包 id>/`）把這面公開牆的照片和岩點收進瀏覽器的專案（`openPublic`），接著精修；發佈用 `packJob`，是同一個包的新版本（`version` 加一，不認人）。同一個包只收一次，專案 id 記在 localStorage（`climbio.wallpub.<包 id>`），再開直接回到那個專案。停用（`retired`）的岩點不進編輯器，只記進 `published`，之後發佈照樣留著。

## 三個步驟（步驟列，跟 Crag 同一種）

| 步驟 | 做什麼 |
|---|---|
| 牆面 | 岩館 → 分區 → 牆的卡片（縮圖、岩點數、要看幾顆）；上方「加牆面照片」（HoldScan 偵測加 HoldKit 外框，幾秒，過程用全螢幕過場）、「我的岩點貓牆面」；點一面進岩點 |
| 岩點 | 編輯器（見下）：預設停在待確認的第一顆，一顆一顆看、修；「逐顆檢查完了」在面板底部；步驟旁小字是全部待確認幾顆 |
| 發佈 | 每面牆一列：尚未發佈／已發佈第幾版／有更新；按「發佈」或「更新發佈」（要勾選有權發佈）。發佈就是公開 |

## 我的岩點貓牆面

「我的岩點貓牆面」列出這台發佈過的 3D 牆（瀏覽器的 IndexedDB `climbio-wall3d`；Studio 不登入、沒有帳號，所以「我的牆」就是這台發佈過的）。選了跳到 3D 牆工作區 `../wall3d/#<工作檔的牆 id>/<版本 id>`：這台選過資料夾就按「打開 <資料夾>」直接進，沒有就選工作檔資料夾，或按「下載已發佈的版本」在空資料夾重建工作檔（基底加那一版的 patch；只有帶 patch 的版本才有）；資料夾的牆 id 不對就拒絕。以前從岩點貓帶進來的牆（`w.pack`）照舊能編輯、發佈成岩點貓分享包的新版本，但現在沒有帶新的進來的入口。

- 發佈是同一個包的新版本：檔案照岩點貓的分享包（`ShareTools.wallPackage`，同一個包 id、同樣的檔名）寫進開放資料集，岩點貓上的這面牆換成新版；整面都發（岩點貓沒有裁切）。
- **刪除、合併已公開的岩點＝停用**：別人在這面牆上的路線用岩點 id 指到它們（路線只帶跟牆上不同的外框）。進度檔的 `published` 記每顆已公開岩點公開時的外框 `{ id: poly }`；發佈時，已公開、現在不在岩點清單裡的（刪掉、合併掉的），照公開時的外框留在畫面裡，節點標 `props.retired: true`（`app.js` 的 `retiredOf`）；復原讓它回來就不再停用。發佈後這份外框更新成當時的樣子。
- 岩點貓收這面牆（新收的）：停用的岩點只放進原始岩點檔（補別人舊路線的外框、`retired` 標記留著），我的岩點檔沒有它，所以新路線點不到；舊路線自帶它的外框，照樣看得到、可以從路線拿掉（`js/sync.js` 的 `saveSnap`）。已經收過這面牆的人：岩點貓讀公開牆時（雲端函式 `walls` 的 `routes` 回 `src`、`ver`＝牆的畫面在哪、現在第幾版），版本跟上次不同就重讀牆的岩點（`js/sync.js` 的 `refreshHolds`、`applyPublicHolds`）：牆主人新增的加進來、停用的從我的岩點檔拿掉、沒人改過的換成新外框；我自己刪掉的不放回來，我改過、自己畫的照舊；照片尺寸變了就不動。自己公開的牆（`w.pack`）不更新。

## 編輯器（手機、電腦同一套）

照片全幅（深色），工具浮在照片上：左上上一面、下一面牆和牆名，右上復原、重做，下方一排工具（新增、手畫、裁切、多選、待確認）；選到岩點後，動作列浮在它旁邊（手機固定在工具列上方）。右側（手機是底部一條，往上展開）只放「待確認」清單：縮圖加原因、進度條、「逐顆檢查完了」。沒有手勢、快捷鍵的說明列。

- **外框都用 HoldKit 算**（本機、幾十毫秒、不下載模型）：新增是在照片上拖一個框，外框成為候選，「採用」才加進去；選到一顆按「重描」，用它的範圍重算候選。
- **手動修正**：拖頂點、拖邊上任何一點新增頂點、點兩下頂點（或選到頂點按「刪頂點」）刪掉、手畫（拖一圈，或逐點點擊再「完成」）、合併、平滑、刪除、復原與重做。拖頂點時（滑鼠、觸控都一樣）上方有放大鏡，照原圖像素畫，十字線是頂點會落的位置；頂點與邊的點擊範圍在觸控時更大。
- **待確認**：有旗標的、可能重複的、SAM2 跟原外框不同還沒決定的。選到一顆跟 SAM2 不同的，兩個外框並排（綠色是原外框、青色虛線是 SAM2），動作列是「採用 SAM2」「保留原外框」；自己修了也算決定。J／K 跳到上一顆、下一顆待確認，A 沒問題，N 新增、P 手畫、R 重描、M 合併、X 刪除、C 裁切、B 只看待確認、Z 復原、`[`、`]` 換牆。
- 手機沒有選資料夾，專案存在瀏覽器的私有檔案系統，所以從 `/lab/` 或 Studio 首頁「最近的專案」進來；沒有 SAM2（模型太大）。手機（`appkit/landing.js` 判斷，`html` 加 `ak-handset`；本機加 `?phone` 看）的版面只換掉放不下的：底部一條「上一顆、待確認幾顆、下一顆、清單」，清單往上展開（最高 52% 螢幕），按了任何動作或點了清單就收起來。
- 手機的 iPhone Safari 要實機測；Playwright 的 WebKit 存不了專案（OPFS 寫入讀回是空的），自動測試只跑 Chromium（內部 e2e 案例）。

## 為什麼分開

HoldScan 偵測加 HoldKit 外框（跟岩點貓同一套，本機、幾秒、不下載模型），夠定路線用，外框比較粗。要精準的外框用 SAM2（約 300 MB 的模型、每張數分鐘），只在電腦版，岩館管理者平常不用開。

## SAM2 精修（電腦版）

牆面卡片的「精準重描」整面跑一次（手機沒有）：開始前先寫幾顆、約幾分鐘（要編碼的視窗數乘上每個視窗的時間，WebGPU 約 2.3 秒、WASM 約 5.5 秒）、第一次要下載約 300 MB，確認才開始。裁切範圍裡每個偵測框重描；有 WebGPU 用 WebGPU，建不起來或第一次跑失敗就改用 WASM；編碼器從 Hugging Face 下載，第一次後存瀏覽器私有檔案系統。

- **結果掛在岩點的 `sam`**（`{ poly, flags, iou, pick }`），原外框不動：跟原外框重疊（IoU）到 0.9 以上又沒旗標的，直接採用 SAM2（`pick: 'auto'`）；其餘 `pick` 空白，進待確認，人選了才改成 `sam`（採用 SAM2）、`keep`（保留原外框）、`edited`（自己修）。岩點 id 不變，路線不受影響；手畫、改過形狀的岩點不動，已經決定過的重跑也不動。
- 跑完有待確認的，直接進那面牆的待確認。
- 旗標（SAM2 結果要看的岩點）：兩次解碼的遮罩重疊低於 0.97（小岩點低於 0.98）、偵測信心低於 0.6；只存在 `.studio`，不進公開檔案。

## 研究記錄（開放資料）

精修的結果是公開資料，目的是讓偵測越來越準。只存「自動結果跟最後結果的差異」，不存編輯過程（拖曳、復原、平滑、旗標、花多久都不記）。

- **進度檔的 `base`**（`.studio/progress/<牆 id>.json`）：自動偵測加重描的結果 `{ 岩點 id: { poly, flags } }`，由 `app.js` 的 `noteBase` 在 HoldKit 偵測時寫（SAM2 重描時只補沒有的），是原外框；SAM2 的結果在岩點的 `sam`，不覆蓋它。匯入的牆沒有 `base`。
- **牆的 `reviewed`**（`project.json`）：人按「逐顆檢查完了」的時間。沒有它，沒被改的岩點只能算「沒看過」，不能當正確答案。
- **記錄**（`record.js` 的 `buildRecord`，公開時才算，沒有 `base` 回 null）：`{ holdlab, wall, sha256, license, reviewed, tools, flagged, deleted, reshaped, added, sam }`。
  - `deleted`：誤偵測，留自動的外框。`added`：漏偵測，外框在最後的 `holds`。`reshaped`：邊界不準（重疊 IoU 低於 0.9），留自動的外框和 IoU；小修不記。沒改的不寫，等於 `base` 跟 `holds` 一致。
  - `flagged`：自動結果標了要看的岩點，沒改的也留，用來校準信心。
  - `sam`：SAM2 跟原外框不同的岩點，人的選擇：`{ 岩點 id: { poly（SAM2 的外框）, iou, flags, pick: sam｜keep｜edited } }`；一致就直接採用的不記。
  - `tools`：holdkit 版本、偵測與 SAM 模型版本。
- **公開**（編輯器工具列的「公開」，`app.js` 的 `publishUi`）：經雲端函式 `datasets`（`publishWall`）（`functions/walls-dataset.js`，不登入、不記擁有者）寫進 Hugging Face 的公開資料集 `climbio/walls`，不經過 Drive。一面牆寫成 `walls/<包 id>/v<版本>/`：`<牆 id>.jpg`、`<牆 id>.thumb.jpg`、`<牆 id>.json`（Climbio Format v2 的照片畫面）、`<牆 id>.edits.json`（上面的研究記錄，沒有 `base` 就沒有）、`index.json`；同一個 commit 更新根目錄的 `walls.jsonl`（目錄，研究者先下載它；格式見 [資料集說明](walls-dataset-card.md)）；版本每次加一、舊版本留著；只算裁切範圍內的岩點。權杖在 Secret `HF_TOKEN`（只能寫這個倉庫），讀取免登入。索引在 Firestore `datasets/{包 id}`（名稱、現行版 `version`、最新版 `latest`、`reviewed`、時間、檔案、內容雜湊，Climbio 唯一保存的資料），沒有擁有者，任何人都能發新版本，靠發佈端驗證（`functions/wall-check.js`）：每顆外框合理（至少 3 點、不超過 500 點、在照片內、面積不小於 12 像素平方也不超過照片的 4 成、不自己交叉）；新版本不能少掉前一版的岩點（刪除、合併的標成 `retired`，外框留著）；照片尺寸不變；相對前一版最多變動 30% 的岩點（新增、改形狀、停用合計，至少允許 3 顆），超過整份拒絕，要分成多次發佈。**現行版**（`/p/<id>/` 導向的版本）是最新一個「逐顆檢查完了」的版本，沒有就是最新的；新版本沒檢查過、現行版檢查過時現行版不換。每個網路來源每天最多 30 次，超過預算時暫停（同 `projects`）。不記修改時間或節奏。
- **不能收回**：公開後 Climbio 不因作者要求刪除；只有侵權、含可識別個人、法令要求才移除（要重寫倉庫歷史）。沒有私人選項，私人的牆用附近交換（WebRTC，[sharing.md](sharing.md)）傳給對方。公開前對話框列出內容並要求勾選「我有權公開」。沒有公開的牆不進任何資料集。

## 程式

- `sam.js`（SAM2.1 base+，解碼器 `models/decoder_single.onnx`、`decoder_multi.onnx`，自己匯出的，只給整面重描用）、`editor.js`、`app.js`、`index.html`。
- 外框的幾何（遮罩、輪廓、平滑、合併、找重複、修自交）用 `studio/wall/geometry.js`。
- 隱私：照片只在你的電腦上處理。
