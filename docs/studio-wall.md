# Climbio Studio：Wall（室內牆面，電腦、平板、手機）

網址 `/studio/wall/#<專案 id>`（`#<專案 id>/<牆 id>` 直接打開那面牆；舊網址 `/studio/holdlab/` 轉址過來）。入口是 Studio 首頁的「室內牆面」卡和 `/lab/`；沒有專案 id 時是岩館的作品清單（沒有作品就連到首頁的「交給 AI」）；首頁交過來的照片（`#inbox=`）每張一面牆、分組變分區。3D 牆不在 Wall 裡，從 `/lab/` 進 `studio/wall3d/`。專案是牆面專案資料夾（`studio/wall/store.js`）；電腦版 Chrome 存在選的資料夾，其他（手機、iPad）存在瀏覽器的私有檔案系統。頂列沒有返回，只有 Studio 字標連回首頁；工作區各自獨立。

**固定連結** `/studio/wall/#p=<公開牆的包 id>`：不選資料夾，從開放資料集（`/p/<包 id>/`）把這面公開牆的照片和岩點收進瀏覽器的專案（`openPublic`），接著精修；發佈用 `packJob`，是同一個包的新版本（`version` 加一，不認人）。同一個包只收一次，專案 id 記在 localStorage（`climbio.wallpub.<包 id>`），再開直接回到那個專案。停用（`retired`）的岩點不進編輯器，只記進 `published`，之後發佈照樣留著。

## 五個步驟（步驟列，跟 Crag 同一種）

| 步驟 | 做什麼 |
|---|---|
| 牆面 | 岩館 → 分區 → 牆的卡片（縮圖、岩點數、要看幾顆）；上方是跟 Crag 路線清單同一種的工具列，「加牆面照片」（HoldScan 偵測加 HoldKit 外框，幾秒，過程用全螢幕過場）；還沒有牆時主畫面只有「加牆面照片」；點一面進岩點 |
| 岩點 | 編輯器（見下）：預設停在待確認的第一顆，一顆一顆看、修；「逐顆檢查完了」在面板底部；步驟旁小字是全部待確認幾顆 |
| 檢查 | 一整頁：還有待確認岩點、還沒按「逐顆檢查完了」、處理失敗的牆，點了打開那面（`StudioShell.checks`） |
| 報告 | 每一步的岩點外框跟最後的岩點比（見下「岩點報告」），上方切換牆；發佈步驟每面牆的「報告」也打開這裡 |
| 發佈 | 每面牆一列（`StudioShell.pubList`）：尚未發佈／已發佈第幾版／有更新；只有尚未發佈和有更新的才有「發佈」或「更新發佈」鈕（要勾選有權發佈；從公開牆收進來精修的牆不再問，收進來沒改過也不算有更新）；發佈完成後對話框只留網址，不再出現發佈鈕。發佈就是公開。每面牆都有「匯出 ZIP」（不公開）：`<牆 id>.json`（Climbio 公開格式 v2 的照片畫面，只含裁切範圍裡的岩點）和 `<牆 id>.jpg`（照片），就是[內嵌頁](embed.md)和別的 App 要的資料；匯出前先用 `validate` 驗證，不合格不匯出 |

## 岩點報告

發佈前（「報告」步驟）、已公開的牆（`/studio/wall/#r=<公開牆的包 id>`，不用專案，上方有到 `#p=` 接著精修的連結）、Lab 的 Hold Lab 頁（`/lab/hold-lab/`）是同一個畫面：`studio/wall/report.js` 算數字、`report-view.js` 畫、`report.css` 排（顏色取頁面的主題，Studio 深色、Lab 淺色）。步驟卡、定義與限制是三條線共用的報告框架（`studio/report-frame.js`、`report-frame.css`）：Lab 的 3D 牆頁用 `studio/wall3d/report.js` 把開放資料集 `climbio/wall3d-lab` 的 `pipeline/*-summary.json`（重建、偵測、投票、留出照片檢查）整理成步驟，天然岩場頁用 `studio/crag/lab-report.js` 整理包裡的 `lab.json`（每區模型、留出照片認牆、路線投影誤差）；數字一律從檔案讀，頁面不寫死。

- **階段**：發佈前從這面牆的研究記錄還原（`fromRecord`，跟發佈時寫進 `<牆 id>.edits.json` 的同一份）：自動偵測、（人選過 SAM2 的）SAM2、人工檢查。已公開的牆有開放資料集的各步比對資料（`research/hold-lab/<包 id>/stages.json`，version 2）就用它的各步外框（`fromStages`：自動偵測、重描外框、SAM2、AI 檢查），否則從那一版的 `edits.json` 和畫面還原。岩點貓的記錄（有 `final`）畫面是原始岩點，人工檢查換上 `final` 的外框。
- **數字**：最後一步是答案，前面每一步跟它一對一配對（重疊 IoU ≥ 0.3 才算找到）：蓋到答案不到 85% 是切掉一角、多出來超過 25% 是外框太大、沒配到是多認，答案沒被配到是漏掉；寫成每 100 顆真實岩點的找到、外框貼、多認。最後一步跟前一步比，有岩點 id 照 id 對，標出沒動或微調、重畫（重疊不到 0.9，跟研究記錄同一個值）、手畫新增、刪掉。各步比對資料裡原本算好的分類不用，一律在這裡重算。
- 照片上：左右拖曳對照前一步、「標出問題」用顏色標分類、「看改的地方」逐一放大這一步變好或人改過的岩點；Ctrl／⌘ 滾輪、雙指縮放。

## 從岩點貓帶進來的牆

以前從岩點貓帶進來的牆（`w.pack`）照舊能編輯、發佈成岩點貓分享包的新版本，但現在沒有帶新的進來的入口。

- 發佈是同一個包的新版本：檔案照岩點貓的分享包（`ShareTools.wallPackage`，同一個包 id、同樣的檔名）寫進開放資料集，岩點貓上的這面牆換成新版；整面都發（岩點貓沒有裁切）。
- **刪除、合併已公開的岩點＝停用**：別人在這面牆上的路線用岩點 id 指到它們（路線只帶跟牆上不同的外框）。進度檔的 `published` 記每顆已公開岩點公開時的外框 `{ id: poly }`；發佈時，已公開、現在不在岩點清單裡的（刪掉、合併掉的），照公開時的外框留在畫面裡，節點標 `props.retired: true`（`app.js` 的 `retiredOf`）；復原讓它回來就不再停用。發佈後這份外框更新成當時的樣子。
- 岩點貓收這面牆（新收的）：停用的岩點只放進原始岩點檔（補別人舊路線的外框、`retired` 標記留著），我的岩點檔沒有它，所以新路線點不到；舊路線自帶它的外框，照樣看得到、可以從路線拿掉（`js/sync.js` 的 `saveSnap`）。已經收過這面牆的人：岩點貓讀公開牆時（雲端函式 `walls` 的 `routes` 回 `src`、`ver`＝牆的畫面在哪、現在第幾版），版本跟上次不同就重讀牆的岩點（`js/sync.js` 的 `refreshHolds`、`applyPublicHolds`）：牆主人新增的加進來、停用的從我的岩點檔拿掉、沒人改過的換成新外框；我自己刪掉的不放回來，我改過、自己畫的照舊；照片尺寸變了就不動。自己公開的牆（`w.pack`）不更新。

## 編輯器（手機、電腦同一套）

照片全幅（深色），工具浮在照片上：左上上一面、下一面牆和牆名，右上復原、重做，下方一排工具（裁切、多選、待確認）；選到岩點後，動作列浮在它旁邊（手機固定在工具列上方）。右側（手機是底部一條，往上展開）只放「待確認」清單：縮圖加原因、進度條、「逐顆檢查完了」。沒有手勢、快捷鍵的說明列。

- **外框都用 HoldKit 算**（本機、幾十毫秒、不下載模型）：補點和重描跟岩點貓一樣用**長按**（滑鼠左鍵或手指原地按住 0.5 秒；拖曳、Shift、Alt 不算）：按在岩點上（或外框外一點點）是重描那顆；按在空白處是補一顆，先給以按的位置為中心、大小取附近岩點中位數的方框（碰到旁邊的岩點就縮開、不超出照片，沒有岩點時取照片短邊的 1/20），HoldKit 辨識出的外框包住按的位置、沒有蓋到別的岩點就換上，不然留著方框；兩種都是候選，可以拖頂點、拖邊上的點調整，「採用」才加進去或換上。選到一顆按「重描」也是同一個重算。沒有框選新增和手畫。
- **手動修正**：拖頂點、拖邊上任何一點新增頂點、點兩下頂點（或選到頂點按「刪頂點」）刪掉、合併、平滑、刪除、復原與重做。拖頂點時（滑鼠、觸控都一樣）上方有放大鏡，照原圖像素畫，十字線是頂點會落的位置；頂點與邊的點擊範圍在觸控時更大。
- **待確認**：有旗標的、可能重複的、SAM2 跟原外框不同還沒決定的。選到一顆跟 SAM2 不同的，兩個外框並排（綠色是原外框、青色虛線是 SAM2），動作列是「採用 SAM2」「保留原外框」；自己修了也算決定。J／K 跳到上一顆、下一顆待確認，A 沒問題，R 重描、M 合併、X 刪除、C 裁切、B 只看待確認、Z 復原、`[`、`]` 換牆。
- 手機沒有選資料夾，專案存在瀏覽器的私有檔案系統，所以從 `/lab/` 或 Studio 首頁「最近的專案」進來；沒有 SAM2（模型太大）。手機（`appkit/landing.js` 判斷，`html` 加 `ak-handset`；本機加 `?phone` 看）的版面只換掉放不下的：底部一條「上一顆、待確認幾顆、下一顆、清單」，清單往上展開（最高 52% 螢幕），按了任何動作或點了清單就收起來。
- 手機的 iPhone Safari 要實機測；Playwright 的 WebKit 存不了專案（OPFS 寫入讀回是空的），自動測試只跑 Chromium（內部 e2e 案例）。

## 代理做牆面：岩點檔的必走流程（一次做完，AI 檢查不能跳過）

AI 代理替岩館（原岩、內嵌示範、對外給岩點檔）產生或精修牆面的岩點檔，**多面牆一次做完，中途不停下來問人**；岩點辨識人眼看得出來的，AI 也要看得出來，**不把辨識的判斷丟給人**；人只負責 AI 不能代替的決定（要不要公開發佈），做完整理成一份清單**一次**交給人，人在手機的 AI App（Claude、ChatGPT…）看、回一段字就好，不用在本機環境。

**入口只有一個，所有代理（Claude、Codex、別的引擎）照同一套做：`node tools/wall-batch.mjs next <工作資料夾>`。** 它印出現在做到哪、下一步要跑的指令、要看的圖在哪、判斷檔怎麼寫；分級的規則寫在程式的 `POLICY`，不用自己讀文件、自己決定哪些要看。需要 playwright 加 Chromium；SAM2 第一次下載約 300 MB。

| 步驟 | 指令 | 誰做 |
|---|---|---|
| 1 偵測、2 SAM2 精修、3 匯出牆的分享包 | `run <工作資料夾> <照片…>` | 程式，全部牆連續跑；單面失敗自動重試（預設 3 次，SAM2 偶發的檔案系統錯誤重來就過），還不行就記 `failed` 繼續下一面；做過的牆跳過 |
| 4 分級檢查（**必做**） | `check <工作資料夾>`：先自動處理（見下「分級」），再出要看的對照圖 | 程式 |
| 5 看圖判斷（看不準的放大再看一次：`recheck`） | `next` 會列出每面牆要看的圖（`sheets/`、`sam-sheets/`、`audit-sheets/`、`overview/`）；代理逐張看圖，把全部牆的判斷寫成一個 JSON，`apply <工作資料夾> <判斷.json>` | 代理（圖多時分給子代理，最後合併成一個 JSON）。**看不準（`unsure`）不是交給人的出口**：`apply` 之後 `recheck` 把這些放大、多帶周圍（含整顆 volume）重新出大圖，這一輪**不能再答 unsure，一定要定案**（`"<牆>#recheck"`）；實在分不出來就保留原樣並在交付說明照實寫 |
| 6 整理給人 | `review <工作資料夾>` → `review/index.html`（單檔、圖都內嵌、手機寬度）；AI 還沒判斷完的牆不會交給人 | 程式 |
| 7 交給人 | 把 `review/index.html` 發成 Artifact（手機的 App 直接打開），一次貼給使用者；使用者每件點一個選項、複製回覆貼回對話 | 代理 |
| 8 記人的判斷 | 使用者回覆後逐項 `resolve <工作資料夾> <牆>:<題 id 或 sam:<岩點 id> 或 publish> <選項> --by human:<名稱> --said "<原話>"`，再 `review` 確認；更新示範資料 | 代理 |

### 分級（POLICY）：能自動的自動、AI 看圖的只看該看的，看不準的放大再看、定案

| 項目 | 怎麼處理 | 依據 |
|---|---|---|
| SAM2 重描後**沒有**「候選對不上」「分數低」旗標 | 程式直接採用 SAM2 外框，**不看圖** | 三面牆的人工檢查，98 到 99% 沒有重畫 SAM2 的外框（南港 99、市民抱石 98、萬華 96）；SAM2 的外框比 HoldKit 的粗外框準，所以「兩個外框 IoU 不到 0.9」不是要看的理由（明德 638 顆裡 592 顆如此、南港 520 顆裡 480 顆如此） |
| SAM2 有「候選對不上」「分數低」旗標 | **AI 看圖**：`sam`（採用 SAM2）、`keep`（保留原外框）、`delete`（不是岩點、重複、碎片）、`unsure`（看不準，給人） | 這兩種旗標約佔 5 到 7% 的岩點；要看的多半是重複、碎片、陰影、貼紙（要刪的約 6 成、要重描的約 2 成） |
| 兩個外框重疊（IoU）≥ 0.70 | 程式自己處理：拿掉比較小的那顆 | 用已判斷的 59 題對照：這 10 題全部是「同一顆，拿掉其中一顆」，沒有例外；0.6 到 0.7 已經開始分歧（有要合併的、有不同岩點） |
| 兩個外框重疊 < 0.70 | **AI 看圖**：`ok`（不同岩點）、`rm1`／`rm2`（拿掉重複外框）、`merge`（同一顆的兩半合成一顆）、`unsure` | 低於 0.6 混著不同岩點、重複、合併，只靠重疊分不出來 |
| 上面兩種程式自己處理的結果 | **抽查**：隨機抽 SAM2 12 個、重複岩點 6 對給 AI 看圖：`ok`／`bad`（錯的程式還原）；錯超過 25% 要在交付時說 | 自動不等於不檢查 |
| 全牆 | **總覽**：分成 3×2 張疊上外框，看系統性的錯誤（照明燈被當岩點、長方形外框疊在大岩點上、貼牆長條外框偏鬆），沒有回 `ok` | 逐顆看不出整面的問題 |
| 偵測信心低、邊緣不確定（沒有上面兩種旗標） | 採用 SAM2，**不另外看** | 試過用「小又新偵測」「面積很大」這類規則抓要刪、要改的，召回率只有兩成多，加了也不會少看多少 |

不會處理的：偵測沒找到的岩點、大量體（要人在 Studio Wall 補畫）、偵測信心低但沒被前面抓到的貼紙或陰影。交付時照實寫這幾項。

### 規定
- **不中途問人**：偵測、精修、分級檢查、修岩點、整理清單都是代理自己做完；失敗重試、記錄、繼續，不因為某面牆出錯、某題難判斷就停下來問。看不準的先答 `unsure`，由 `recheck` 放大再看並定案（定案那一輪不能再答 `unsure`），不留給人。
- **AI 檢查不能省**：`next` 列的圖都要看、判斷都要 `apply`；`review` 不會把沒做完的牆交給人；少了 AI 檢查的岩點檔不算完成，不能放進示範頁或發佈。
- **牆面資料預設是私有的**：岩館、客戶的牆面照片、岩點、路線不上公開資料集、不進公開 repo；`run` 預設不出發佈題，使用者明說這面牆要公開才加 `--public`。客戶專屬示範（仿客戶畫面的內嵌頁）只留在內部、單檔私下交付，不放公開主機。
- **人只看一種：「要不要公開發佈」**（只有公開的牆才有；只能由人答，發佈就是公開、收不回，工具不會發佈）。岩點辨識的判斷全部由 AI 做完，包括看不準的（放大再看、定案）。`review` 在 AI 檢查（重複岩點、SAM2、抽查、總覽、再看一次）都做完之前，不會把那面牆交給人。
- **不替人決定、不替人按**：人的判斷一定帶 `--by human:<名稱>` 和 `--said "<原話>"`，沒有就不收；代理不替人按「逐顆檢查完了」。
- 交付時寫明每面牆：岩點數、程式自己處理幾個、AI 看圖幾個（各判斷了什麼）、抽查錯幾個、交給人幾個、失敗的牆和原因，以及上面「不會處理的」。

## 為什麼分開

HoldScan 偵測加 HoldKit 外框（跟岩點貓同一套，本機、幾秒、不下載模型），夠定路線用，外框比較粗。要精準的外框用 SAM2（約 300 MB 的模型、每張數分鐘），只在電腦版，岩館管理者平常不用開。

## SAM2 精修（電腦版）

牆面卡片的「精準重描」整面跑一次（手機沒有）：開始前先寫幾顆、約幾分鐘（要編碼的視窗數乘上每個視窗的時間，WebGPU 約 2.3 秒、WASM 約 5.5 秒）、第一次要下載約 300 MB，確認才開始。裁切範圍裡每個偵測框重描；有 WebGPU 用 WebGPU，建不起來或第一次跑失敗就改用 WASM；編碼器從 Hugging Face 下載，第一次後存瀏覽器私有檔案系統。

- **結果掛在岩點的 `sam`**（`{ poly, flags, iou, pick }`），原外框不動：跟原外框重疊（IoU）到 0.9 以上又沒旗標的，直接採用 SAM2（`pick: 'auto'`）；其餘 `pick` 空白，進待確認，人選了才改成 `sam`（採用 SAM2）、`keep`（保留原外框）、`edited`（自己修）。岩點 id 不變，路線不受影響；手畫、改過形狀的岩點不動，已經決定過的重跑也不動。
- 跑完有待確認的，直接進那面牆的待確認。
- 旗標（SAM2 結果要看的岩點）：兩次解碼的遮罩重疊低於 0.97（小岩點低於 0.98）、偵測信心低於 0.6；只存在 `.studio`，不進公開檔案。

## 研究記錄（開放資料）

精修的結果是公開資料，目的是讓偵測越來越準。只存「自動結果跟最後結果的差異」，不存編輯過程（拖曳、復原、平滑、旗標、花多久都不記）。

- **進度檔的 `base`**（`.studio/progress/<牆 id>.json`）：自動偵測加重描的結果 `{ 岩點 id: { poly, flags } }`，由 `app.js` 的 `noteBase` 在 HoldKit 偵測時寫（SAM2 重描時只補沒有的），是原外框；SAM2 的結果在岩點的 `sam`，不覆蓋它。匯入的牆沒有 `base`。
- **牆的 `reviewed`**（`project.json`）：人按「逐顆檢查完了」的時間。沒有它，沒被改的岩點只能算「沒看過」，不能當正確答案。
- **記錄**（`record.js` 的 `buildRecord`，公開時才算，沒有 `base` 回 null）：`{ holdlab, wall, sha256, license, reviewed, tools, flagged, deleted, reshaped, added, sam }`。
  - `deleted`：誤偵測，留自動的外框。`added`：漏偵測，外框在最後的 `holds`。`reshaped`：邊界不準（重疊 IoU 低於 0.9），留自動的外框和 IoU；小修不記。沒改的不寫，等於 `base` 跟 `holds` 一致。
  - `flagged`：自動結果標了要看的岩點，沒改的也留，用來校準信心。
  - `sam`：SAM2 跟原外框不同的岩點，人的選擇：`{ 岩點 id: { poly（SAM2 的外框）, iou, flags, pick: sam｜keep｜edited } }`；一致就直接採用的不記。
  - `tools`：holdkit 版本、偵測與 SAM 模型版本。
- **公開**（編輯器工具列的「公開」，`app.js` 的 `publishUi`）：經雲端函式 `datasets`（`publishWall`）（`functions/walls-dataset.js`，不登入、不記擁有者；請求要帶 `source: 'studio'`，岩點貓 App 和舊版沒帶標記會被拒絕：公開牆只由 Studio 發佈，岩點貓不上傳牆）寫進 Hugging Face 的公開資料集 `climbio/walls`，不經過 Drive。一面牆寫成 `walls/<包 id>/v<版本>/`：`<牆 id>.jpg`、`<牆 id>.thumb.jpg`、`<牆 id>.json`（Climbio Format v2 的照片畫面）、`<牆 id>.edits.json`（上面的研究記錄，沒有 `base` 就沒有）、`index.json`；同一個 commit 更新根目錄的 `walls.jsonl`（目錄，研究者先下載它；格式見 [資料集說明](walls-dataset-card.md)）；版本每次加一、舊版本留著；只算裁切範圍內的岩點。權杖在 Secret `HF_TOKEN`（只能寫這個倉庫），讀取免登入。索引在 Firestore `datasets/{包 id}`（名稱、現行版 `version`、最新版 `latest`、`reviewed`、時間、檔案、內容雜湊，Climbio 唯一保存的資料），沒有擁有者，任何人都能發新版本，靠發佈端驗證（`functions/wall-check.js`）：每顆外框合理（至少 3 點、不超過 500 點、在照片內、面積不小於 12 像素平方也不超過照片的 4 成、不自己交叉）；新版本不能少掉前一版的岩點（刪除、合併的標成 `retired`，外框留著）；照片尺寸不變；相對前一版最多變動 30% 的岩點（新增、改形狀、停用合計，至少允許 3 顆），超過整份拒絕，要分成多次發佈。**現行版**（`/p/<id>/` 導向的版本）是最新一個「逐顆檢查完了」的版本，沒有就是最新的；新版本沒檢查過、現行版檢查過時現行版不換。每個網路來源每天最多 30 次，超過預算時暫停（同 `projects`）。不記修改時間或節奏。
- **不能收回**：公開後 Climbio 不因作者要求刪除；只有侵權、含可識別個人、法令要求才移除（要重寫倉庫歷史）。沒有私人選項，私人的牆用附近交換（WebRTC，[sharing.md](sharing.md)）傳給對方。公開前對話框列出內容並要求勾選「我有權公開」。沒有公開的牆不進任何資料集。

## 程式

- `sam.js`（SAM2.1 base+，解碼器 `models/decoder_single.onnx`、`decoder_multi.onnx`，自己匯出的，只給整面重描用）、`editor.js`、`app.js`、`index.html`。
- 外框的幾何（遮罩、輪廓、平滑、合併、找重複、修自交）用 `studio/wall/geometry.js`。
- 隱私：照片只在你的電腦上處理。

## 公開牆一定有岩館名稱，沒有擁有者

Studio 發佈的公開牆一定帶岩館名稱（新牆用分區所屬的岩館，沒有就用專案名稱；`node tools/studio.mjs publish` 沒有 `props.gym` 會拒絕）；雲端函式 `publishWall` 沒有岩館名稱回 400。岩點貓上的公開牆不能改名、不能增加照片，只能刪除。

**沒有擁有者、不用金鑰**：牆不記是誰發佈的（沿用 [open-versions.md](proposals/open-versions.md)）。只有 Studio 能發佈牆（`source: 'studio'`），任何人都能發佈新版本，在 Mac、Windows、換電腦、換 AI 代理都一樣，不用搬金鑰檔。每次發佈是新的一版（`walls/<包 id>/v<版本>/`，舊版本留著），岩館要固定在某一版，內嵌的網址就用那一版的網址（見 [embed.md](embed.md)）。

**岩點貓看到哪一版，由程式自動判定（現行版）**：新版本一定先過內容驗證（`functions/wall-check.js`：外框合理、不少掉前一版的岩點——刪除、合併的要標 `retired` 留著、照片尺寸不變、一個版本變動不超過 30%），沒過整份拒絕。通過後只有同時符合下面三項才成為現行版，否則照樣存成新版本，岩點貓不換：
1. 照片還是同一張（指紋和現行版一樣）；
2. 是最新一個「逐顆檢查完了」（`edits.json` 的 `reviewed`）的版本；
3. 現行版已經檢查過時，新版本也要檢查過。

**手動下架**：只有維護者（`node tools/wall-routes.mjs unpublish <牆 id>`，需要維護者身分）；岩館想收回就聯絡維護者。下架拿掉找牆面入口和所有人的線，資料集已公開的檔案留著；90 天沒更新也會自動下架。要更新牆用同一個牆 id 再發佈就是新版本，不用下架舊牆。
