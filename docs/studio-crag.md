# Climbio Studio：Crag（戶外岩場 Guidebook）

網址 `/studio/crag/`（Climbio Studio 的 Crag 工作區，從 Studio 首頁進來，見 [studio-design.md](studio-design.md)），給小岩場的開發者自己做一本 Guidebook：拍照、自動長出岩壁地圖、拖一拖修正、加路線、畫 Topo、輸出 [Climbio 公開格式 v2](../format/README.md)。電腦版工具（左邊岩壁地圖、右邊岩壁與照片；視窗窄時上面地圖、下面岩壁），手機也能用（見「手機」）。頂列下方的步驟列：岩場資訊 → 區域圖 → 路線清單 → 路線圖 → 發佈（見 studio-design.md 的「步驟列」）。跟 Wall 一起安裝成一個 App（`studio/manifest.webmanifest`、`studio/sw.js`）。

## 手機

手機（`appkit/landing.js` 判斷，在 `html` 加 `ak-handset`；本機加 `?phone` 看）只用來接著編現有的岩場：首頁只有「交給 AI」的說明（手機打不開專案資料夾）和最近的專案（跨裝置專案需自行匯出 ZIP／匯入，不提供帳號同步），不開新的一本、不加照片（Studio 首頁的新專案、路線圖照片條的加入照片、區域圖的示意圖、沒有岩壁時的「匯入照片」都藏起來）。五個步驟都在，只換掉手機上不好用的：

- 路線清單不是試算表：每條路線一列只看編號、名稱、難度、路線圖，點一列打開路線表單（`#routeDlg`）改所有欄位、刪除；「新增路線」也是打開表單。清單上面只留一行搜尋和新增（＋），復原、刪除、貼上表格、篩選膠囊、欄名都拿掉，區域分頁照留。發佈對話框沒有「匯出 ZIP」。表單佔滿鍵盤上面看得到的範圍（照 `visualViewport` 調整），裡面自己捲，按鈕黏在下面。長按拖曳換位置照舊。
- 不貼表格、不匯入 CSV（`#lPaste` 藏起來）；首頁也不轉換路線書。
- 區域圖的地圖佔上面六成，工具列一行（放不下左右滑）。
- 路線圖本來就是手機版面（照龍洞手機版）。

區域圖上，有拍照位置和朝向的照片畫成視錐（`geo.js` 的 `photoWedge`：拍照位置、朝向、等效焦距算的水平視角；1px 細線的扇形加深色暈，淺色地圖、航照都看得到），選到的岩壁的照片亮起來；點扇形的頂點（拍照的位置）打開那張照片的路線圖，點扇形其他地方時編輯中的形狀優先。這本有 3D 模型、照片記著模型上的鏡頭（`props.model`）時，頁首多一個「3D 場景」（`studio/scene/`，見 [studio-design.md](studio-design.md)）。

外觀是 Studio 的固定深色：顏色都用 `css/brand-tokens.css` 的 studio token（見 [studio-design.md](studio-design.md)）；Topo 路線的語意色和地圖的圖例色不換成品牌色。

一本是一個專案資料夾（同 Wall 的專案資料夾格式，見 [studio-design.md](studio-design.md)）：`index.json` 是組合，地圖、照片畫面與圖層以 id 命名為 JSON，照片以同 id 的圖片檔保存；從路線書轉換的另有 `source/`（原始檔、大綱、轉換紀錄，發佈與匯出 ZIP 一起帶，見 [guidebook-convert-format.md](guidebook-convert-format.md) 的「原始檔與重跑」）；電腦版 Chrome 使用選定的資料夾，iPad 可保存在瀏覽器中。發佈時公開內容進入 Climbio 開放資料集。

## 用法

1. AI 代理交給 Studio 首頁的照片（照片有拍照位置時猜 Crag）：建一本新的、匯入照片，自動做一次：沒有位置的照片照拍攝時間歸岩壁（`placeByTime`），有紅筆的照片描路線（見「畫 Topo」的全自動描路線）。路線表（CSV、TSV）從「加資料」進來走轉換路線書（檔名當岩場標題）。「加資料」的「建立空白岩場」（電腦，`#new`）開空的一本給自己手動建，標題列改名；「轉換路線書」（`#book`）把 Word、網頁或大綱的路線書變成一本（見下）；「匯入岩場站」（`#site`）把任何岩場站的 v2 出口變成一本（見下）；Studio 首頁最近的專案旁的「刪除」刪除整本。
2. 「匯入照片」選檔（手機可以選照片或拍照），或把照片拖到地圖、岩壁欄。每張照片讀 EXIF 的拍照資料，縮到長邊 2560、重新編碼成 JPEG（原檔的 EXIF 不留）存起來，另做縮圖。匯入的照片跟已經畫好 Topo 的照片（通常是路線書的圖，可以是裁切、縮小過的）是同一次快門、而且比較大時（見「畫 Topo」的找原圖；匯入的照片只當原圖，不會被別張換掉），原圖換掉那張：圖層照對位（單應性）搬到原圖上，原圖放進同一面岩壁、排在原來的位置，那張拿掉；還沒畫 Topo 的不換（描路線時拿來相減）。匯入中又選或拖進來的照片排在後面，這批做完接著匯入。
3. 照片自動歸岩壁：拍照位置相距 15 公尺內、而且鏡頭朝向相差 40 度內（有一張沒有朝向就只看位置）的歸同一面，取最近的；都不符合就開一面新的。拍照位置的水平誤差（EXIF 的 `GPSHPositioningError`）超過 10 公尺的不用（樹林裡、剛開定位時常有幾十到上千公尺），當成沒有拍照位置，`camera` 照原樣留著。沒有拍照位置的照片：同一批匯入裡跟某張有位置的照片拍攝時間相差 1 分鐘內，就歸到時間最接近那張的岩壁（只歸岩壁，不借位置，不參與牆線）；附近沒有的，跟前一張 1 分鐘內連拍的同類照片歸同一面；否則自己一面、沒有牆線。這些照片縮圖左下角都有標記，地圖上不畫它們的拍照點。
4. 調整：點縮圖右上角的圓圈選取（可以多選；點縮圖本身是畫 Topo），下方列「移到…」別的岩壁或新岩壁、刪除；縮圖也可以直接拖到別的岩壁或「新岩壁」。岩壁的「⋯」合併到別面、刪除（照片一起刪）。岩壁名稱直接改。空掉的岩壁自動拿掉。
5. 岩壁地圖（`mapkit/` 的 `MapEditor`，見下面「岩壁地圖」）：每面岩壁一段牆線（匯入的岩場站也可能是岩石的多邊形）。平常點岩壁只是選取（右邊那張小卡跟著亮）。步驟列的「區域圖」是編輯模式：地圖放寬、上方一排工具；點岩壁、岩石、區域、步道選到它，拖頂點修正、按邊上的中點加頂點、右鍵刪頂點，「岩壁面換邊」把牆線反過來，「刪除」拿掉這塊形狀（岩壁、區域和上面的路線留著）；「畫岩石／岩壁／區域／步道」點地圖加點，「完成」後岩石、岩壁、區域要取名稱（岩石、岩壁在哪個區域裡就放進那個區域），Enter 完成、Esc 取消；「復原」（Ctrl／⌘＋Z）退回上一步。修過的形狀之後不再照照片自動重算。滾輪或雙指縮放與旋轉，拖曳平移；左上角開關底圖、回到整張。
   - 「區域圖」專心畫好區域圖：底圖（航照、等高線、OpenStreetMap）一開始都不開，在左上的底圖選單開，或按 `A`（航照）、`T`（等高線）。照片的拍照位置是程式用的（照片自動歸岩壁、推估牆線），不畫在地圖上。
   - 右邊換成區域清單（不放路線）：區域、岩壁、岩石照節點樹，顏色跟路線表格一樣，名稱直接改。點一列選到地圖上的形狀並縮放到它；點地圖上的形狀，清單跟著亮。大區域常被裡面的岩石蓋住：點它的邊、或在清單點它，就選得到。
   - 還沒有形狀的（例如匯入時只有名稱的區域、沒有拍照位置的岩壁）那列有「畫範圍」／「畫牆線」，畫完接到那個節點。
   - 岩場位置：書裡有岩場節點（匯入岩場站、轉換路線書建的）時，清單最上面多一欄，貼 Google 地圖複製的「緯度, 經度」，存成岩場節點的 `geo`（Point）。發佈時照片都沒有拍攝位置（路線書轉的），就用它當岩場在紅點貓世界地圖上的位置；照片有拍攝位置照舊用照片的。清空就拿掉。
   - 新增區域：清單最下面「新增區域」→ 在地圖上框一圈 → `Enter`（或工具列的完成）。框到的岩壁、岩石（還不在別的區域裡）自動放進這個區域；名稱先叫「區域 n」，清單裡的名稱框已經選好，直接打。畫岩石、岩壁也一樣，不跳出取名的對話框。
6. 示意圖：地圖左上角的「示意圖」載入一張圖（例如路線書裡手畫的岩場配置），半透明疊在地圖上，載入後進入對準：拖曳移動，拖右上角的圓點旋轉和縮放，按打勾完成。之後照著示意圖拖牆線（可以同時開航照底圖對照）。再按一次可以重新對準、換一張（沿用位置）或拿掉。示意圖僅供 Studio Crag 編輯使用：圖存在本機，位置寫在 `author:sketch`，不匯出、不發佈。
7. 岩場資訊（右上的設定、步驟列的「岩場資訊」）：名稱、國家（ISO 國碼，使用者自己選，存在 `author:country`，發佈時以 `cc` 寫進世界清單，紅點貓的世界用它分第一層；不選就沒有 `cc`，不寫進公開格式的 `props.settings`）、署名（寫進 Guidebook 和自己建立、跟著 Guidebook 署名的檔案的 `attribution`，匯入的檔案不動；從別人的版本改來的只能加上自己的，見「匯入岩場站」）、難度系統（預設 YDS，貼上時認不出系統的難度和列表顯示用它；抱石的路線用抱石的系統：岩場是法式就用 Font，其他用 V，岩場本來就用 V、Font 照舊，難度的選單和篩選的區間也跟著）。岩壁離拍照點的距離（5 公尺）、磁偏角（0）是算牆線用的參數，不給人改。岩壁地圖由 AI 代理照照片產生（`M.regenerate`），人不用重算，拖牆線修正就好（2026-11-22 拿掉「照照片重新產生岩壁地圖」鈕）。
8. 「匯出」下載 ZIP：`index.json`（組合）、`<id>.json`（地圖、照片畫面、圖層）、照片檔（照片畫面的 `href`，自己拍的是 `<id>.jpg`）；每份 JSON 先過 `format/format.js` 的 `validate`。另外附下載照片前先看的圖（紅點貓收這本時先顯示）：一張合成預覽圖 `preview.jpg`（720 px 寬：上面是入口照片 4:3，下面把每張照片的小圖 120×90 排成每列 6 格；組合的 `props.preview` 記位置，照片項目的 `props.tile` 是第幾格），收的人只要先下載這一張，照片下載到哪、小圖就亮到哪；清單上的卡片用它的上半，不另存入口照片。岩壁數、路線數也不存，讀的人從組合的 `nodes` 數。檔案放法照公開格式的「放法與連結」（[format/README.md](../format/README.md)）：路線節點在組合的 `nodes`，圖層只放 bolt、確保站和標註，`tools/format-placement.mjs` 檢查。發佈前一定要有岩場位置（照片的拍攝位置、岩場節點的 `geo`／「岩場位置」欄位，或地圖上岩場形狀的中心：岩壁、分區的牆線，岩石、區域、岩場的範圍，道路、陸地不算），都沒有就不能發佈；另外附給世界地圖圖釘用的縮圖 `thumb.jpg`（240×180，只有入口照片）。發佈的檔案不同：只放 `index.json`（入口）、`pack.json`（其餘 JSON 全部合在裡面，檔名 → 文件）和照片檔，不再逐檔發佈 JSON；讀的一方（紅點貓、Studio 匯入）只讀 `pack.json`。不附辨識用的特徵點檔；匯入來的照片帶著別人的特徵點欄位（`props.features`）也不帶進這本。
9. 「發佈」：公開放進開放資料集 `climbio/crags`，得到一個公開網址（見「發佈」）。發佈就是公開；要私下給人用匯出 ZIP 或備份，Climbio 不管這一塊。

## 路線清單（步驟「路線清單」，`studio/crag/grid.js`）

專心改、找路線：整個畫面只有路線表格（不放區域圖、不放照片）。照片在「路線圖」、岩壁的形狀與合併在「區域圖」。

- 每面岩壁一段（標題列是岩壁名稱和路線數，名稱直接改），還沒分配岩壁的在最上面「未分配」（有才出現）；岩壁照節點樹排，區、岩場這類上層當標題。最上面一列欄名黏在頂端，每段的欄對齊。
- 表格上面一條工具列（跟區域圖、路線圖同一種，只有圖示，名稱與快捷鍵在提示）：復原、新增路線（`Ctrl+Enter`）、貼上表格、搜尋（`Ctrl+F`）；選到路線才出現刪除。
- 選取與拖曳（SortableJS，`studio/vendor/`）：長按一列（或點編號那格）選整列，Shift 選一塊；長按後按著拖，選到的列一起搬，放下去的位置即時讓出來，放開才存（可以拖到別面岩壁；拖的時候才在最下面出現「未分配」和「新岩壁」，新岩壁在有岩場節點的書裡放在岩場底下）。岩壁、區域按著標題拖（名稱框、按鈕以外；標題不會反白選到路線的字）：岩壁可以換位置、拖進別的區域；區域連底下的岩壁一起搬，在同一層換位置（`M.moveNode`，順序記在 `props.order`）。路線清單裡區域是一個區塊（標題＋底下的岩壁、區域），大區域是上面的分頁。岩壁的合併在區域圖。`Alt+↑↓` 也能把選到的列往上、往下移。
- 分大區域看：岩場分成兩個以上大區域（從最上層往下，第一層分開的區域）時，欄名上面一排大區域（含路線數），一次看一個；從路線圖回來或選了別區的岩壁，就換到那一區。搜尋時看全部。只有岩壁、沒有區域就不分。
- 篩選（跟龍洞一樣的膠囊，在欄名上面）：難度區間（YDS 是 5.9-／5.10／5.11／5.12／5.13+，V 每三級一段，其他照開頭的數字）、路線種類、沒畫路線圖；同一組選幾個是任一個，不同組都要符合。只列目前大區域有的，兩個以上才列。不排序，路線照編號的順序。欄寬至少放得下欄名。
- 最右邊「路線圖」欄：這條畫好 Topo 的打勾。
- 路線編號（岩場資訊選）：每面岩壁從 1 開始（預設）、每個大區域從 1 開始（同一個 area 節點底下照岩壁、路線的順序一路編；沒有區域時整個岩場就是一個區域）、手動（像龍洞：多一欄「路線編號」存在路線的 `props.number`，編號那格空著）。Topo 的編號牌照這個編號。岩場資訊頁的選項用膠囊、字短（「每面岩壁」「每個區域」「手動」；「附上底圖」只列航照、等高線），完整說明放在 `title`。
- 新增路線插在目前那列的下面（沒有選到就接在目前岩壁、或第一面岩壁的最後），叫「新路線」、名稱框已經選好，直接打。
- 搜尋：任何一格有這段字的路線（名稱、難度、首攀、說明……）；沒有符合的岩壁整段藏起來。
- 欄名照龍洞的路線 Sheet（維護的人最多，不用重新學）：路線名稱、難度、路線種類、高度、繩距、Bolt 數、首攀、定線者、代號、路線資訊描述；最左邊是編號（在岩壁裡的順序），最右邊一小條表示 Topo 畫了沒。顯示哪些欄位是岩場資訊的「進階：路線表格的欄位」（`author:columns`）；沒選過時是基本欄位（難度、路線種類、高度、Bolt 數、路線資訊描述）加上有資料的繩距、首攀、定線者。
- 難度、路線種類用選的，不用手打：編輯時格子下面出現清單（難度照預設系統由易到難：YDS、French、Font、UIAA、V、段級；British 沒有清單照打），打幾個字縮小範圍（打 `11` 剩 5.11a～d），↑↓ 移動、Enter／Tab／點一下選。打的字不是清單裡的，存成清單裡第一個有這段字的（打「運」存「運動」）。
- 操作像 Google 試算表，但點一下格子就編輯（拖過別格或 Shift 是選一塊；編輯框跟格子一樣大，字比格子寬才往右長）；難度、路線種類的選單放在最上層，不被下面的岩壁蓋住，下面放不下就放上面。沒在編輯時方向鍵移動、直接打字（含中文輸入法）蓋掉、Enter／F2 改原本的內容；編輯中貼上多格（Tab、換行分隔）照表格貼；Enter 存了往下、Tab 往右、Esc 取消、Alt＋Enter 換行；方向鍵移動；Delete 清空（名稱不能清）；Ctrl＋C／X／V 複製、剪下、貼上（Tab 分隔，跟試算表互通）；Ctrl＋D 用第一列往下填；Ctrl＋Z 復原（跟區域圖同一份復原紀錄）。存檔後表格重畫時，正在打的字留著。
- 貼上從選取的左上角往右、往下蓋過去，只蓋在同一面岩壁裡；超過這面岩壁最後一條的列變成新的路線（要有名稱，沒有的提示不新增）。
- 高度、繩距、Bolt 數要是數字，打錯的格子不改並提示。多語的名稱與說明只改中文。移動、新增後同名同岩壁的跳提示，不擋。
- 區域的顏色照龍洞網站：大區域各一個顏色（節點的 `props.color` 有寫就用它，否則照龍洞的九個顏色依序配），底下的分區、岩壁用同一個顏色由深到淺；只有一個的上層（整個岩場）不上色。顏色是算出來的，不存進資料。
- 工具列的「貼上表格」（貼上表格、匯入 CSV：一次加很多條，可以對應欄位；對話框裡「選 CSV 檔」）：
  - 貼上表格與 CSV：有 Tab 就當試算表複製的，否則是 CSV（逗號或分號，引號裡可以換行；檔案不是 UTF-8 就當 Big5）。第一列有認得的欄名（名稱、難度、類型、長度、繩距、bolt、說明、首攀、定線者、代號、岩壁，中英文都認）就當標題；沒有標題時看內容猜（難度、類型、數字依序是長度和 bolt 數、文字是名稱）。每欄的對應、有沒有標題都能改。「岩壁」欄照名稱放進已有的岩壁，沒有的開新的；沒有這欄就放進選的岩壁。同名（不分大小寫）同岩壁的標成重複，預設略過。在 Guidebook 裡（不在表格、輸入框）直接貼上、或把 CSV 拖進來，也會打開貼上路線。
  - 難度寫成 `{ 系統: 值 }`：`5.11a` 是 yds、`V3` 是 v、`初段` 是 dan；`6a`／`6A` 預設系統是 French 或 Font 就照它，否則小寫當 French、大寫當 Font；認不出的用預設系統。類型認中英文（運動、傳統、抱石、頂繩……），認不出的照原樣。
- 工具列的「加入資料」：這本匯入照片、貼上表格（手機沒有這顆）；新的一本、路線書、岩場站由 AI 代理做（Studio 首頁的「交給 AI」）。
- 照片在「路線圖」：照片條最後的「＋」加入照片（還沒有照片時，步驟列的「路線圖」直接選照片，匯入的進度寫在步驟上），按右鍵移到別面岩壁或刪除；岩壁合併、刪除也可以在「區域圖」清單那列的「…」。
- 頂列只有返回和名稱：匯入照片、路線、發佈、匯出、設定都在步驟裡。
- 畫 Topo 畫面右邊的「新增路線」用對話框（名稱、難度、類型、長度、繩距、bolt 數、首攀、定線者、岩壁、代號、說明）。

## 畫 Topo（`studio/crag/topo.js`，用 TopoKit 的 `TopoEditor`）

- 點照片縮圖打開（網址 `#<組合 id>/<照片 id>`，返回鍵回到 Guidebook）。版面跟龍洞手機版一樣，電腦和手機同一套：照片佔滿畫圖區（外面是深色），控制浮在照片上。
- 浮在照片上的控制（半透明深色底、白字，跟岩點貓的圓鈕一樣）：
  - 左上是目前的路線（編號、名稱），點了打開路線清單（這張照片可以畫的路線，這張畫好的深色勾、別張畫好的淡色勾，最下面「新增路線」）；`↑↓` 換路線，也可以直接點照片上的線。
  - 左下選工具：畫線 `L`、Bolt `B`，按了才開，再按一次或 `Esc` 回到調整。Bolt 跟線分開：平常只看線、只改線（bolt 不顯示也點不到）；開了 Bolt 才顯示 bolt（放大才畫全部路線的），上面一排選放 Bolt 或確保站 `A`。
  - 右下：分岔 `F`（畫線時、有別條路線可以分岔才出現）、復原 `Z`（重做 `Y`）、刪除點 `Delete`／右鍵（選到點時才出現）。
  - 放大鏡（TopoKit 的 `aim: 'always'`）：手指按住瞄準、拖點時顯示，滑鼠拖點也是。沒有縮放按鈕：滾輪、雙指縮放。
  - 照片下面一排整本的照片，照岩壁排（岩壁名稱夾在中間），目前的框起來，角落的數字是這張畫了幾條；點了或按 `[` `]`（PageUp／PageDown）換上一張、下一張。
  - 快捷鍵整個畫面都有效（TopoKit 的 `keys.window`），打字、對話框裡不算。
- 編輯時就是紅點貓看到的樣子（TopoKit 只有一種樣子；bolt 只在 Bolt 工具時顯示，那時 `bolts: 'zoom'` 跟紅點貓一樣）：粗線、編號帶難度、名稱；只有正在編的那條為了編輯照原樣（每個點有把手、頭尾不收、牌子避開它的點）。bolt 牌子帶位置（「× B01」）只給有在管理 bolt 編號的岩場：匯入的圖層裡就有 bolt、確保站（例如龍洞，`M.managesBolts`）；小岩場只標 ×。
- 清單是這面岩壁（照片的 `props.node`）的路線，加上圖層上已經有的別面岩壁的路線；照片同時拍到別面岩壁（例如糖果屋和女巫塔在同一張）時，清單底下的「其他岩壁的路線」展開（有別面岩壁的路線才出現），挑一條就加進這張照片的圖層、畫線後出現在上面的清單；打開時選好第一條這張還沒畫的。右邊的短線：亮色是這張畫過、灰色是別張照片畫過。「新增路線」在這面岩壁加一條並選起來。
- 平常是「調整」（TopoKit 的 `edit` 工具，沒有按鈕；`V` 也回到調整）：點別條線換成那條路線，點這條的線在那裡插一個點，拖點移動，點空白處不加點；這條還沒有線時點空白處一直加點（換路線、換工具、`Esc` 才停），按著 Shift 點也加點。其他工具：畫線（一直往後加點，點在線段中間插進那一段）、Bolt（`B01`、`B02`…）、確保站（`A01`…）；分岔（還沒畫線的路線點別條線的一個點，複製到那裡為止的前段）、刪除點（或右鍵、`Delete`）、清除這條、復原／重做（`Z`、`Y`）。滾輪、雙指縮放，手機點一下加點。
- 從照片描路線（路線圖照片條的第一顆，全自動；描完重新打開這張）：整本的照片都描線，每張的線由左到右。轉換路線書建的書，每張照片帶著它拍到的路線（大綱裡照片後面的表格；排列由右至左的已轉成由左到右），這張的線只在這幾條裡依序配，前面照片的線數對不上不會把後面擠掉；配完就拿掉這份提示，不留在照片上。沒有提示的照片（手動加的、之後再描的）依序配給這面岩壁還沒畫線的路線（照清單順序）；畫好的路線不動，多出來的線不配，提示幾條沒有路線可配。路線書的圖跟作者的原始照片都在這本時，先找出同一次快門的原圖（見下面的找原圖），原圖照對位對齊到路線書的圖再相減，取出作者的筆跡：線從起點完整描到頂、bolt 的小 X 也抓得到（靠近線的給那條線，其他照左右分串，三個以上、上下排開的一串變成一條只有 bolt 的路線，由下往上 B01、B02…；最上面兩個差不多一樣高、左右挨著的是確保站 A01、A02，只有這樣並排兩個的是只標了確保站的路線〔傳統攀〕，沒有線段），筆跡只算偏紅的顏色，座標照對位換到原圖上，線和 bolt 畫在乾淨的原圖上；原圖換掉路線書那張（同一面岩壁、同一個位置，路線書那張拿掉；已經畫了 Topo 的圖層照對位搬過去）。找不到原圖的照片照舊找紅筆。沒有提示的照片，路線書大多照照片順序、由左到右列路線，所以多半配得對；配錯的在畫 Topo 裡修：選錯的那條「清除這條」，選對的路線重畫。
- 找原圖（`studio/crag/pair.js`）：路線書的圖常是裁切、縮小、轉了一點、調過亮度、畫了紅線的，所以不比整張的長相，先用照片的特徵點（`studio/crag/match.js`：AKAZE＋單應性，OpenCV.js 在 Worker 裡跑）找候選（每張大的照片跟每張比它小的比，內點 8 個以上的前三名），原圖裁出對應的區域（多留 15%）再算一次特徵點、比一次得到精準的對位（裁到只剩四成的也對得準，線的誤差約 1～2 像素），最後原圖照對位對齊到路線書的圖、逐像素比灰階的相關係數（紅筆的像素不算，`trace.js` 的 `alignScore`）：0.78 以上算同一次快門（同一張裁切、縮小、調亮度的 0.8～0.97；同一面岩壁的連拍、換位置拍的 0.4～0.73，幾乎一樣的連拍可能到 0.9，所以取最高的）。一對一：路線書常把同一張照片放兩次（整張和裁切的特寫），本身還找得到更大原圖的照片不當原圖，同一張原圖先配最大的那張（特寫留著）。門檻用 48 張故意裁切（四成到全張）、縮小（480～1000 px）、轉 3 度、調亮度、畫紅線的大邱田照片和同一面岩壁的連拍定的；大邱田的 Google 文件加上作者的 57 張照片實測：路線書 46 張圖裡 29 張找到原圖，都放進對的岩壁（作者的照片裡有 6 張縮小的副本，所以匯入、一起選的照片只當原圖）。
- 紅線辨識（純運算在 `sourcekit/trace.js`，紅點貓收藏共用；`studio/crag/trace.js` 只負責取像素與對齊；「從照片描路線」用）：照片縮到長邊 1200 像素再找：挑出很鮮的紅色（手機或電腦畫的純色，地上的落葉、紅土不算），拿掉白底名牌裡的紅字，把虛線的空隙補起來，夠長的一組細化後取最長的一條路、簡化成折線（起點是比較低的一端，繞著起攀圈的開頭換成圈的中心）；兩條路線共用起點（V）或頂端（∧）時從最低（最高）點拆成兩條；比對角線一成短的碎片（文字、抱石墊）不要。照片拍到的路線比找到的線多（共線）時，在骨架上找由下往上、端點到端點的路徑（y 不會往下超過對角線 2%），一條一條挑蓋到最多還沒蓋到的，直到剩下的都是細化的小毛刺；還是少就把黃筆（接線）也算進去再找一次；數量比照片上的路線多就維持原樣。**共線的路徑必須共用同一組點**：Topo 沒有共用線段，分岔、合併是複製前段的點，兩端座標相同的線段 topokit 才視為共用、只畫一次（`topokit/lines.js`），所以依每個像素被哪些路徑走過把路徑切段，同一段只簡化一次、各路徑接起來；各自簡化會讓共用的一段座標差一點，變成每條各畫各的。共用起點的線，頂端在左邊的排前面。原圖相減（`traceDiff`）也帶路線數，共線拆分與黃色接線一樣有效（路線數是路線書那張照片帶的，換成原圖後不再有）。路線書抽出的照片標 `origin: 'authorized'`：轉換、發佈的人聲明有權利，工具不另外檢查來源與授權。
- 任何顏色的線、號碼牌與路線號碼（`sourcekit/trace.js` 的 `tracePen`、`traceDashes`、`traceBadges`、`traceTopo`，`sourcekit/badge-digits.js` 讀號碼）：沒有紅線時（`traceBlob`）找任何顏色的細長鮮色線，白色虛線另外用「方向一致、長短間距均勻、至少 4 段」的鏈偵測；照片上印的號碼牌（純色方塊加白色號碼）也偵測，並用樣板讀出號碼（不是每個都對）。找不到線的號碼牌，全自動標成**路線號碼**（沒有線、只有位置的路線：指向路線節點的 `Point` 標註，`props.label` 是號碼、`props.size` 是牌子邊長、`props.style.stroke` 是原牌子的顏色；topokit 把牌子蓋成 1.2 倍、蓋住原牌子），讀到的號碼配給編號一樣的路線，其他照左到右的順序配。畫 Topo 的工具列有「號碼」（快捷鍵 N）：點一下標出選取路線的號碼位置，拖曳把手移動，路線有線（兩點以上）時以線為準、不寫號碼位置；路線清單的打勾、照片角落的數字、發佈前的「畫過 Topo」都把路線號碼算進去。
- 每次修改存成這張照片的圖層（一張照片一個圖層，同一條路線可以在好幾張）。全部清掉就拿掉圖層。
- 線停在確保站中間（自動，`M.endAtAnchors`）：線的最後兩點剛好是這條路線的兩顆確保站時（紅線辨識、舊資料常把兩顆確保站連起來，線尾橫著拐一下），換成兩顆的中間。存圖層、匯入岩場、打開一本時都做，改了就存回去。
- 相鄰路線的起點對齊（自動，`M.alignStarts`，存檔時）：照片上左右相鄰（起點水平距離在照片寬 12% 內）、起點高度差在照片高 4% 內的一群，起點都截到那一群最高的起點，編號牌排成一條水平線比較整齊；只截短、不往下補。
- 路線清單的每一列標出畫過線的路線（亮色短線）；畫過的照片縮圖右下角有標記。
- 刪路線時圖層上它的線段與 bolt 一起清；刪照片、刪岩壁時圖層一起刪。

給維護者的教學見 [guidebook-convert.md](guidebook-convert.md)（含大綱的完整寫法）。

- AI 代理交給 Studio 首頁的路線書打開轉換對話框（`crag/#bookInbox=…`；轉換來的岩場列在岩場頁、標「路線書」，見 studio-design.md）：選檔案或在文字框貼上、改**大綱**（Markdown：`#` 岩場、`##`… 區與岩壁、「欄位：值」、路線表格、`![圖說](檔名)`），下面即時顯示會變成幾區、幾面岩壁、幾條路線、幾張照片（找不到圖檔的另外算）和要修的地方，「建立」開一本新的（存在瀏覽器裡）。
- 讀檔不用 AI（`docread.js`）：Word（`.docx`：`word/document.xml` 的段落樣式 `Heading1`…、`Title`，表格，圖片照 `r:embed` 對到 `word/media/`）、網頁（`.html`，或 ZIP 裡的，例如 Google 文件的「網頁（.html，壓縮）」：`h1`…、`p.title`、表格、`img`），讀成一串區塊再排成大綱（`toOutline`）：書名（沒有就是第一個標題）去掉「戶外岩場路線書」這類字尾當岩場；標題拿掉【】、前面的編號、中文後接的英文翻譯，層數照樹的深度；編號接著前一個標題（例如 14 之後的「15.沙漏石」）的一般段落當同一層的標題；最上層的一般段落和名稱跟交通有關（交通、車行、停車、公車……）、底下沒有表格與下層標題的段落收進岩場的「交通」，圖不收；其他只有文字的最上層標題（警示、救援）收進岩場的「說明」；圖片後緊接、40 字以內的一行是圖說（這一節第一個就是圖片時不算）。大綱、`.md`、`.txt` 照原樣讀；一起選的圖片照路徑、檔名（不分大小寫）對到大綱的圖。
- 大綱 → Guidebook（`outline.js` 的 `fromOutline`）：最上層的標題是岩場（`crag`），底下還有標題、或表格有「岩壁」欄的是區（`area`），其他是岩壁（`wall`）；節點的 `props.order` 照大綱的順序。表格照「貼上路線」的規則讀（`table.js`；欄名對不上時找欄名裡的關鍵字，取最靠後的）；「岩壁」欄開同名的岩壁；區底下沒有岩壁欄的路線收在區底下（路線清單列在「未分配」）並提醒。路線沒寫類型時用上層的「類型」，再沒有就看難度（V、Font 是抱石）和 bolt 數（運動）；bolt 欄有「傳攀」這類字的是那個類型、數字是 bolt 數；名稱兩行而第二行是英文的是多語名稱。岩場的「來源」（https）寫成組合的 `source.url`，「署名」「授權」寫在組合。圖片放進它的岩壁（`M.addPhoto` 指定岩壁），區或岩場底下的不放。
- 「複製給 AI」：複製 `outline.js` 的 `AI_PROMPT`、規則讀到的問題和目前的大綱，使用者貼給任何 AI 聊天，再把回覆貼回文字框。
- 建立：照片照「匯入照片」處理（縮圖、重新編碼），接著跑一次全自動描路線。直接選的照片大綱沒用到的（例如作者的原圖，預覽寫「另外 N 張照片」）也收進來，找原圖時換掉同一次快門的路線書圖；沒配到的不留（不然每張開一面空的岩壁），提示幾張沒有放進來。
- 命令列：`node tools/guidebook.mjs read|check|build|apply|validate|prompt`（見 [guidebook-convert-format.md](guidebook-convert-format.md) 的「命令列」）。讀檔在 `convert.js`、問題清單在 `report.js`，Studio 的轉換預覽和命令列共用；`build` 在無畫面的 Chromium 跑 Studio 本身，換原圖、描紅線的結果跟在 Studio 按「建立」一樣。
- 底線是每條路線都有東西可點：`model.js` 的 `autoTopo` 在描線之後，替照片上有、卻沒描出線的路線補一個短線段記號（`author:stub`，位置平均排開在照片下半；只補確定拍在這張照片上的：大綱附了這張的路線，或這面岩壁只有一張照片），Topo 編輯器裡拖到位置或重畫。
- 岩場位置（`outline.js` 的 `findPosition`）：從文字抓「緯度, 經度」寫進岩場節點的 `geo`；對話框有「岩場位置」欄（自動填、可改、自己填的優先）。天然岩場沒有位置不能發佈（`publish.js` 的 `needsPosition`）。
- 區域圖：區或岩場底下的圖掛在那個節點上（`overview`，沒有路線，不描線、不找原圖，`model.js` 的 `isOverview`），紅點貓顯示在岩場頁的區域照片；有座標的區域圖另轉成 GeoJSON（「區域圖給 AI」複製 `ai-prompt.js` 的 `AI_MAP_PROMPT` 加岩壁標題）。
- 給 AI 的提示只有 `studio/crag/ai-prompt.js` 一份（沒有 import）；教學頁 `guides/convert/`（`/guides/convert/`；舊網址 `/studio/convert/` 轉過去，大綱格式說明 `studio/convert/ai-work.txt` 網址不變）直接讀它。原始照片是轉完之後的選用優化（建立後加進照片，Studio 比對換上）。
- 照片與路線的對應、排列、地圖（`outline.js`）：「排列：由右至左／由左至右」寫在岩場、區或岩壁（轉換文件時從「Right to left 右至左」這類一行短字自動判斷）；一面岩壁有好幾張表時，每張表是它前面那張照片拍到的路線，只有一張照片時整面的路線都是它的，同一張照片後面的第二張以後的表是照片上沒有畫線的路線；照片帶著由左到右的路線給「從照片描路線」用（見上面）。選檔時一起選 `.geojson`（或放在 ZIP 裡）是岩壁地圖：`LineString` 的 `properties.wall` 是岩壁名稱（牆底線，畫線方向決定面朝）、`properties.kind` 是 `trail`／`route`，`Point` 的 `properties.name` 是地點；畫出來的線當成手動畫的，之後加照片也不重算；地圖畫面的 `props` 一併設好：`bounds`（所有線和地點外加 30 公尺，步道、入口都在裡面）、`home`（一開始的畫面，只對岩壁外加 25 公尺）、`fit: contain`（縮小時寬高都放得進畫面，沒寫的話直立的手機看不到整張的寬）。示意圖只存在這台電腦、不會匯出，要讓地圖跟著岩場走，就把手繪圖轉成這份向量地圖（岩壁位置用有 GPS 的岩壁校正，手繪圖大多不成比例，殘差有十幾公尺，所以位置以 GPS 為準、手繪圖只提供朝向和步道的形狀）。

## 匯入岩場站（`studio/crag/site.js`）

- Studio 首頁的「匯入岩場站」打開「匯入岩場」，體驗照紅點貓的收岩場（見 [redpoint.md](redpoint.md) 的「收岩場」）：
  - 上面貼網址或分享連結（「貼上連結」讀剪貼簿，分享訊息夾著文字也行），按了直接匯入，不再多問。
  - 下面是 Climbio 上發佈的岩場（雲端函式 `datasets` 的 `list`，跟紅點貓的「世界」同一份：縮圖、名稱、發佈日期）和常用的岩場站（龍洞）。選了先看確認卡：背景已經在下載，按「匯入」才存成一本；「取消」就不收。
  - 開箱：封面（發佈時做的合成預覽圖上半，沒有就是第一張下載好的照片）從模糊到清楚，每張照片一格小圖（預覽圖下面那格），下載到哪亮到哪，數字「21 面岩壁 · 49 條路線 · 照片 17/30」跟著跳；下載好、也按了匯入就打開那一本。
  - 同一個岩場匯入過（專案記了來源網址：`project.json` 的 `src`，最近的專案清單也帶著；Climbio 發佈的看 `/p/<id>/`，開發版、正式版的網址算同一個）：直接打開那一本，不再下載、不變成兩本。
  - 照片 4 張一起下載（每個檔案經過公開網址要一秒多，一張一張太慢）。別的網站的圖先下載成 blob 再顯示（頁面的 CSP 只讓圖片讀自己的網站）。
- 讀法：任何岩場站的 v2 出口網址（入口是一個組合，例如 `https://longdong.web.app/climbio/longdong.json`），順著 `items` 讀完整棵組合樹（同一層一起讀），變成一本新的 Guidebook，Topo 照片下載存進本機。只收 `https`（入口、項目、照片都是），圖檔要是圖片；網址沒有資料（404）說可能已經下架或換了網址。
- 網址可以是岩場站的入口、公開發佈的 `/p/<id>/index.json` 入口，也可以直接貼分享連結：App 網址 `?topo=<網址>` 取出那個網址（`site.js` 的 `entryOf`）。
- 連結 `/studio/crag/#site=<網址>`（網址用 `encodeURIComponent` 編碼）：打開就直接匯入那個網址，匯入完打開來編。每打開一次就匯入成新的一本。
- 網址只收 https。入口有 `props.pack` 就先讀 `pack.json` 一次、其餘的檔案從裡面拿；讀不到才一份一份讀。
- 節點：岩場、區（`area`）、分區（`sector`）、路線照原本的 id 與樹收進組合的 `nodes`；分區就是放路線的岩壁。路線原本的欄位和岩場站自己的詞彙（`站名:欄位`，例如龍洞的 `longdong:` 五金、安全評級）照原樣，不另外換算；沒有 `order` 的補上原本的順序。
- 岩壁地圖：各區的地圖畫面併成一張（步道、道路、區域這些標註一起；地圖自己的節點，例如地點，留在地圖畫面的 `nodes`），只有一段的 `MultiLineString` 換成 `LineString`，當成手動畫的線（之後加照片不重算）。
- Topo：照片畫面和疊在上面的圖層內容原樣收進來，換新的檔案 id（同一台裝置匯入兩次各存一份）；照片的 `props.node` 是圖層上路線所在的分區，所以縮圖出現在那面岩壁。可以直接接著畫（編輯的就是匯入的圖層），打開時線段的編號牌照路線的編號。
- 3D 模型（`surface: model` 的畫面，例如大砲岩）和模型上的路線圖層：Studio Crag 不編輯，原樣帶著（換新的 id，模型檔一起下載存進專案），從模型拍的快照（照片畫面的 `props.model`）指到新的模型；發佈時連模型檔（`.glb` 或高斯潑濺 `.spz`）一起放進開放資料集，紅點貓打開就是 3D。
- **3D 版說明頁**：[`guides/crag3d.html`](../guides/crag3d.html)（英文版 `en/guides/crag3d.html`；舊網址 `/studio/crag3d/` 轉過去）寫「把 2D 路線書變成 3D 版」的流程（拍兩套照片、建模、AI 把 2D 路線放到 3D、檢查、發佈）、誰做什麼、現況；拍法在 [`guides/shoot-3d.html`](../guides/shoot-3d.html) 的「岩場 3D 模型：退後拍一套」（貼近拍給岩壁近處與起攀辨識，退後拍給高斯潑濺：站在步道離岩壁 8–12 m、弧線每 1–2 m 一張、高中低各一輪、加岩頂樹冠與兩端、轉角左右斜 35°）。兩頁都是靜態頁，沒有 i18n 語言包，中英各一份，改一邊記得改另一邊。
- 署名：組合寫 `derivedFrom`（入口網址、id、時間），署名、授權用入口的；照片、圖層、地圖保留原本的 `attribution`、`license`，另寫 `derivedFrom`（原本那份的網址、id、時間）。原本的署名拿不掉：匯入時記在本機（`props['author:origin']`，匯出時拿掉），設定、發佈畫面上方列出原本的署名，欄位只填自己的；Guidebook 的署名寫成「原本的；自己 改編」，沒填就是原本的。改署名只換 Guidebook 和自己建立的檔案（沒有 `derivedFrom`、`source` 的），匯入的不換。
- 是快照：之後岩場站改了不會同步，也不回寫（龍洞的路線主資料仍是 TOCC 的試算表）。

## 岩壁地圖（`studio/crag/map.js`，用 mapkit 的 `MapEditor`）

- 岩壁地圖畫面直接交給 mapkit：岩壁節點（`wall`）當成分區（`sector`）畫，所以牆線、岩壁面朝向（右手邊）跟岩場站一樣；步道、道路、區域、地點照 mapkit 的詞彙畫（匯入的岩場站地圖有就有）。拍照點是小圓點。
- 一開始的畫面與「整張」看岩壁、區域和拍照點；可以移動的範圍再往外 1.5 公里。
- 區域圖的編輯用 mapkit 的受控模式（`setEdit`）：`studio/crag/map.js` 自己判斷點到哪個標註（線在 `LINE_HIT_PX` 內優先，再來是包住點的最小多邊形），拖曳直接改那個標註的形狀（一塊或多塊照原本的型別），停手 0.3 秒發 `shape` 才存；岩壁的線照最長那段重算朝向（`props.aspect`）。復原由 `app.js` 記（改之前整份標註和節點各存一份，最多 50 步）。資料變了就重建 `MapEditor`（畫面位置、選取、編輯模式留著）。
- 底圖：OpenStreetMap、國土測繪中心的航照與等高線，預設都關；地圖只標開著的底圖署名，不標岩場的作者（作者自己在編輯）。

## 發佈（`studio/crag/publish.js`、`studio/backend.js`；上傳與登記跟 Wall 同一種，見 [studio-design.md](studio-design.md) 的「發佈」）

岩場資訊（步驟列第一步）是一整頁，所有選項都看得到，改了就存：名稱、署名、難度系統、國家、原始資料（網址，只收 https）、交通（岩場節點的 `props.approach`，只有有岩場節點的書才有）、路線編號、路線清單的欄位、發佈（附上底圖）。

- **授權一律 CC BY-SA 4.0**：公開資料集只收開放改編的，所以沒有「開放其他人改編」的選項（2026-11-22 拿掉）；以前關掉的自己的書發佈前會擋下，人按「改成開放改編」才改（`M.setRemix`）。匯入的 Guidebook 照原作者的授權：原作者是 ND 的，在 Studio 可以看、在這台改，不能發佈。
- **附上底圖**：岩場範圍（岩壁、岩石、區域、步道的形狀往外 40 公尺）的國土測繪中心航照、等高線圖磚跟資料一起發佈（政府資料開放授權條款第 1 版，要署名）；OpenStreetMap 的圖磚使用規範不允許打包散布，不列出來（電腦、手機都一樣）。每種最多 160 張，岩場太大就少放最清楚的那層。檔名同一層 `tile-<種類>-<z>-<x>-<y>.jpg`，地圖畫面的 `props.tiles` 記 `{ kind, href（{z}{x}{y} 樣板）, minZ, maxZ, have（有的 z/x/y）, credit, license }`；紅點貓的岩場地圖照收的網址畫這些圖磚（mapkit 的 `tiles` 選項）。

Guidebook 的公開資料入口是 `https://climbio.app/p/<Guidebook id>/index.json`（開發版在 `climbio-dev.web.app`），由開放資料集提供；對話框提供該次發佈版本的固定 `/p/<包 id>` 分享網址。新版本有新的 id，可透過 `origin` 與 `root` 找到相關版本。

發佈時多放一個合併檔（`studio/crag/publish.js` 的 `withPack`）：`pack.json`（同一層所有 JSON），入口的 `props.pack` 指到它；紅點貓匯入（`redpoint/io.js` 的 `fromUrl`）一次讀回，一本 125 個檔案的 Guidebook 從約 125 次請求降到約 10 次（入口、`pack.json`、照片）。逐檔的檔案照發佈，沒有 `pack` 的舊專案、合併檔讀不到都照逐檔讀。格式見 [format/VOCABULARY.md](../format/VOCABULARY.md) 的 `pack`。

1. 步驟列的「發佈」打開對話框（對話框裡也有「匯出 ZIP」，匯出完關掉對話框），同時問雲端函式 `datasets` 開了沒：沒部署、連不上顯示「發佈服務還沒開」，超過預算顯示「發佈暫停中」，發佈按鈕不能按。
2. 第一次發佈列出會公開的內容（照片、路線、Topo、岩壁地圖、拍照位置與方向的張數）、授權 CC BY-SA 4.0。拍照位置與方向照原樣公開，沒有可以關掉的選項（要先看有幾張照片有，就在這份清單裡）。按了發佈就算同意，之後不再列出。署名欄每次發佈都看得到（改編的上面列出原本的署名，欄位只填自己的），改了就存、算一次修改，才有下一版可以發。
3. `origin` 不是 `self`／`authorized` 的畫面（紙本、來源不明）擋下並列出，刪掉才能發佈。
4. 按「發佈」：不用登入，每次發佈是新的專案 id（`origin` 指到上一版）。檔案跟匯出 ZIP 一樣，每份 JSON 先過 `validate`；照片畫面的 `camera` 照原樣公開，拍照位置也登記給「世界」的地圖。
   發佈中是獨立的全螢幕過場（`#pubRun`），發佈完或失敗才關，中間不能操作（Esc 關不掉，關分頁、重新整理先問）。跟匯入岩場反過來：封面是入口照片，照片小圖一開始都亮著，分析特徵點時框起來，傳出去（或沿用上一版、不用重傳）就往上飛走；下面是進度條和目前在做什麼（分析照片、下載底圖、上傳、登記、做分享連結）。`studio/dataset-publish.js` 的 `onFile(path)` 告訴過場每個檔案好了。
   發佈成功後，對話框顯示該次發佈的 `/p/<包 id>` 分享連結；再次修改並發佈會取得新的版本網址。沒有內容改動時不重複發佈；修改判斷使用 `studio/crag/publish.js` 的 `contentSig`。從公開版本匯入（`#site=`）、還沒發佈過的，第一次打開時記下內容指紋（`author:publish` 的 `fromSig`），跟它一樣就沒有發佈鈕、狀態寫「跟公開版一樣」：沒改就發佈只是把同一份再發一次。
   **複製改編連結**：發佈過時，對話框最下面多一個「複製改編連結」，複製 `<發佈的網域>/studio/crag/#site=<公開網址>`，貼給別人用電腦打開就匯入這本接著編（見上面的 `#site=`）。
   發佈就是公開：沒有「私人／公開」的選擇，一律放進開放資料集、出現在紅點貓的「世界」。
5. 上傳、登記（`type: guidebook`）見 [studio-design.md](studio-design.md)。公開資料集保留成品，新版本使用新專案 id，並透過 `origin` 追溯。

**發佈前擋下，不在背景補資料**：Studio 打開書、匯入時不自己補國家、署名、授權；發佈對話框照 `mustFix` 擋下並說要改什麼——沒選國家（到岩場資訊選）、署名重複（「楊礎豪；楊礎豪 改編」，按「整理署名」）、自己的書不開放改編（按「改成開放改編」）。命令列 `tools/guidebook.mjs publish` 在開瀏覽器之前就擋（國家、署名重複、授權不是 CC-BY-SA-4.0、已發佈過沒給維護者連結）。

**國家**：紅點貓的世界照國家分組（國家 → 地區 → 岩場），沒有國家的會被放到最後的「其他」，所以發佈前一定要有：岩場資訊的「國家」沒選，發佈鈕不能按、訊息說先選（`cgNeedCountry`）。轉換路線書的大綱岩場底下寫「國家：tw」（`outline.js` 的 `parseCountry`，兩個字母的國碼，台灣、臺灣也認得）就會帶進設定。國家是 Studio 的本機設定（`author:country`），匯出成包時拿掉，所以命令列發佈（`tools/guidebook.mjs publish`）每次都要給：`--country`，或包裡 `source/outline.md` 的「國家：」。發佈後確認世界清單：Studio 在背景等最多約 1 分鐘，讀不用快取的公開清單（`Backend.listGuidebooks({ fresh: true })`），發佈訊息後面接「已出現在紅點貓世界的「台灣」」或還沒更新、國家不對；命令列等最多 3 分鐘，連世界的樹（`world.json`）一起確認，不對就以失敗結束。

**大改變成新的一本**（設計見 [crag-open-versions.md](proposals/crag-open-versions.md)）：沒有維護者、金鑰，誰都能發下一版。打開發佈對話框時跟上一版（自己上一次發佈的，沒有就是匯入的那一版）比（`checkBig` → `versions.js` 的 `bigChange`）：一次刪超過 3 條路線、2 面岩壁、3 張照片（或上一版的 10%，取大的）就是大改，對話框說「會發成新的一本，原本的照舊」，名稱跟原本一樣就擋下要先改名（`mustFix`）；發佈時沒有 `origin`、自己是 `root`、從第 1 版算起。**編輯連結** `/studio/crag/#edit=<岩場 id>`（發佈頁「複製改編連結」產生，id 是這本的第一版 root）：點開從公開清單找最新的一版，這台有那一版的專案就打開、沒有就匯入（`fromEditLink`），連結一直有效。**不列入世界**：發佈對話框的勾選（`#pubUnlisted`，寫在組合的 `props.unlisted`，換勾選算一次修改），發佈帶 `listed: false`；公開清單找不到的書，版本紀錄和編輯連結改問 `Backend.guidebookVersions`（`bookRows`）。命令列更新已發佈的書：`tools/guidebook.mjs` 匯入前在 sessionStorage 放 `climbio.studio.adopt`（`{ project, root }`），書打開時 `applyAdopt` 接在那一版後面。

**版本關聯**：發佈新的專案 id，使用 `origin` 指向上一版、`root` 指向最初版本。公開清單依同一來源群組版本，開發版與正式版各自保留本機編輯資料。

**版本紀錄**（`studio/crag/versions.js`，發佈頁這本書一列的「版本紀錄」；發佈過、或從公開版本匯入的才有）：公開之後人人可以匯入來改、再發佈成新的一版，這裡列出同一本書（公開專案清單同一個 `root`）的所有版本，新到舊：第幾版（照發佈時間）、時間、從第幾版改的（`lineage` 的最後一個）、下載數，這個專案發佈的那版標「這個專案」，匯入來源標「從這版匯入」。
- 每一版自動跟它的上一版比，摘要一句（+3 條路線 · 改 2 條路線 · 4 條線 · 岩壁地圖 1 處；一樣的寫「內容跟上一版一樣」），點開看明細：岩場資訊（名稱、署名、授權、原始資料）、新增／刪掉／改了的區域、岩壁、路線（改的列欄位改前改後：名稱、位置、順序、難度、鉤環數、說明、首攀…）、照片、路線圖上的線。
- 怎麼比：節點（岩場、區域、岩壁、路線）照 id（各版之間不變，匯入保留）；照片照 `sha256`（匯入會換 id）；線照「哪張照片的哪條路線」（路線的線加它底下的鉤環、確保站）；岩壁地圖照節點的形狀。
- 「在紅點貓看」開那一版的 `/p/<id>`；「從這一版開始改」用 `#site=` 匯入那一版成新專案（同一版匯入過就打開那本），之後發佈的新版 `origin` 指到那一版，等於從那一版分出來，原本後面的版本照樣留著。
- 只在 Studio 裡算（讀公開檔案，發佈過的版本不會再改，讀過就留著），不動雲端函式、規則與公開格式。

`datasets` 的 `list`（`type: guidebook`）列出所有發佈的 Guidebook（新到舊，最多 300 本：名稱、公開網址、有 `preview.jpg`（合成預覽圖）時附上它的網址（新發佈的不再產生 `thumb.jpg`，世界地圖的圖釘直接用預覽圖的上半；舊的發佈還有 `thumb.jpg` 時一併附上）、拍照位置的平均），給紅點貓的「世界」。

自架的站沒有這兩個函式時，`studio/backend.js` 的 `SERVICE` 留空就沒有發佈；匯出 ZIP 照舊。

發佈只有 Studio 這一條路：`datasets` 的寫入 op 要 App Check 權杖，只有 Climbio 網頁拿得到（`studio/backend.js` 的 `appCheck`，同岩點貓、紅點貓用的 `Backend.appCheckToken`），腳本不能直接發佈。發佈前確認照片、Topo、GPS、署名與授權符合公開條件；公開後由開放資料集提供讀取。

## 牆線怎麼推估（`studio/crag/geo.js`）

- 每張照片從拍照點沿鏡頭方向推一段距離（設定），拍到的寬度 = 距離 × 底片寬 ÷ 等效焦距（橫拍 36mm、直拍 24mm；沒有焦距當成 26mm）。
- 牆線垂直於這面岩壁照片的平均朝向，蓋住每張照片拍到的範圍。點的順序：沿著點前進，岩壁面朝右手邊（從照片看過去由左到右）。
- 岩壁節點的 `props.aspect` = 鏡頭方向的反方向；拖過端點後照牆線的方向重算。
- 鏡頭朝向以正北為準：EXIF 標磁北（`GPSImgDirectionRef` 是 `M`）的加上磁偏角（東為正，固定 0），沒標或標 `T` 的照原值。
