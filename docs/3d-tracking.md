# 3D 相機追蹤測試

入口為 `/3d/`（`?wall=<牆 id>` 指定牆，省略時進入自動辨識模式，也可從上方選單手動切換室內外岩壁）。此頁只提供 3D 模型與即時相機，不包含照片、貼圖、定線、登入或檔案選取。牆的模型和岩點外框直接讀這面牆發佈的資料包（`/p/<牆 id>/` 的 `wall.json`、模型、`overlay`，跟看線、定線同一份）；岩點貓存過的檔案（`hold-models` 快取）直接用、不再下載。`/3d/` 自己只帶相機比對資料（`manifest.json` 指向 `camera-<雜湊>.json`）。預設滿版顯示並收起工具，只有工具入口與開啟相機按鈕；工具展開為浮層，不縮小測試畫面。預覽保持滿版，拍攝請求依螢幕直橫向設定寬高與比例，不固定 4:3，也不將橫向 1280×720 強制當直向來源。影像與外框用相同 cover 映射，鏡頭名稱明確時優先主鏡頭；工具可手動選取。螢幕轉向後重新請求對應比例並重定位，工具與網址列伸縮不反覆重啟相機。瀏覽器可能回傳不同於請求的格式，因此 log 同時記錄請求／實際寬高、影像映射與水平／垂直可見像素比例；不能單憑 zoom=1 宣稱與原生相機 1× 完全一致。影像只在裝置內處理，紀錄由使用者按「複製紀錄」自行提供。

## 相機看線

岩點貓（正式版、測試版）看 2D 牆、有相機比對資料的 3D 牆（`/3d/manifest.json` 的 `wall` 是這面牆的 id）路線圖時於「⋯」選單提供「相機看線」，畫面不顯示追蹤頁的「工具」（`auto=1` 時 `boot.js` 設 `data-embed`）。相機影格用 VideoFrame 轉移給 Worker 取灰階（不支援時才用 canvas 擷取），最快每 50 ms 送一幀。3D 牆在岩點貓裡蓋一層全螢幕的 `/3d/?ui=2&auto=1&wall=<牆 id>&route=岩點id:角色,…`（角色 `s` 起攀、`h` 手點、`f` 腳點、`t` 完攀）；`auto=1` 一進來就直接請求並顯示相機畫面，隱藏岩壁與路線切換列，不出現載入說明、開始按鈕或過渡畫面，比對資料與模型於背景平行載入，載好後才開始追蹤並疊這條線的岩點、照角色上色。牆沒有追蹤資料，或資料包的場景編號跟相機比對資料不同時，顯示載入失敗。

## 接口

追蹤頁和使用它的 App 之間只靠下面兩條接口；改任何一條都是兩邊一起的事，先講好再改，不單方面改：

1. **呼叫方式**：`/3d/?ui=2&auto=1&wall=<牆 id>&route=<岩點 id>:<角色>,…`。`wall` 是牆發佈的 id（`/p/<牆 id>/`）；`route` 的岩點 id 是資料包 `wall.json` 的 `holds[].id`，角色 `s`／`h`／`f`／`t`；`auto=1` 一進來就開相機、不先秀模型。追蹤頁內部怎麼辨識牆、定位、畫外框可以自由改，這組參數和行為要保持。
2. **資料**：牆的模型與岩點只讀牆發佈的資料包（`climbio-3d-wall/2`，見 [3d-wall.md](3d-wall.md)）。相機比對資料是另一份檔（`climbio-3d-tracking-camera/1`：`scene`、`focalRatio`、`references`），以 `scene` 對上資料包的 `scene`；目錄 `manifest.json`（`climbio-3d-tracking/2`）記哪面牆（`wall`）、場景、比對資料的檔名、大小、sha256。不另帶自己的模型或岩點檔。

## 現場比較

每檔使用相同位置、光線與動作：靜止約 10 秒，緩慢左右移動約 20 秒，再遮住鏡頭約 3 秒並恢復。可繼續移到轉角或改變距離。點「工具」可顯示指標與紀錄操作。有明顯外框偏移或岩點消失時，按對應標記；最後複製紀錄並貼到對話。拒絕剪貼簿權限時提供純文字選取與 JSON 下載。

牆面是原岩明德 Spraywall（牆 id `d1c27twdlbyor9cs`）。相機比對資料有 60 個參考視角、41,026 個追蹤特徵，約 2.4 MB，不含影像。岩點外框由資料包的 `overlay`（每顆岩點的面）算出：頂點權重＝周圍的面屬於這顆岩點的比例，畫權重 0.4 的等高線；只送出邊緣的面。首次開啟相機另載入共用 OpenCV 執行期，後續由瀏覽器快取。

## 數據判讀

- **FPS**：模型／外框繪圖頻率；**Hz**：影像處理結果更新率，最多約 10 Hz；**ms**：擷取影像至 Worker 回傳結果的時間，不包含鏡頭感測器與螢幕顯示的完整延遲。
- 紀錄按每次相機工作階段、每次追蹤模式切換分段，含初次定位時間、執行期載入時間、有效結果比例、外框可見時間比例、掉追蹤與過期隱藏次數、重定位時間。
- 每檔保存延遲、處理耗時、繪圖／影像頻率、內點數、特徵重投影誤差、相鄰姿態變化、draw calls 與實際繪圖面數的摘要；另留最近 240 秒的一秒級序列及問題標記。
- 特徵重投影誤差不等於岩點的人工正解精度；實際可見偏移依使用者標記輔助判讀。人物遮擋尚未做人像遮罩；失去可靠定位或結果過期才隱藏外框。
- 數據記錄牆的資料載入時間與是否來自快取，避免把熱快取與冷啟動混為一談。

紀錄不含照片、相機幀、音訊、GPS、相機 deviceId／groupId 或完整姿態矩陣。最後一份紀錄存在本機，重新整理後尚未開始新測試仍能複製。切換回模型、進入背景或離開頁面都停止相機。沒有自動上傳或分析服務。

## 來源與驗證

網頁程式原始碼在 `3d/source/`。只讀模型 glb 的頂點與三角形，不解貼圖。

Node 案例 `tools/tracking3d.test.mjs` 檢查相機比對資料與紀錄契約。相機成功定位只能在實機驗證；沒有實機結果時不能把模型介面當成定位通過。

## 運動感測比較

工具中的「純影像／旋轉輔助」可切換模式，預設純影像。第一次開啟輔助會在瀏覽器需要時申請運動感測權限；拒絕或不支援時維持純影像。取得權限後，兩模式都記錄感測事件頻率、旋轉速度、去重力加速度大小及影格年齡，沒有絕對朝向或原始感測矩陣。資料留在裝置，與既有「複製紀錄」一起匯出。

旋轉輔助以相鄰相機影格附近的裝置姿態差，預測光流的起始搜尋位置；結果仍經雙向光流及 PnP 影像驗證，失敗退回一般光流。沒有靠感測器生成岩點定位或在舊影格上外插外框。超過 100 ms 沒有對應姿態、影格間隔超過 250 ms、轉角大於 20 度、螢幕轉向改變或使用前鏡頭時不採用預測。沒有新影片影格就不重複處理同一幀，舊定位依原本期限隱藏。

先用相同動作各測一段純影像和旋轉輔助，分段比較人工偏移、掉追蹤、延遲，以及預測嘗試／通過影像驗證次數。模式切換重新定位，不把重定位過程當成已證實改善。感測軸向、影片時間與原生相機的實機差異仍需現場測試。

## 發布與頁面更新

`/3d/` 的 HTML 每次重新驗證，不快取舊目錄頁。打包時與 `/hold/` 一起對 JS／CSS 引用加發布版本，避免新程式和舊頁面混用。程式啟動先比對介面版本；載入舊 HTML 時以版本查詢參數自動重新載入一次，仍不一致則顯示載入失敗並提供錯誤紀錄，不把原始 JavaScript 錯誤直接放在相機畫面。

相機尺寸以播放後第一個實際影格的 videoWidth／videoHeight 為準，不以 getUserMedia 回傳瞬間的 getSettings 判斷。若實際影格恰好是請求寬高的倒數方向，停止舊串流，以交換寬高和倒數比例的請求重開同一鏡頭一次；仍反向時停止並記錄錯誤，不繼續顯示大幅裁切的畫面。螢幕直橫向切換重新開啟相機並重定位，網址列伸縮不重啟。每次請求、首幀前設定、實際首幀尺寸與更正旗標保留於紀錄。這是修正已觀察到的 Safari 寬高反向，不以合成測試宣稱原生 1× 的實機光學視野已相同。

相機預覽使用獨立 Canvas 直接畫影片影格，與辨識擷取共用來源，不依賴原生 video 顯示層的縮放。成功的鏡頭及直橫向請求方式只記在這個頁面的記憶體；再次開啟直接沿用，避免重複開預設鏡頭再切主鏡頭、反覆嘗試錯誤方向。每次仍確認首幀，若平台行為改變可更正一次。匯出包含是否重用設定、預覽繪製方式與低解析度黑邊診斷摘要；不匯出像素，也不依暗部邊界自動裁切影像。

停止後的未恢復掉追蹤時長固定於該段結束時，不隨稍後匯出繼續增長；新段的延遲／誤差樣本不沿用舊段最後一幀。相機 mute／unmute 事件只記錄狀態，協助判讀影格中斷。

## 難定位角度的診斷

紀錄新增最近 240 筆定位診斷：本幀特徵數、3D 匹配數、光流保留數、最大 PnP 內點、影像覆蓋率、最佳參考視圖的索引／匹配數與拒絕原因。重新搜尋時記錄，每秒也取一次持續追蹤摘要。標記偏移／掉點時，同時保留當下定位診斷（另含前三個參考視圖匹配數）及低解析度黑邊摘要。資料不包含像素、描述子或特徵座標；不降低定位門檻。

相機穩定 30 FPS 但沒有姿態，代表辨識／定位未通過，不等於相機停格；畫面沒有外框時的 0 繪圖 FPS 也不能當成影片卡頓。特徵多但 3D 匹配少，才支持視角或參考特徵覆蓋不足的推測；匹配多而幾何拒絕，則需看內點、覆蓋率與誤差。

## 多岩壁自動辨識與相機路線標記

- **多牆自動辨識**：不帶 `wall` 時預設為「自動辨識」，也可從上方選單手動鎖定單一岩壁。室內牆從各牆發佈的資料包（`/p/<牆 id>/wall.json`、模型、`overlay`）與 `3d/manifest.json`（支援單牆及多牆項目）對應 `scene` 載入相機比對資料；模型模式初始載入不請求任何照片或貼圖。開啟相機後，背景才依序載入公開的戶外 3D 岩場指南包（`/p/<岩場 id>/index.json`，支援 `.spz` 點雲與 `.glb` 網格模型），由模型深度投影與照片 ORB 特徵在執行期動態建立追蹤庫，不將 base64 特徵建置產物寫進版控。搜尋階段先對各候選牆做描述子粗篩排序，再對前幾名執行 PnP 幾何驗證，通過門檻即切換對應岩壁並進入光流追蹤。
- **路線標記與切換**：非 `auto=1` 模式時，畫面底部提供路線膠囊列切換。室內人工岩牆支援 `?route=`、`?r=` 分享連結、`localStorage`（`climbio.arRoute`）、本機 `climbio-db` 已存路線與預設示範線，選取路線後非路線岩點隱藏、路線岩點依起攀／手點／腳點／完攀著色並疊加 S／T／序號標記；戶外天然岩場則將 3D 路線折線投影至相機視野，沿用 `topokit` 繪製路線折線、起攀編號與難度牌。
