# 自動測試與手機驗證

自動測試分成純邏輯、瀏覽器操作、Firebase 整合與手機實機四層。完整使用情境仍有下表列出的缺口，不能宣稱 Android／iOS 所有情境正常。

## 執行

日常的案例選擇見 [development.md](development.md)。首次準備環境與完整回歸：

```sh
npm ci
npm ci --prefix functions
npx playwright install chromium webkit
npm run check
npm test
npm run test:e2e
```

每次只使用一個 worker，符合本機 8 GB 記憶體限制。測試網站由 `tools/serve-test.py` 提供，加大連線佇列以承受程式與字型同時載入，避免連線被重設。Playwright 使用 `127.0.0.1:8876` 與每例獨立的瀏覽器 context，`tests/e2e/fixtures.mjs` 設 `climbio.site.main` 讓本機接主網的後端介面（各例換成假的）；不讀 `localhost:8765` 或手機既有資料。所有外部請求一律攔截，避免測試建立正式帳號、上傳照片。一般互動測試使用專案內的測試素材或在測試中生成照片，資料只寫測試用 IndexedDB；舊版範例牆相容性另由 內部 e2e 案例 隔離驗證。測試使用真實程式；直接寫入資料只用於準備牆面 fixture，不能當成拍照／匯入流程已通過。

`npm test` 執行 `tools/*.test.mjs` 與 `functions/*.test.js`，驗證本機定線、分享、裝置金鑰簽章與公開 API 的替身邏輯；不能代替正式 Firebase App Check、部署或兩台實機的附近交換驗證。

`npm run test:boot` 用 Android Chromium 模擬跑 `tests/e2e/boot-smoke.spec.mjs`，確認岩點貓與紅點貓開機沒有腳本錯誤或白畫面。紅點貓另有開機看門狗（`appkit/recover.js`，見 [redpoint.md](redpoint.md) 的「啟動」）：主程式損壞時自動讓等待中的新版接手，或清快取後重載，不動 IndexedDB。

`npm run test:e2e` 在 Chromium／WebKit 兩個瀏覽器設定執行下列情境：

- 開場的「開始拍」打開選照片（Android 先選拍照或相簿），選好照片進裁切；三組文案各自的畫面輪播；沒選照片會留在開場並可再次選擇，沒有「用示範牆」入口；啟動與 PWA 首裝不預載 `demo/demo.json` 或 `demo/demo.jpg`。
- Android 安裝提示與尚未收到原生安裝事件時的說明；iOS 三步安裝說明。
- LINE 內建瀏覽器的 Android intent 連結與 iOS 外開說明（只驗證網頁分流）。
- 中文、英文、日文（其餘語言包由 `tools/check.mjs` 檢查 key）開場文字與重新載入後保存（各一例）。
- 普通測試牆與照片寫入 IndexedDB、點卡片打開、重新載入後資料仍存在。
- 長按既有岩點只選取，不跑模型、不換外框；長按沒有岩點的地方不放方框，直接打開圈選，畫一圈才補上，外框就是畫的形狀（不削成粗略的多邊形）。
- 長按放大時照片上那一點留在指尖下；按著從空白處移到岩點上再放開，改成選那顆、不再圈。
- 單點編輯的復原、刪除浮在岩點下方，下面放不下就放上方。
- 按「重描」：合格就換上、復原拿得回來；結果重疊、無效、太小時留著原本的並提示，失敗時說原因；已編輯、離開、刪除、復原後的晚回覆不覆寫操作。
- 圈起來換上手畫的形狀，圈到的別顆岩點不動，復原拿回原本的；Node 測試另驗證繞過起點多畫的一段剪掉、手抖平均掉、沒畫回起點也照畫的收起來。
- 長按成立前移動或加入第二根手指，不新增岩點。
- 完成補點自動依起攀／手／腳／完攀／順序模式加入路線；既有點的選取不變，取消不加入。
- 3D 牆補點的方框（也用來判斷按在框外一點點算不算那顆）：Node 測試驗證密集岩點左右、上下、斜邊、凹形、照片邊緣的空隙會調整方框，保留長按位置且不與既有輪廓相交。
- 新增牆面：選了照片就預熱偵測、重描、整理外框；按完成先出分析畫面、馬上送偵測，再存檔。偵測完就出現下一步和 ×（偵測失敗也能關），岩點醒來演完自動進定線；重描、整理在背景做，做完之前長按不能改岩點、上方提示還在描，做完提示收起、重描的外框換上。進入定線會提前準備解碼器，這台沒有照片特徵才跟雲端要一次。Node 測試另驗證重複觸發共用初始化、下載失敗後重試、同一個提示共用一次重描。

重描的自動測試在 MobileSAM 介面使用可控制的替身，驗證手勢、畫面與非同步保護；模型品質應另以取得適當授權的照片測試集實跑，不能以替身測試代表辨識準確率。

失敗保留截圖與 trace，HTML 報告在 `playwright-report/index.html`。

WebKit 的非持久 context 在 macOS 寫入 Blob 會出現 `UnknownError: Error preparing Blob/File data to be stored in object store`；獨立的文字／物件／Blob 實驗可重現，改用持久 context 後可寫入。Ubuntu 的相同收線與照片存檔案例也會失敗。`tests/e2e/fixtures.mjs` 因此替每個 WebKit 案例建立獨立暫存目錄並在結束時清理，保留真正的 IndexedDB 與照片 Blob，不以替身繞過存檔。這項測試引擎限制不構成 iPhone 實機失敗的證據。



內部 e2e 案例 在 Chromium／WebKit 手機設定驗證一比一拖曳、相鄰路線預覽、完整就位、短拖回彈、快速短撥、首尾阻力、同手勢反向、取消、吸附途中再抓住、雙指縮放、邊緣與直向手勢、減少動態效果、最後反向撥回，以及 720 顆岩點／每條 120 點的大牆拖曳不反覆重畫；並保存拖曳中與就位後截圖。實機流暢度與 iPhone Safari 手感仍需手機確認。

## 測試只留功能

測試只回答「功能壞了沒有」：流程走得通、資料存得進去、返回退得回、錯誤有處理。不斷言版面數值（欄數、尺寸、位置）、排序、文案、像素基準圖：這些改一次畫面就要跟著改期望值，不新增，遇到就刪。測試資料不進 repo：能用開放資料集（climbio/walls、crags、walls3d、crags3d）的就下載使用，其餘由測試程式合成。

| 測試層 | 能確認 | 不能代替 |
|---|---|---|
| Node 測試 | 資料與狀態轉換、重試次數、錯誤分類 | DOM、觸控、第三方服務 |
| Pixel 7 設定＋Chromium | Android UA、手機版面、瀏覽器操作 | Android 作業系統與實際 Chrome 安裝流程 |
| iPhone 13 設定＋WebKit | iPhone UA、觸控版面、WebKit 操作 | iOS Safari 發行版、主畫面 App、鍵盤及系統授權 |
| Firebase Emulator（待建） | 公開牆寫入、裝置簽章與規則隔離 | 正式 App Check、實機網路與部署設定 |
| Android Chrome／主畫面 App、iPhone Safari／主畫面 App 實機（待測） | 安裝、相機、手勢、系統分享、前背景、LINE 跳轉 | 其他 OS／手機版本；需在報告寫明版本 |

Playwright 的裝置設定模擬 UA、尺寸、觸控等參數，WebKit 測試不能直接當作 Safari 實機結果。依據：[裝置模擬](https://playwright.dev/docs/emulation)、[瀏覽器支援](https://playwright.dev/docs/browsers)。

## 補齊順序與完成判準

1. 先補資料風險：規則、登出、刪除、雙裝置衝突與收線合併。建立 Emulator 隔離資料；不得用正式帳號繞過權限。
2. 補核心旅程：拍照／匯入 → 裁切 → 固定偵測結果 → 編岩點 → 定線 → 記錄 → 產圖 → 收線。API 只在邊界替換，每步驗證畫面與持久化資料。
3. 補 HTTPS／Service Worker 的離線、更新，以及錄影／原生分享 API 的成功、取消、拒絕與背景恢復。
4. 兩平台各以一般瀏覽器、主畫面 App 跑安裝、相機、公開分享、附近交換、我的裝置配對、返回與鎖屏。記錄 OS／瀏覽器版本、commit、截圖與實際結果。

所有 P0 資料安全與核心旅程通過，且兩平台實機項目有版本與結果，才可說「指定環境已驗證」。覆蓋表新增產品功能時同步補案例；沒有執行的情境保留「待測」，不能以 UA 模擬通過推論全平台正常。
