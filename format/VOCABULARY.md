# 詞彙

節點的 `type` 和 `props`、檔案與標註的 `props` 常用的寫法。詞彙是約定，不是格式本身：新增詞彙不改規格、不升版本，讀的人略過不認得的。同一件事請用這裡已有的詞，沒有就自己加（各站自己的資料用 `站名:欄位`，例如 `longdong:safety`），用的人多了再收進來。

## `type`

| 值 | 意思 |
|---|---|
| `area`、`crag`、`sector`、`wall` | 區域、岩場、分區、岩壁。層次：主區域（`area`、`crag`）可以有多個主區域或多個子區域（`sector`、`wall`），子區域有多個 Topo（照片）、多條路線；岩場可以是主區域，也可以是子區域（見 [README.md](README.md) 的「放法與連結」） |
| `gym`、`room` | 岩館、岩館裡的區域 |
| `route` | 路線（抱石題、運動攀登、傳統攀登……） |
| `pitch` | 繩距（上層是一條路線） |
| `hold` | 岩點 |
| `bolt`、`anchor` | bolt、確保站 |
| `ascent` | 一次攀爬紀錄（通常不公開） |
| `poi` | 地圖上的其他地點，用 `props.kind` 分：`parking`、`toilet`、`rescue`、`trailhead`…… |

## 路線

| `props` | 內容 |
|---|---|
| `code` | 好讀的代號，例如 `longdong/jag38d` |
| `number` | 路線編號（路線書上自己填的號碼，例如龍洞的 `568`）；沒有就照順序編 |
| `grade` | `{ 系統: 值 }`，可以同時寫多個：`yds`（5.11a）、`french`（6c）、`uiaa`、`british`、`v`（V3）、`font`（6A）、`dan`（日本的級段：`3級`、`初段`）；岩館自訂的用岩館自己的系統名稱，例如 `{"市民抱石": "藍"}` |
| `style` | `boulder`、`sport`、`trad`、`toprope`、`mixed`、`aid`、`ice`、`dws` |
| `length` | 長度（公尺） |
| `pitches` | 繩距數 |
| `bolts` | bolt 數（只記數量；位置用 `bolt` 節點） |
| `order` | 在同一個上層（例如岩壁）裡的順序：數字小的在前，岩壁上通常由左到右 |
| `holds` | 岩點 id → 角色：`s` 起攀、`h` 手點、`f` 腳點、`t` 完攀。岩點不在這個圖層疊的畫面（跨照片的路線，見 README「同一面牆的幾張照片」）就寫「畫面 id#岩點 id」 |
| `seq` | 出手順序（岩點 id 陣列，別張照片的岩點一樣寫「畫面 id#岩點 id」） |
| `setter`、`fa` | 定線者、首攀 |
| `set`、`removed` | 上線日、拆線日（`YYYY-MM-DD`） |
| `status` | `open`、`closed`、`removed` |
| `description` | 說明（字串或多語物件） |

## 岩點

| `props` | 內容 |
|---|---|
| `source` | `detect`（自動偵測）、`edited`（偵測後改過）、`manual`（手畫） |
| `retired` | `true`：停用。這顆岩點公開過、之後被刪掉或合併掉，標註照公開時的外框留在畫面裡，別人的舊路線還指得到它；新路線不該讓人選到它 |

## 岩壁、地點

| `props` | 內容 |
|---|---|
| `code` | 好讀的代號 |
| `aspect` | 岩壁朝向（度，從正北順時針） |
| `order` | 在同一個上層裡的順序（數字小的在前），例如分區裡的岩壁、岩場裡的分區 |
| `approach` | 交通：怎麼到（開車導航到哪、停車、大眾運輸、走多久；字串或多語物件），寫在岩場或分區節點 |
| `description` | 說明（字串或多語物件） |

| `props` | 內容 |
|---|---|
| `route` | 爬的路線（全域 id 或「檔案id#節點id」） |
| `date` | `YYYY-MM-DD` |
| `style` | `onsight`、`flash`、`redpoint`、`send`、`attempt`、`toprope` |
| `note` | 筆記 |

## 畫面

| `props` | 內容 |
|---|---|
| `crop` | 顯示的範圍 `{ x, y, w, h }`（畫面座標）；標註的座標不受影響 |
| `photos` | 照片畫面：它所屬的「同一面牆的幾張照片」組合（`type: photos`）的網址；收到一張就能找到同一面牆的其他張 |
| `thumb` | 縮圖的網址（相對路徑或 https），讀的人下載照片前先顯示。組合的入口圖用 `props.preview`（一張合成預覽圖：上面入口照片、下面每張照片的小圖，照片項目的 `props.tile` 是第幾格），讀的人下載其他檔案前先下載、先顯示；不另存縮圖檔（舊的收藏有單獨的 `props.thumb`，讀的人仍認得） |
| `anchors` | 對位點：`[{ "at": [x, y], "geo": [經度, 緯度] }]`，把照片或向量圖放回地圖上 |
| `basemap` | 地圖畫面建議的底圖（說明文字或網址） |
| `node` | 畫面拍的、畫的是哪個節點（全域 id 或「檔案id#節點id」），例如一面岩壁的照片 |
| `model` | 照片是從 3D 模型拍的快照時，模型和拍的角度：`{ "id": 模型畫面的 id, "camera": { "position": [x, y, z], "target": [x, y, z], "fov": 垂直視角（度） } }`（模型的座標）；讀的人可以從同一個角度打開模型 |
| `background` | 3D 模型畫面：背景模型畫面的 id（例：岩壁用網格 `.glb`、四周山林與天空用高斯潑濺 `.spz`）；讀的人把它畫在模型後面，被模型擋住的地方不畫 |
| `sky` | 3D 模型畫面：現場的背景顏色 `["#天空上方", "#地平線", "#地面"]`（從照片取色），讀的人當模型後面的漸層，讓淡出的邊緣融進去 |

## 標註

| `props` | 內容 |
|---|---|
| `style` | 畫法：`stroke`（顏色）、`width`、`dash`、`fill`、`icon` |
| `label` | 顯示的文字 |
| `size` | 標記的邊長（畫面座標，照片是像素）：路線號碼的牌子用，照片上原來就印著號碼牌時，牌子蓋成它的 1.2 倍 |
| `route` | 只用在這條路線（圖層裡的路線節點 id）的形狀。同一顆岩點在某條路線外框不一樣（定線的人自己修過），或畫面上沒有這顆時，圖層寫一個帶 `route` 的標註；其他路線照用畫面上的 |
| `source` | 這個形狀從哪裡來，跟岩點的 `source` 一樣 |

## 戶外 Topo

TopoKit（`topokit/`）畫戶外照片上的路線用的寫法，都是上面已有詞彙的用法：

| 節點／標註 | 內容 |
|---|---|
| `bolt`、`anchor` 節點的 `name` | 位置：bolt 由下往上 `B01`、`B02`…，確保站 `A01`、`A02`…；`parent` 是路線 |
| 路線的 `LineString` 標註的 `props.label` | 編號牌的文字（路線的編號） |
| 路線的 `Point` 標註（路線號碼：照片上標了路線的位置、沒有畫線） | 編號牌的中心位置；`props.label` 是號碼、`props.size` 是牌子邊長、`props.style.stroke` 是牌子顏色。路線有 `LineString` 時以線為準，不再寫這個標註；指向 `bolt`、`anchor` 節點的 `Point` 才是 bolt |
| bolt、anchor 的 `Point` 標註的 `props.label` | bolt 旁邊的材質說明（例如 `316-TW`） |
| 路線的 `LineString` 標註的 `props.style.stroke` | 覆蓋線的顏色；沒有就依路線的 `props.style`（`sport` 藍色，其他紅色） |
| 3D 模型（`surface: model`）上的路線 | 見下面「3D 岩場」 |
| 分叉、合併（照片與 3D 一樣） | 沒有另外的共用線段：分叉的兩條路線各自寫一份共用的前段，合併的各自寫一份共用的後段，共用那段在每條路線裡座標完全相同（差一點就是兩條線）。兩端座標相同的線段就是共用：只畫一次（歸編號在前的那條），選到哪條路線，它經過的共用段跟著亮；編號牌放在各自不共用的那段上；3D 的遮擋表照點算，共用段在每條路線裡一樣 |

## 3D 岩場（`surface: model`）

一個岩場的 3D 版：整個岩場一個模型，路線是疊在模型上的 3D 折線，每面岩壁、整個岩場各有一張快照。範例見 `examples/crag3d*.json`（組合 `crag3d.json`，其他是它的各個檔案；範例不附模型和照片）。

| 檔案 | 內容 |
|---|---|
| 模型畫面 | `kind: view`、`surface: model`、`mime` 必填；`href` 指到模型檔：高斯潑濺 `.spz`（`mime: model/x-spz`）或網格 `.glb`（`mime: model/gltf-binary`，貼圖內嵌）；沒有 `w`、`h`。`props.node` 指到岩場；可有 `props.background`、`props.sky`（見「畫面」） |
| 路線圖層 | `kind: layer`、`on` 是模型畫面的 id；`marks` 每條路線一個 `LineString`（座標是模型的 `[x, y, z]`，沿著岩面），`node` 指到路線、`props.label` 是編號牌的文字；圖層的 `props.sight` 是遮擋表的規格，每條路線標註的 `props.sight` 是那條路線的表 |
| 岩壁快照 | 一面岩壁一張 `surface: photo` 的畫面：`props.node` 指到岩壁節點、`props.model` 記模型和拍的鏡頭（見「畫面」）。岩壁照 `props.order` 排，就是沿著岩壁走的順序。快照不畫路線（路線在圖層裡）。建議 1080×2340、垂直視角 74.36°：左右的範圍剛好是 3:4、50° 的整面岩壁，手機上整張快照剛好填滿 |
| 全區快照 | 一張 `surface: photo` 的畫面，`props.node` 指到岩場（或分區）、沒有路線圖層，`props.model` 同上；建議 4:3（例如 1600×1200、垂直視角 45°），看得到整段岩壁。讀的人當岩場的封面，也是第一次進 3D 的第一個畫面；沒有這張就沒有全區的開場 |

座標與單位：模型自己的座標，單位公尺，y 朝上；鏡頭的 `position`、`target` 同一組座標，`fov` 是垂直視角（度）。

**遮擋表**（路線標註的 `props.sight`；圖層的 `props.sight` 是規格）：從各個方向看，路線每個點被岩壁擋住的表，讀的人不用自己算。

- 規格：`{ "step": 點的間距（公尺）, "az": 方位角格數, "el": [起始仰角（度）, 每格度數, 格數], "dist": [距離上限（公尺）…] }`。
- 表的點就是標註 `LineString` 的點（路線照 `step` 取樣），表的點數必須等於座標的點數。
- 值是 deflate（raw）壓過再 base64 的 4 位元陣列（一個位元組放兩個，低 4 位元在前），共 點數 × `el` 格數 × `az` 個，順序是點、仰角、方位角：第 `k = (點 × el 格數 + 仰角格) × az + 方位格` 個值，位元組 `k >> 1`、`(k & 1) × 4` 位元。
- 方位角格 = `round(atan2(x, z) / 2π × az)` 取餘數（`x`、`z` 是從點往看的人的方向）；仰角格 = `round((asin(y) 的度數 − 起始仰角) / 每格度數)`，限制在 0 到格數 − 1。
- 0 是沒擋住；k 是在 `dist[k-1]` 公尺內有岩壁擋住，看的人比那裡遠就看不到這個點。

讀的人的約定（建議，不影響驗證）：
- 岩場裡有路線的 Topo 都是同一個模型的快照（`props.model.id` 相同），才用 3D 看；部分是、部分不是，照一般 Topo 看。一個岩場多個模型還沒有定義。
- 沒有 `props.sight`：路線不做遮擋，全部畫。沒有 `props.background`、`props.sky`：背景用淺灰藍的單色。
- 快照一定要有：舊版的讀的人、2D 的 Topo、分享預覽、離線的備援都用它。
- 單一檔案的大小：Climbio 的開放資料集每個檔案 25 MB 以下，作者端要把模型壓到這個大小。

## 地圖

mapkit（`mapkit/`）畫岩場地圖（地圖畫面，經緯度）用的寫法：

| 節點／標註 | 內容 |
|---|---|
| 沒有節點的標註的 `props.kind` | 底圖：`land` 陸地、`building` 建物、`parking` 停車場（多邊形）；`highway`、`tunnel`、`road` 道路、`trail` 步道（線）。`props.source: "osm"` 表示來自 OpenStreetMap |
| 沒有節點、`props.kind: "route"` 的線 | 建議的行進路線（例如單向繞一圈的車道、步行路線），照畫線的方向走 |
| `area`、`crag` 節點的多邊形、`sector` 節點的線 | 區域範圍、分區的岩壁（沿著牆底）。岩壁的畫線方向決定岩壁面朝向：岩壁在左手邊、岩壁面朝右手邊 |
| 標註的 `props.style.fill`、`stroke` | 區域的填色與外框色、岩壁的顏色 |
| `poi` 節點的 `props.kind` | 另外有 `rescue`（救援點，`props.label` 是編號）、`first-aid`（急救器材，`props.label` 是編號）、`boat`（船艇接駁點）、`helicopter`（直升機吊掛點）、`hazard`（危險地形）、`place`（地名）、`line-name`（沿著線排的道路、步道名稱，`props.line` 是哪一種線） |
| `poi` 節點的 `props.tone` | 地名的顏色種類：`place`、`road`、`trail`、`sea`、`warning` |

| 地圖畫面的 `props` | 內容 |
|---|---|
| `bounds` | 移動範圍 `[西, 南, 東, 北]` |
| `extent` | 底圖資料的範圍 `[西, 南, 東, 北]`：畫面最寬到這裡、圖磚畫到這裡 |
| `home` | 一開始的畫面 `[西, 南, 東, 北]`；沒有就用所有區域的範圍 |
| `fit` | `contain`：縮小時寬高都放得進畫面（直立的手機也看得到整張）；沒寫時縮小只看上下，剛好填滿框，範圍比畫面寬就看不到整張的寬 |
| `purpose` | 地圖的用途：`approach` 交通圖（怎麼到岩場：道路、停車、公車站、建議路線）；沒寫是岩場地圖 |

交通圖的 `parking` 地點有名稱時，讀的人可以拿它當導航的目的地。

## 圖層

| `props` | 內容 |
|---|---|
| `gym` | 岩館（Climbio 的岩館字串：`岩館#標籤#分區`） |
| `thumb` | 它疊的牆的縮圖網址（相對路徑或 https）：讀的人拿到圖層就能跟牆同時下載 |
| `preview` | 先顯示用的極小預覽圖（`data:` 圖片，長邊約 96px）：讀的人拿到圖層就先顯示，縮圖、照片到了再換 |

## 組合

| `type` | 意思 |
|---|---|
| `site` | 一個站：`props.url` 站的網址、`props.listed` 願不願意被列進總目錄；項目是站上各岩館的清單 |
| `walls` | 一間岩館的牆面（一組牆）：項目是一面牆（路線圖層，或還沒有路線的牆畫面）；Wall 與岩點貓的分享包都是這種 |
| `directory` | 總目錄：項目是各站的岩館清單 |
| `guidebook` | 一本 Guidebook（Studio Crag）：節點是岩壁（`wall`）、分區、路線；項目是岩壁地圖和照片，每張照片後面接著疊在它上面的 Topo 圖層 |
| `photos` | 同一面牆的幾張照片（牆太寬、有轉角，一張拍不完）：項目是照片畫面（或疊在它上面的路線圖層：讀圖層就拿得到畫面和路線），照在牆上的左右排；`props.links` 是兩張之間的對齊 |

| 項目的 `props` | 內容 |
|---|---|
| `thumb` | 縮圖（網址或 `data:` 圖片） |
| `walls` | 公開的牆面數 |
| `routes` | 公開的路線數 |
| `site` | 站名（總目錄裡） |

| `guidebook` 組合的 `props` | 內容 |
|---|---|
| `settings` | 這本的設定，另一個人匯入就有完整的設定：`{ numbering, grade, distance, declination, pack, columns? }`。`numbering` 路線編號怎麼來（`wall` 每面岩壁從 1、`area` 每個大區域從 1、`manual` 用路線自己的 `props.number`）；`grade` 難度系統（`yds`、`french`、`uiaa`、`british`、`v`、`font`、`dan`）；`distance` 從拍照點沿鏡頭方向推的距離（公尺，推算岩壁位置用）；`declination` 磁偏角（度）；`pack` 附上的底圖（`ortho`、`contours`）；`columns` 路線表格顯示的欄位（沒選過就不寫）。讀的人略過不認得或格式不對的欄位 |
| `preview` | 合成預覽圖：`{ href, w, h, count, tile: { w, h, cols, y } }`。一張圖放兩樣東西：左上起寬 `w`、高 `tile.y` 的入口照片（4:3），下面從 `y` 起把每張照片的小圖排成格子（每格 `tile.w`×`tile.h`、每列 `cols` 格，由左到右、由上到下；`count` 是格子數，照片在更下層的組合裡時（例如整個岩場底下有好幾個區域）靠它知道有幾格，沒有就數項目的 `props.tile`）；收這本時先下載這一張，下載照片時小圖一格格亮起來；清單上的卡片也用它的上半（入口照片），不另存入口照片 |
| `pack` | 合併檔（發佈用，讓讀的人一次讀回同一層所有檔案，不用逐檔請求）：`{ href }` 指到 `pack.json`，內容 `{ docs: { 檔名: 文件 } }`。`docs` 是同一層除了入口以外的每份 JSON（跟逐檔的內容一樣）。逐檔的 JSON 照樣發佈，不認得 `pack` 的讀的人略過它、照舊逐檔讀；`pack.json` 讀不到、沒有 `pack` 的舊專案，讀的人也逐檔讀 |

岩壁數、路線數不存，讀的人從組合的 `nodes` 數（見 [README.md](README.md) 的「放法與連結」）。

| `guidebook` 組合的項目 `props` | 內容 |
|---|---|
| `tile` | 清單用的快取：這個項目是一張照片，它的小圖在 `preview` 格子裡的第幾格（從 0 起，照項目的順序）。不打開檔案就知道哪些項目是照片、有幾張 |

| `photos` 組合的 `props` | 內容 |
|---|---|
| `links` | `[{ a, b, H, dx, dy }]`：項目 `a`、`b`（項目的 `id`）有重疊；`H` 是 3×3 透視變換（依列排 9 個數），把 `a` 的照片座標換到 `b`，重疊範圍裡準（轉角、不同平面的照片外插會變形）；`dx`、`dy` 是重疊點的位移中位數（`b` 的原點在 `a` 的座標），排左右用。手動接的沒有 `H` |
